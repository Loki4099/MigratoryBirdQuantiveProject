# v0.21 存储维护与冷归档运行手册

状态：实现已落地，生产清理尚未执行。  
实现入口：`style_rotation.storage.maintenance.StorageMaintenanceService`

## 1. 保留边界

系统按以下顺序分类，前一类优先于后一类：

1. **Product pin**：Product 的六格 Portfolio Cell/Result、所选模型对应的 Predictive Cell/Result、Product/Qualification/Compiled Strategy/Research Spec、Benchmark、Comparison Context、Data Bundle、Universe、执行与监控政策、后续 Monitoring Snapshot 及其递归血缘。
2. **当前实验**：显式指定的 Suite、最新 Suite、仍有 queued/running Work Item 的 Suite，以及这些 Suite 的递归依赖。
3. **可回收旧实验**：其余实验专属 Artifact Manifest，包括已经失去业务表关联的 v0.2 旧实验发布物。
4. **共享或未分类**：默认保留，不猜测、不删除。

Qualification 到 `source_suite` 的依赖不会把整套 Suite 变成 Product pin；Suite 根身份单独保留。只要六格、结果或 Predictive 证据不完整，Manifest 回收会 fail closed。

## 2. Workspace 研究缓存

- 默认 TTL：14 天。
- 默认容量上限：10 GiB。
- 顺序：Product/在用/最近访问/异常路径 pin → TTL → LRU 容量回收。
- Product 或 queued/running Work Item 文档中出现的 cache key 会被保护。
- 引用清单读取失败、路径越界、未来时间戳等异常一律 fail closed。
- 执行前会重新锁定并检查引用与 `last_accessed_at`；文件先原子移动到隔离目录，数据库提交后才删除隔离文件，失败时恢复。

## 3. Lineage 冷归档

`lineage.lineage_manifest` 有不可更新/删除触发器，维护服务不会绕过它。当前实现只执行安全的第一阶段：

1. 生成 dry-run 和稳定 `plan_id`。
2. 要求操作人回传精确 confirmation token。
3. 按默认 256 MiB 上限生成 Zstd Parquet 分片。
4. 写入后重新读取全部归档行，核验每个 canonical manifest hash 与整文件 SHA-256。
5. 生成紧凑 receipt/tombstone JSON，记录 artifact ID/type/key、fingerprint、content hash、manifest hash、归档 URI/hash。

Receipt 中 `database_compaction_executed` 固定为 `false`。只有在备份、独立 restore-test、Product 页面/冻结回测/血缘/最新仓位一致性测试全部通过后，才能另建专用 Alembic 迁移，把热库完整 Manifest 替换为 tombstone。禁止手工关闭触发器或直接删除生产 Manifest。
