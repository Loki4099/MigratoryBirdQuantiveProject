## 2. 版本定位

v0.21不是单纯的前端换皮，也不是全量重写v0.2。它是：

> 在v0.2不可变发布、指纹、血缘与实验底座上，完成一次跨层契约升级，建立“定向研究工作台 → 严格实验 → 人工选择候选 → 发布后样本外观察”的完整研究闭环。

核心目标：

1. 研究者从Asset开始逐层选择Factor、Signal、Model和Strategy，只运行明确选择的合法分支；
2. 上游选择实时约束下游，不合法对象保留可见但置灰并解释原因；
3. 大规模资产、局部缺失、动态PIT Universe和多Model分支不破坏可复现性；
4. 实验以统一、可比较、包含容量与冲击的合同运行；
5. 研究者从优秀实验中手动升级Product，并从激活后开始观察真实新增数据上的表现；
6. 永久记录研究选择漏斗、预警、暂停、退役和替代，研究筛选体系本身也可被检验。

## 3. 明确非目标

v0.21不包括：

- 公网、多用户、账号角色和客户展示系统；
- 券商接入、真实下单、订单簿回放或整数股撮合；
- 做空、杠杆、盘中交易、止损止盈和协方差优化；
- 前端手输窗口、权重、K、阈值、公式或模型超参数；
- 自动搜索Signal子集、K、权重或Strategy参数；
- Active Product中的静默自动重训或静默换模型；
- 微服务拆分和v0.1遗留代码的大爆炸清理；
- 把Product宣称为已统计验证、可实盘或可向客户推荐的策略。

## 4. 总体架构与导航

### 4.1 架构

继续采用PostgreSQL + Python/FastAPI + React的模块化单体。Web API和长任务Worker使用独立进程，共享同一数据库和正式领域服务。

正式领域扩展为：

```text
catalog → data → factor → signal → model → strategy → experiment
    ↘        lineage / ops / workspace                    ↘ product
```

新增两个正式模块：

- `workspace`：Research Draft、选择上下文、兼容矩阵、Compiled Research Spec、规模估计和Run提交；
- `product`：Product Version/Enrollment、Monitoring Snapshot、Alert、Review与生命周期。

### 4.2 前端导航

- `Workspace`替换`Research desk`并成为默认首页；
- Research保留`Assets / Factors / Signals / Models / Strategies`；
- `Experiments`容纳运行状态、预测诊断、策略排名和结果详情；
- `Products`替换`Compare`，展示研究候选及样本外监控；
- 独立`Data`页面与导航移除；数据质量、覆盖和Eligibility进入Workspace/Assets，完整Artifact进入System；
- 独立`Compare`页面移除；实验比较属于Experiments，产品比较属于Products；
- System保留Runs、Artifacts/Lineage和API。

### 4.3 API原则

- GET保持只读，浏览器不计算金融结果；
- 新增受控POST Command API，API只做状态、权限、版本、幂等与命令提交；
- 关键命令使用Idempotency Key、expected revision、审计事件和稳定reason code；
- 本版仅监听loopback，操作者使用本地稳定`researcher_id`。

## 5. 正式对象、身份与不可变性

### 5.1 研究链

```text
Mutable Research Draft
→ Immutable Compiled Research Spec
→ Compiled Model Instance(s)
→ Strategy Instance(s)
→ Compiled Strategy Version(s)
→ Experiment Suite / Cell / Attempt / Result
→ Product Version + Product Enrollment
→ Append-only Monitoring / Alert / Review
```

- Draft可自动保存、复制、修订，并使用乐观锁；
- Compile发布不可变Spec；Run只能引用Compiled Spec；
- 相同语义配置产生相同Fingerprint并复用已有Artifact；
- `Accepted Result`仅表示系统质量验收通过，不表示研究者点赞；
- 研究者的选择动作是`Promote to Product`，Promotion本身进入审计和Selection Context；
- 不设置Experiment人工Accept/Reject门禁，也不设置长期Product Draft。

### 5.2 Compiled Strategy与Materialization分离

`Compiled Strategy Version`冻结日期无关的规则图：精确Signal集合、Model Preset或Training Policy、Strategy Preset、Asset Set或Universe Methodology、Defense、Schedule和Execution Policy。

具体Experiment或Monitoring Materialization另行冻结：Universe History Publication、Data Bundle/Vintage、as-of、区间、Engine、Benchmark Set、Cost Model和Metric Catalog。Product因此可以在不改变规则身份的前提下消费未来As-Known Data Vintage。

### 5.3 Product拆成Version与Enrollment

- `Product Version`不可变，依赖Compiled Strategy、Qualification Bundle、Monitoring Policy、Benchmark Set与Capital/Cost Policy；
- `Product Enrollment`表示一次激活和样本外观察周期，保存Lifecycle、revision和生效时间；
- Lifecycle Event、Monitoring Snapshot、Alert Transition、Review Decision全部append-only；
- 同一Compiled Strategy Fingerprint同一时刻最多一个active/suspended Enrollment；
- v0.2历史`strategy_product_*`作为Legacy Compiled Strategy只读保留，不篡改既有Artifact类型、指纹或历史Result。

## 6. 统一选择、卡片与参数治理

### 6.1 选择流程

标准链路为：

```text
Asset / Asset Set / Universe
→ Factor Definition + Variant
→ Signal Template + Version
→ Model Definition + Preset
→ Strategy Definition + Preset
→ Compile / Run
```

Asset、Factor、Signal、Model和Strategy均可多选；卡片内部已发布参数版本可按本层契约单选或多选。所有多选展开成明确不可变分支，不把数组临时塞入算法。

### 6.2 统一交互

每层必须支持：

- Family/分类聚合信息卡；
- checkbox或版本选项；
- 中文名、英文名、symbol/key、alias、family、标签、公式说明等多字段搜索；
- 一次查询命中多个对象，精确symbol/key优先；
- 搜索仍能找到置灰对象；
- 不合法项置灰并显示稳定reason code、缺失输入和修复建议；
- 详情、数据导出、覆盖/缺失、版本、血缘与来源；
- 从详情跳回Workspace后保留Draft上下文。

### 6.3 参数规则

- 前端只能选择代码和Catalog已经发布的Version/Preset；
- 不提供任意数字、公式、权重、Target、K或超参数输入；
- 新参数必须修改底层代码、Schema/Catalog、测试和版本后发布；
- Workspace实时显示选择数、下游合法数、分支树、复用数、预计耗时和存储；
- 不设置任意很小的产品级实验上限，允许明确提交长任务；仅保留部署层可配置资源安全限制、确认、取消、恢复和失败处理；
- 上游变化使已选下游失效时保留原选择并标记`selection_invalidated`，不静默删除。

## 7. Asset、Catalog、Data与Universe

### 7.1 Asset页面

Assets页面整体重做，采用“分类卡 → 分类内资产卡”，并提供全局搜索。首版分类至少覆盖股票、ETF、指数/参考序列、防御资产，以及展示型国际股票、固定收益、商品、外汇、数字资产、房地产、波动率和宏观数据。

卡片与详情至少展示：身份、symbol/alias、市场/币种、资产类型、用途标签、数据成熟度、研究/Product能力、覆盖期、最新日期、缺失、公司行动、流动性和血缘。支持下载经清洗的canonical数据，并提供价格/总回报、回撤、成交量/ADV、覆盖与缺失等简单图表。

能力状态使用明确Capability，不用“目录里有”冒充“已进入正式研究/Product链”。资产类型改为可扩展Instrument Type + Capability，而不是继续堆叠硬编码Check Constraint。

### 7.2 稳定资产身份

`security/asset/issuer`是跨Release稳定身份，不归属于某一次Master Data Release。元数据变化使用时效版本或Release Membership；旧发布物不可修改。

多股权类别按issuer去重，每个Universe Snapshot冻结`primary_selection_security`。Ticker变更、合并、退市和公司行动通过稳定ID与事件链接，不能以当前ticker覆盖历史。

### 7.3 主股票Universe

默认股票Universe为`US Liquid Large-Cap 300 PIT`：

- 美国主要交易所普通股，美元计价，排除ETF/ETN、ADR、优先股、权证、SPAC unit、OTC和无法核验公司行动的证券；
- 建议首版数据规则：价格≥5 USD、上市≥252 Sessions、60日有效交易≥55、60日中位成交额≥50M USD、20日中位成交额≥40M USD、当时可得市值≥10B USD；
- 通过门槛后按PIT free-float/total market cap与60日成交额选择最多300个issuer；
- 现成员排名不差于375可保留，新成员优先进入前270，最终目标300；
- 每季度重构，Rank Date、data cutoff、publication和effective session由版本化日历冻结；精确日期在P0数据/日历验证后发布，不能按回测收益移动；
- Universe正式身份为`methodology version → history publication → snapshot → candidate evaluation → membership`。

若没有合格PIT market cap/shares、issuer映射、退市与事件Provider，只能发布明确标记的Liquidity-only或Current Snapshot Exploratory Universe；不得宣称严格大盘PIT，也不得取得Formal/Deployable Product资格。按照第22.1节，它仍可在完整六格身份通过后，由研究者手动登记为带不可移除警告的Product Research Candidate。

### 7.4 退市与终止收益

Formal股票数据必须支持退市、现金收购、换股合并、破产归零等terminal event与terminal total return。Predictive Target和Portfolio Accounting按事件生效日处理，不等待不存在的下一开盘，也不静默删除失败公司。无法核验对价时，对应资产/区间阻断Formal状态并给出原因。

### 7.5 防御篮子

防御资产进入正式链路，但篮子权重不可由前端修改。发布两个绝不自动拼接的版本：

1. `Standard Defensive Basket Long-History v1`：Synthetic Reserve 40%、IEF 25%、TLT 10%、TIP 15%、IAU 10%。用于长历史研究；Synthetic Reserve不是可交易证券，因此该版本不能获得Tradable Product资格。
2. `Standard Defensive Basket Tradable v1`：SGOV 40%、IEF 25%、TLT 10%、TIP 15%、IAU 10%。只从全部成分真实可用且数据契约通过后运行，可参与Product资格。

## 8. Factor

- 保留v0.2的12个派生Factor Definition与28个Variant并迁移为Family卡；
- 同Family只显示一张Definition卡，展开已发布Variant，例如w20/w40/w60；Variant允许单选或多选；
- canonical `open_raw/high_raw/low_raw/close_raw/volume_raw`及明确命名的adjusted序列以Raw/Source Factor Definition形式进入因子库，引用canonical数据而不是复制第二份数值；
- 原始Factor不会自动生成Signal；
- Factor局部缺失只影响对应asset/date，不能让整个Dataset失败；
- Dataset使用Manifest引用可复用Value Partition，并保存missing reason；
- 页面支持搜索、多选、导出、覆盖/缺失、分布、异常、Variant比较和完整血缘；
- Factor页面只做数据本体诊断，不显示未来收益、IC、Top-Bottom或策略收益。

## 9. Signal

- 保留v0.2的27个Template与51个Version，按Template卡聚合；
- 只有依赖当前已选Factor Variant的Signal Version可选，其他版本置灰；
- 用户可多选Signal；不同参数Version是真实不同版本；
- 局部Factor缺失传播为该asset/date Signal缺失，不填0、不删除其他资产；
- Signal页面展示方向、输出类型、归一化、频率、适用Universe、覆盖、缺失、分布、事件率、稳定性、冗余与血缘；
- 经验相关性只对当前上下文/选中集合形成版本化冗余提示，不置灰、不硬互斥、不自动剔除；
- 未来收益Target、Rank IC、Spread、共同评价区间和benchmark全部进入Experiment Predictive Diagnostic。

## 10. Model

### 10.1 Family与输入契约

v0.2的86个固定Specification分类迁移，不平铺成86张选择卡。首批主要Family：

- Deterministic Linear Aggregation，single-signal是其退化基线；
- Directional Voting；
- 未来Training/Ranker/LLM等按不同训练、推理、输出和生命周期契约新增Family。

每个Model Preset声明结构化Input Slot：允许的dimension/family、output type、frequency、min/max count、重复政策和必填语义。

每个候选Model/Preset必须消费**全部已选Signal**。任一Signal不兼容、无法唯一入槽、输入不足、溢出或重复使用，整个候选置灰；不得挑兼容子集，也不得自动枚举子集。每个Signal Version在单个Model Instance中最多使用一次。

多个Model Definition/Preset可同时选择，但只生成并行Model Instance。每条普通Strategy Instance始终绑定一个精确Model Instance；多模型聚合只能作为Packaged Strategy。

### 10.2 运行时缺失与共同集合归一化

普通确定性聚合Family采用`complete_compiled_input_set`：某资产某日缺少任一编译输入时，该资产当日没有Model Score，不对剩余Signal重归一化。

在每个Branch/Decision：

1. 取得PIT Eligible且全部选中Signal均有效的共同资产交集；
2. 检查正式Coverage Gate；
3. 对每个连续Signal在该共同交集内执行Family声明的Branch-local centered percentile rank/normalization，并对齐为higher-is-better；
4. 按Preset聚合为单一`model_score`。

原Signal值、实际`normalized_input_value`、共同集合、归一化Policy、tie处理和输入贡献分别保存并进入Fingerprint/Lineage。未来训练模型使用自己冻结的预处理Pipeline，不自动套用确定性Rank政策。

### 10.3 输出与Target

- 普通Model输出一个有限、可横截面比较、higher-is-better的`model_score`，以及status/coverage/reason；
- `abs(score)`只能称`score_magnitude`，不能冒充confidence；真正校准置信度为未来可空元数据，首版Strategy不消费；
- Output Contract声明范围、分辨率、时间语义、frequency、comparability和missing；
- Output Schedule属于Compiled Model Instance身份。同一选择被weekly和monthly Strategy使用时形成两个独立可复用输出分支；
- 训练型Model的`training_target_version`是正式参数，不同Target产生不同Model Instance；
- 确定性Model的分数算法不因Target改变，但每个Target Kind与Horizon仍形成独立Model Instance、预测诊断与策略实验分支；
- 实际`evaluation_target_version`必须与Compiled Model Instance冻结的Target一致。

### 10.4 训练模型进入Product

训练型Model不会因类型被排除。只有完整策略实验优秀、全部系统门禁通过且研究者手动选择时才能升级。

必须冻结：Feature Schema、预处理、Training Target、训练窗口、rolling-origin时间切分、purge/embargo、超参数、随机种子、训练代码/环境、Artifact发布和失败政策。Qualification验证`Training & Deployment Policy`：每个历史折只使用截止点前数据训练，并在该折后续固定OOS段保持Artifact不变。

Promotion时按同一Policy和激活截止数据生成最终`Activation Model Artifact`，同时冻结`activation_training_cutoff`。v0.21 OOS期间冻结该Artifact，不自动重训。任何新训练Artifact都是Replacement Candidate，必须重新实验、完成6格资格并显式替换旧Product。

## 11. Strategy

### 11.1 共同排序契约

- 输入是每资产/决策时点唯一`model_score`；
- 首版所有横截面排序Strategy只接受`continuous comparable score`；当前Directional/Voting Model只能进入Predictive Diagnostic，不能连接ETF或股票Top-K；未来连续投票强度必须作为新Model Version重新审查；
- missing/abstain资产不排名，neutral是合法值；后续资产自然补位；
- 每个Formal Decision必须满足`rankable / eligible >= 90%`；
- `rankable < K`或任何硬约束后无法形成K个槽位时Decision失败，不缩小K、不放宽约束、不用Reserve伪装；
- Equal Slot Weight固定，首版不按Score大小赋权；
- 连续分数偶发精确并列使用公开的边界槽位比例分配，不用ticker等隐藏字段破坏并列；
- 决策使用截止时已知信息，下一合法共同Session raw open执行。

### 11.2 Multi-ETF Cross-sectional Top-K Rotation

- 接受任意冻结且Strategy Ready的ETF Asset Set；
- 默认`US Style Rotation 4 ETF Sample v1`为IWF/IWD/IWO/IWN，仅是无操作默认、开发Fixture与演示Sample，不是Family上限，也不保证100M Product Eligible；
- 每个Formal Decision至少2只ETF有合法Score；90%规则使2～4只小集合通常要求全覆盖；
- K发布固定选择题`1/2/3/5/10/20`，默认四ETF Sample使用K=2；运行时必须满足`K <= floor(当期rankable ETF数量 / 2)`，确保至少一半ETF留在组合外，不允许因资产不足自动缩小K；
- Frequency：weekly（默认）或monthly；
- Defense：none、fixed_20或Packaged `internal_timing_v1`；
- 不发布buffer和sector cap；
- Primary Benchmark为SPY，Research Benchmark为所选ETF Set同频等权再平衡。

### 11.3 US Large-Cap Cross-sectional Top-K Selection

- 默认`US Liquid Large-Cap 300 PIT`；
- Formal要求每个Decision `eligible >= 100`、Coverage≥90%且最终可形成K个槽位；50～99只只允许Exploratory，少于50拒绝启动；
- K：10、20（默认）、30；
- Frequency：monthly（默认）或weekly；
- Selection Buffer：none或half-K（默认）；首次建仓无buffer，随后原持仓排名不差于`K + floor(K/2)`时可被保留；
- Sector Cap：none或PIT行业风险预算30%（默认）；没有合格PIT行业数据时30%选项置灰；
- 先处理满足Sector Cap的保留持仓，再按最新Score补位；最终不足K硬失败；
- Defense：none、fixed_20或Packaged `internal_timing_v1`；
- Primary Benchmark为SPY，Research Benchmark为同一PIT Eligible Universe同频等权再平衡。

### 11.4 内置防御控制器

`internal_timing_v1`不接受第二个前端Model。它是Packaged Strategy内部固定、可审计的控制器：

- 输入：决策截止时可得的SPY与SMA200状态；
- SPY高于SMA200 2%以上：Defense Budget 0%；
- SPY位于SMA200 ±2%：Defense Budget 20%；
- SPY低于SMA200 2%以上：Defense Budget 40%；
- 缺少SPY或SMA200时Decision失败，不静默回退；
- 只改变Defense Budget，不影响主模型排序；
- 控制器、输入、阈值、篮子版本与血缘冻结进Strategy Version。

## 12. Workspace与编译

Workspace负责可变选择和预检，不展示收益排名。页面按Asset→Factor→Signal→Model→Strategy逐层显示：已选数量、合法候选、失效选择、兼容边、分支数、复用、预计计算/存储和阻断原因。

Compile必须：

1. 规范化全部Version选择；
2. 验证全量Signal→Model Slot与Model→Strategy兼容；
3. 展开每个合法Model Instance×Strategy Preset；
4. 解析不可变Asset Set/Universe Methodology、Schedule和Policy；
5. 生成Compiled Spec、Comparison Context与Fingerprint；
6. 展示自动产生的Predictive和Portfolio Cell数量；
7. 只在运维资源安全限制触发时阻止提交，不隐式采样。

点击Run后，Draft不再影响已经发布的Suite。相同Fingerprint已有有效Result时直接复用。

## 13. Experiment

### 13.1 两类实验

1. `Predictive Diagnostic`：承接Signal/Model相对冻结Evaluation Target的Rank IC、分组收益、命中、稳定性、覆盖、冗余和训练诊断；
2. `Portfolio Backtest`：承接Strategy Target、持仓、成本、容量、NAV、Benchmark和绩效。

Workspace一次Run自动生成所选Signal/Model去重后的Predictive Cell，并为每个Compiled Strategy Instance生成固定Portfolio矩阵。

### 13.2 固定Portfolio矩阵

每个Strategy Instance固定：

```text
Full Common History / Trailing 3Y / Trailing 1Y
×
base_5bps_plus_impact / base_10bps_plus_impact
= 6 Portfolio Cells
```

- 不提供10Y、5Y、Custom Date或资金下拉框；
- 初始资本固定USD 100M，不增加分支；
- Frequency已在Strategy冻结，Experiment只用于筛选；
- Ranking Metric只改变查询排序，不触发新计算；
- Benchmark Set附属于同一Cell，不为每个Benchmark复制Strategy Cell。

### 13.3 Full Common History与fresh-start

`Full Common History`在Compile时解析为不可变Comparison Context。只有resolved start/end、as-of、数据/Universe、Benchmark、Cost、Accounting和Metric版本完全一致的Result才能混排。新增候选形成新Context，不改写旧Result。

Full/3Y/1Y分别建立带`state_reset_at`的fresh-start Strategy Simulation：区间开始以100% Reserve/Cash、无旧持仓启动；允许读取区间前数据完成Factor/Model warmup；在区间内第一个合法执行点建仓。Selection Buffer不能继承窗口外持仓。每个区间的一条Gross Path由5/10bps两条Cost Path复用，不能从一条全历史Target Path裁切三个窗口。

### 13.4 100M、成本与容量

- 100M是每条Primary/Stress路径的初始Currency Capital，之后订单基于各自演化的pre-trade NAV，不在每期重置；
- 同时保存Currency NAV和归一化Wealth Index；
- raw open用于执行展示、Order Notional、ADV参与率和成本；adjusted return ratio用于总回报与权重漂移；
- 首版允许连续Notional/分数股并在详情披露；
- 每笔交易使用决策时已经可得的Trailing 20 Session Median Dollar Volume与波动率；
- 成本为5或10bps基础摩擦，加版本化Liquidity Impact；Impact采用公开、版本化的square-root family，精确系数与上下限在P0数据画像后冻结；
- Order Notional超过Trailing ADV的5%时为`Capacity Rejected`，不能假设在下一开盘全部成交；
- Capacity Rejected仍保留Gross、目标持仓和容量诊断，但不是100M Formal Accepted Result且不进入正式排行榜；它只能带强警告登记为Research Candidate，不能取得Formal/Deployable资格；
- 四ETFSample不保证通过100M容量。若未来需要较小资金或多日执行，发布新的Capital/Execution Policy Version，不能静默放宽旧结果。

### 13.5 Benchmark

两个Family都使用SPY Buy-and-Hold作为Primary Ranking Benchmark。同一Cell另附：

- ETF：Selected ETF Set Equal-Weight Same-Schedule Rebalanced；
- 股票：PIT Eligible Universe Equal-Weight Same-Schedule Rebalanced。

Strategy与Benchmark使用相同fresh-start、有效日期、100M、执行、成本和会计版本。QQQ/IWB/RSP等只作资产/参考分析对象，不进入正式Benchmark Set。

### 13.6 Predictive Target与指标

标准流程发布`future_return`与`cross_sectional_relative_return`两种Target Kind，Horizon固定为5/21/63个共同交易Session；训练Target与Evaluation Target必须同时显示但不混称。

相同`Signal/Model Instance + Asset Set/Universe + frequency + target + data version`只生成一个基础预测Artifact，再派生Full/3Y/1Y窗口指标。

- Common：Score/Target覆盖、有效决策数、Mean/Median Rank IC、Positive IC Ratio、IC IR、Score Dispersion和滚动稳定性；
- ETF：预测Top-1与实现收益Top-1一致率、Top-1 minus Bottom-1 realized spread、Top-1集合换手和随机命中基线；两只ETF时Rank IC退化，不作为主要强度指标；
- 股票：Rank IC、Top-Decile minus Bottom-Decile、`precision@20`、Top-20集合换手和随机基线；
- 指标基于原始Model排序，不混入Strategy Buffer/Sector Cap；
- 分位和边界tie使用公开Policy，不用ticker排序；
- 训练模型另显示rolling-origin折、训练/固定OOS、Target、特征重要性和泄漏检查。

### 13.7 Selection Context与多重搜索

6/6只证明技术、数据、会计和容量合格，不是六份独立Alpha证据。Promotion必须保存：来源Suite/Workspace、完整候选分支、可比候选数、预先选择的排名指标、候选排名、选择理由、Promotion时间和研究者。

系统不得把从数千次历史搜索中挑出的最佳结果标记为“Validated”。激活后的OOS轨道才用于检验筛选体系和策略退化；未来若新增Validated层，必须另行设计预注册、锁定Holdout和多重检验政策。

### 13.8 持久队列与系统验收

新增独立`work_item`队列，使用`FOR UPDATE SKIP LOCKED`、lease、heartbeat、cancel request、stage和failure class；相同Specification最多一个active work item。Run Attempt保留每次尝试历史，不充当队列身份。

Cell状态：`queued/running/completed/failed/cancelled/reused`；Suite状态由Cell汇总。只对infrastructure/interrupted失败原样重试；data_quality/capacity/contract失败需要新数据、依赖或Spec。Attempt完成、Result发布、输出链接和Cell终态在最终事务中原子提交。

`Accepted Result`由系统Quality Gate产生。Portfolio至少检查：依赖/指纹、无未来数据、逐Decision 90% Coverage/K、100M容量、raw execution/ADV/公司行动、Benchmark一致性、NAV/权重/成本对账和Run完整性。Predictive检查时间对齐、无泄漏、最小样本、覆盖和非退化横截面。

### 13.9 Experiment前端

三个入口：`Portfolio Ranking / Predictive Diagnostics / Runs`。

- Ranking独立筛选区间、frequency、排名指标、成本情景、Strategy/Model Family和Universe；
- queued/running/failed/cancelled在Runs，不混进Accepted Ranking；
- 点击整行进入详情；升级按钮只在同一策略分支六格完整、计算质量合格且身份一致时启用；Exploratory、Capacity和P0证据缺口改为Research Candidate警告；
- 详情展示Gross/Net NAV、SPY/Research Benchmark、Excess Wealth、Drawdown、指标、换手/成本/ADV、持仓/行业、Decision Explorer、质量、事件和血缘；
- 导出不可变Summary JSON、Metrics/NAV/Trades/Holdings CSV和Quality/Lineage JSON；图表降采样与完整下载来自同一Artifact。

## 14. Product与样本外监控

### 14.1 Product含义

v0.21 Product只是：

> 研究者从历史实验中选择、正式登记并开始接受样本外观察的Research Candidate。

它不是已验证策略、实盘策略或客户推荐。真正策略仍需独立实盘验证。UI必须显示`Research Candidate`，不得显示`Validated`或`Live Ready`。

### 14.2 Promotion与资格

- 入口位于单条Portfolio Result详情，系统自动聚合同一Qualification Context下精确Strategy的6格Bundle；
- 6/6必须来自同一Suite/Compile Submission，并共享Compiled Strategy、as-of、Data/Universe History、Engine Set、Benchmark Set、Metric Catalog、100M和Impact Model；
- 质量失败、未完成、缺格、身份不一致或invalidated依赖阻断；Exploratory/non-PIT、Capacity Rejected、terminal/impact证据缺口作为不可移除警告；
- Modal展示身份、6格、Selection Context、100M、Primary/Stress、Benchmark、监控起点和不可修改声明；
- 研究者填写名称、可选备注和选择理由后原子创建Product Version/Enrollment并激活；
- 不设置长期Draft；同Fingerprint同一时刻最多一个active Product。

记录`activated_at`、`monitoring_start_at`、`first_decision_at`和`first_execution_at`。`monitoring_start_at`固定为激活后的第一个合法Decision截止点，OOS从该点以100% Reserve开始，随后在首个合法Execution按Schedule建仓；Promotion到该Decision前只显示`awaiting_first_decision`，发布前历史不能回填为OOS。

### 14.3 三条历史轨道

1. `Qualification Backtest`：Promotion时6格证据，永久冻结；
2. `Extended Frozen-Definition History`：同一定义延伸到最新数据，仅作统计辅助；
3. `Post-Activation OOS`：从激活后As-Known数据形成，是检验Research Candidate的主要轨道。

三者不得拼成一条无边界净值曲线。

### 14.4 OOS计算

- 新正式Data Bundle发布后Active Product进入持久监控队列；
- Primary使用5bps+impact，Stress使用10bps+impact，均从100M开始并独立演化；
- 每个Session追加NAV、Benchmark、持仓、成本和容量；Decision日追加Score、排名、Target和解释；
- 动态Universe冻结Methodology，未来Snapshot按同一方法追加；方法语义改变才需要Replacement；
- Monitoring Snapshot冻结as-of、known-at、Vintage、Product、Primary/Stress、Benchmark、指标、Health、Alert与血缘，只追加不覆盖。

### 14.5 Health与最小样本

Lifecycle与Health分离。Health为`observing / healthy / watch / warning / data_interrupted`，由Data/Operational、Capacity、Performance、Predictive/Structural分项组成。

- Data/Contract/Capacity硬异常从第一天即时生效；
- Performance至少126 Sessions；
- Weekly Predictive至少26个Decision；
- Monthly Predictive至少12个Decision；
- 样本不足时指标可展示，但对应分项和Overall保持observing；
- 使用冻结固定长度OOS窗口与Promotion时冻结的同长度历史Reference比较；历史参考窗口不足显示`reference_insufficient`；
- 连续月度复核后10%可watch，连续更严重或多个独立支柱同时恶化可warning/review required；精确阈值、持续次数和Reference进入Monitoring Policy Version；
- Warning只是版本化启发式证据，不是统计断点或自动失效宣告。

### 14.6 生命周期

Lifecycle为`active / suspended / retired / invalidated`，永不物理删除。

- 可随时手动退役；不足12个月且因performance退役时记录`early_manual_retirement/evidence_insufficient`，但不禁止操作；
- 退役使用确认Modal，保存reason、说明、请求时间和生效时间；
- Suspend从下一合法Decision生效，停止新Target，但数据允许时继续估值最后持仓并标记`held_during_suspension`；严重契约问题可Immediate Suspension；
- Resume需预检，在下一合法Decision恢复，不补做错过的交易；
- retired/invalidated不可恢复，再次使用创建新Enrollment和新OOS起点；
- 记录`first_warning_at / review_required_at / retirement_requested_at / retirement_effective_at`，不制造唯一虚假“失效日期”。

### 14.7 替代、迟到与修订

- Model、Strategy、Universe方法、Defense、Execution、Training Artifact或Monitoring Policy发生语义变化时创建新Compiled/Product Version并重新资格；
- Replace冻结显式`cutover_session`：新Product在自己的首个合法执行Session激活，旧Product同Session退役；不同Schedule无需恰好同日决策；
- 数据迟到保留As-Known Gap，不补写成准时Decision/Trade；允许以`market_session + known_at`追加Late Valuation或单独Late Diagnostic；
- 数据修订发布新Vintage，旧Snapshot不覆盖；Corrected Counterfactual单独展示；
- 执行日raw price/ADV缺失、rankable<K或容量超限时不假定成交，保留上一官方持仓并触发Review Required。

### 14.8 Products前端

Products首页为卡片目录，不是研究排行榜，也没有checkbox。支持名称、Model、Strategy、Universe搜索，以及Lifecycle/Health/Family筛选和更新时间/OOS指标排序。

卡片显示：Research Candidate身份、版本、Family、Universe、Lifecycle/Health、激活与OOS年龄、最新数据、Primary OOS收益、相对SPY Excess Wealth、回撤、Alert、下一Decision/Review。

详情使用`Overview / OOS Performance / Decisions & Holdings / Health & Alerts / Qualification / Lineage & Exports`，明确视觉分隔Qualification与OOS。Alert状态为`open/acknowledged/resolved/superseded`；月度Review Decision为`continue/suspend/retire/replace`；所有处理只追加历史。

## 15. 数据与性能实现要求

300股×长历史不能继续使用全量Python tuple、整块JSON hash和单事务物化。正式实现必须：

- 按stage/definition/asset batch/date range流式计算；
- Value表保存稀疏有效值，另存asset/date/stage/reason missing status；
- Dataset以Manifest引用Value Partition；
- Artifact内容哈希使用排序后的Partition Hash Manifest；
- 为横截面计算增加date-first索引，必要时使用表分区或列式Artifact；
- Partition是重试、复用和增量计算单元，Dataset Manifest最后原子发布；
- 大列表采用服务端搜索、稳定游标分页和虚拟列表；
- 图表降采样与完整导出都派生自同一不可变Series Artifact。

## 18. 最终验收标准

1. Draft刷新、复制和Compile后均能还原精确Version选择；
2. 所有已选Signal要么全部进入Model，要么Model/Preset明确置灰；
3. 多Model只产生并行分支，每条普通Strategy只绑定一个Model；
4. 所有参数只来自发布Version，前端没有数字/公式输入；
5. 局部Factor/Signal/Model缺失不让无关资产失效，并有reason；
6. 确定性Model在共同有效资产集合内归一化，原值和实际输入均可追溯；
7. Directional/Voting Model不能连接首版Top-K；
8. ETF/股票每个Formal Decision都执行90% Coverage与绝对数量门禁；
9. 任何硬约束后不足K均失败，Reserve不掩盖故障；
10. Dynamic Universe、issuer去重、PIT行业和terminal event无未来信息；
11. Full/3Y/1Y各自fresh-start，Buffer不继承区间外持仓；
12. 每个Strategy精确生成三条Gross状态路径和六个Portfolio Cell；
13. 100M真实进入订单、成本、ADV和Currency NAV；
14. Capacity Rejected可诊断但不能进入Formal排名或Product；
15. Strategy与Benchmark共享完全一致的执行、成本、资金和日期；
16. Predictive Target、训练Target和评价Target不混称；
17. 相同语义Fingerprint复用，不同Context不拼接；
18. Work Item崩溃可接管，取消、重试和失败分类可审计；
19. Accepted只代表系统质量，不存在隐含人工Accept门；
20. Promotion必须聚合同一Context 6/6并保存完整Selection Context；
21. Product始终显示Research Candidate，不宣称Validated/Live Ready；
22. OOS严格从激活后As-Known数据形成，Qualification/Extended/OOS不拼接；
23. 训练Product冻结Policy与Activation Artifact，不自动重训；
24. Monitoring在126 Sessions、26 weekly或12 monthly Decision前保持observing；
25. Lifecycle与Health分离，暂停、退役、替代不删除历史；

- Target Kind固定为`future_return`与`cross_sectional_relative_return`；后者等于同一Decision/Horizon下资产Future Return减去当期有效Universe等权均值。

### 22.4 资产数据输入与基本面边界
