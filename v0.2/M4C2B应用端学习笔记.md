# M4C2B 应用端学习笔记：为什么 API 与页面也属于研究可信度

## 这层解决什么问题

数据库里有正确结果，不代表用户一定能正确阅读它。只读 API 把发布物转换成稳定契约；页面再把目标频率、样本区间、经济方向、质量状态和血缘放在指标旁边，降低脱离上下文解读数字的风险。

## 关键选择及优缺点

- weekly/monthly 必须显式选择：优点是不会混排不同目标；代价是用户需要切换两次才能比较。
- API 返回上游 artifact 身份：优点是每个结果都可追溯；代价是响应字段更多。
- 页面使用后端统计，不在浏览器重算：优点是 API、导出和页面口径一致；代价是新增指标必须先完成后端发布。
- 高相关只提示不删除：优点是保留研究判断；代价是信号列表可能显得重复。
- 上游页面不显示策略收益：优点是不会把某个策略环境下的表现误写成 Signal 固有能力；代价是用户需要到未来的策略/实验页面查看最终收益。

## 实际检查页面时看什么

先确认频率、未来收益目标、共同区间和共同期数，再看 Signal 方向与经济解释。随后同时看 Rank IC、正 IC 比例、Top-Bottom、年度稳定性和质量提示。最后检查冗余诊断与血缘，而不是根据某一个最高数字直接认定 Signal 有效。

## Docker 补测的意义

组件测试证明页面能正确解释 API 契约，Python 单元测试证明查询和响应规则成立；PostgreSQL 集成测试才证明真实迁移、发布数据和 SQL 查询可以首尾连接。因此当前结果适合继续开发，但回到可启动 Docker 的环境后仍要补跑集成回归，才算完成真实数据库验收。
