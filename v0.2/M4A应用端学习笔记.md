# M4A 应用端学习笔记

## 模板、正式信号和版本有什么区别

模板是批量生成规则，例如“对这些收益窗口都建立 continuation”。正式信号是研究和模型真正引用的对象，例如 5 日 continuation 与 252 日 continuation。版本则表示同一个正式信号的规则发生了时间上的替换。把并行参数误当成版本，会让人以为 v5 淘汰了 v1，也无法同时构建多窗口模型。

## 为什么 Signal 必须直接引用 Factor Variant

只说“使用动量因子”无法重算结果，因为窗口和公式版本不明确。直接引用 Factor Variant 可以准确回答它使用 20 日还是 252 日测量。优点是血缘可靠、错误容易定位；代价是正式对象数量更多。

## 为什么连续信号和事件信号不能共用一种标准化

连续信号比较每个日期资产之间的相对强弱，适合横截面排名。穿越事件表达“今天是否刚刚发生某件事”，如果再次排名会把没有事件的 neutral 状态扭曲成相对好坏。二者需要共同的发布框架，但需要不同的计算语义。

## 为什么 prediction horizon 不直接写死为周或月

同一个信号可以分别评价未来一周和未来一月，两项结论可能不同。将期限放入版本化 evaluation target，可以复用信号原值，又能明确收益起止价格、执行延迟和交易日历。代价是评价对象更多，但不会把某个市场环境下的结论冒充信号永久属性。

## 审查类似设计时可以问

1. 参数不同的对象是并行研究信号，还是确实是前后替换的版本？
2. 信号是否只引用一个精确 Factor Variant？
3. 方向、标准化、极值、缺失和并列规则是否全部显式？
4. missing、neutral 和 event absence 是否被严格区分？
5. 模型维度是否错误地固化在 Signal definition 中？
6. 预测期限是否通过明确目标绑定，而不是藏在代码默认值里？
