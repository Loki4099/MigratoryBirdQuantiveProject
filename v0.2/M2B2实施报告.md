# M2B2 实施报告：真实采集适配器与 XNYS 日历

## 交付结论

M2B2 已把 M2B1 的数据契约和 snapshot 存储接到真实数据入口。系统可以显式抓取 Yahoo/yfinance 日线 wrapper 输出和 FRED CSV 原始响应，生成版本冻结的 XNYS sessions，并通过 artifact DAG 保存完整依赖。该阶段仍不把任何抓取结果批准为 canonical research data。

## 已交付

- `YahooYFinanceSnapshotAdapter`：固定 `auto_adjust=False`、公司行动和单线程参数，逐 ticker 保存未清洗 wrapper 表格；
- `FredCsvSnapshotAdapter`：保存 FRED HTTP 响应原始字节、状态及有限响应头；
- `SourceAcquisitionService`：按资产和参考利率分别抓取、生成 snapshot identity 并幂等发布；
- `XNYSCalendarGenerator`：使用 `exchange_calendars` 生成 session、UTC 开闭市时间和提前收盘状态；
- `CalendarPublicationService`：将日历版本和 sessions 原子发布并绑定 master data 与 calendar series；
- `style-rotation data fetch` 和 `style-rotation data calendar`；
- `exchange-calendars==4.13.2` 进入依赖快照。

## 关键边界

1. Yahoo/yfinance 快照是 wrapper 返回表格的未清洗序列化，不宣称是 Yahoo HTTP 原始报文或历史 vendor vintage。
2. FRED 快照保存 HTTP response bytes；解析缺失标记、数值和 availability date 属于 M2B3。
3. `as_of_at` 当前记录抓取完成时点，不凭空声称拥有更早的信息 vintage。
4. 日历版本固定库名、库版本、覆盖区间和每个 session；更换库版本或覆盖区间必须形成新 artifact identity/version。
5. CLI 不隐式选择 latest canonical data；当前命令只发布 source evidence。

## 验证

- 2026 年感恩节休市和次日 13:00 ET 提前收盘案例；
- 适配器请求参数、原始字节和时间语义单元测试；
- snapshot 与 calendar 重复发布幂等测试；
- published calendar session 数据库防篡改测试；
- Yahoo/yfinance 与 FRED 最小真实联网烟雾测试；
- 全量 Ruff、Mypy、Pytest 与 Alembic schema drift 检查。

## 下一阶段

M2B3 将从已发布 snapshot 解析 raw observations，构建 adjusted OHLC 与 DGS3MO canonical dataset，记录 coverage/quality issues，并生成 universe eligibility snapshot。正式因子链路只能消费通过质量门的 published data bundle。
