# M7A1 实施报告：v0.2 Gross 组合会计核心

## 交付结果

本阶段先冻结不依赖数据库的执行与毛组合会计，避免把 v0.1 的成本口径带入新实验链：

- 决策严格映射到冻结执行政策要求的下一共同交易日；
- 每日按“上一收盘持仓→隔夜漂移→开盘调仓→日内收益→收盘权重与 NAV”计算；
- 使用 total-return adjusted open/close，保存 adjusted execution price；
- 初始状态为 100% synthetic reserve，首次建仓产生完整交易比例；
- 保存 gross daily return/NAV、资产与 reserve 收盘权重、执行记录及每只资产的买卖/不交易记录；
- `one_way_turnover` 包含全部 sleeve 的绝对权重变化后除以二；
- `gross_traded_fraction` 只累计可交易资产的绝对权重变化，供后续逐边成本使用；
- reserve 权重变化不被误当成证券交易；
- 不在 gross 会计中混入成本场景，确保 2/5/10 bps 能共享同一目标、漂移权重和 gross 路径。

## 为什么不复用旧 Backtest Calculator

旧计算器将 bps 乘在 one-way turnover 上；v0.2 已确认的口径是对每个实际买入或卖出的资产名义金额收费，因此成本基数必须是 `gross_traded_fraction`。新会计核心单独建在 Experiment 域，可以防止跨版本口径被意外继承。

## 验证

12 个新增黄金样例覆盖：下一交易日映射、区间末端排除、首次建仓、漂移后再平衡、储备收益、两种换手、预算守恒、统一复权比例不变性、确定性重算、缺失价格/储备数据、未来利率、错误权重与伪造执行延迟。

全量 Python 单元测试为 164 passed；Ruff 与 Mypy 全部通过。本阶段是纯计算层，不写数据库，因此没有新增 PostgreSQL migration 或集成测试。
