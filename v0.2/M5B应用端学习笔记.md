# M5B 应用端学习笔记：模型分数是怎样安全地产生的

## 共同暖机与缺失不是一回事

不同 Signal 可能从不同日期开始，例如交叉事件需要上一日状态。模型可以等到所有输入都准备好后再开始，这是共同暖机；但开始以后某个输入突然缺一只资产或一天数据，就是异常缺失。v0.2 允许前者，拒绝后者，避免通过偷偷删行得到看似完整的结果。

## 为什么不能缺哪个就重新分配权重

假设三个 Signal 权重各三分之一，某天缺一个后把其余两个临时改成各二分之一，实际运行的已经不是原 specification。这样结果身份、经济解释和不同日期的可比性都会变化。因此当前选择直接失败并修复数据。

## 加权模型和投票模型输出如何阅读

- 加权模型的 score 保留输入强弱，接近 1 或 -1 表示多个加权输入形成较强同向结果；
- 投票模型先忽略大小、只保留每个维度的方向，score 表示加权投票余量；
- direction 只是 score 的符号；
- confidence 是 score 的绝对值，表示内部一致/强度，不应理解成“有 70% 概率赚钱”。

## 显式输入映射有什么价值

每个 Model component 都记录它实际用了哪一个 Signal Dataset。将来查看某日模型结果时，可以沿着 Model→Signal→Factor→Data 逐层返回准确发布物，而不是根据名称猜测当时使用了哪个“最新版”。

## 应用端检查要点

先检查 specification 和 Model Engine，再看 universe、data bundle、eligibility、覆盖区间与 input-set hash。若两个结果输入集合不同，即使 specification 名称相同，也不应当成完全相同的研究样本直接比较。
