# M3A 应用端学习笔记

## Definition、Version 和 Variant 分别解决什么问题

- Definition 回答“测量什么”，例如 total return；
- Definition Version 回答“这一版怎么算”，包括公式、输入和代码实现；
- Variant 回答“具体用什么参数”，例如 20 日或 252 日。

如果把三者合成一张表，公式升级、参数扩充和概念改名会互相牵连，后续很难说明究竟哪里发生了变化。

## 为什么一个 Dataset 只对应一个 Variant

优点是引用精确、版本变化局部、质量问题容易定位。代价是一次完整运行会产生较多 dataset artifact，但这些对象很小，换来的可追溯性对研究系统更重要。

信号以后不会说“我使用这一批因子结果”，而会说“我使用 total_return 120 日这个参数实例的这一次正式数据发布”。

## 为什么 Factor 表里没有方向

收益、RSI 或偏度只是测量结果。高值究竟代表顺势、反转、风险警告还是不采取行动，属于信号的经济解释。同一个测量可以支持多个方向不同、但都有理由的信号。

把方向放进 Factor 会再次产生 v0.1 的混淆，也会让 IC 等有方向指标被错误当成因子的固有属性。

## 为什么还不能马上在页面看到因子值

M3A 只冻结“对象身份和数据库边界”。真正计算还需要固定 engine version、读取 bundle、验证 eligibility、处理暖机并对 float64 内容确定性哈希。把这些一次性混在迁移中，会让错误更难定位。

## 检查类似设计时可以问

1. 稳定概念、公式版本和参数实例是否被分开？
2. 下游引用的是准确参数实例，还是含糊的一批结果？
3. 方向是否错误地进入了测量层？
4. 新目录版本能否复用未改变对象？
5. 本地机器目录是否与数据库中已发布的原件做过内容校验？
