# M6B1 实施报告：Strategy Product 与目标仓位纯计算

## 交付结果

M6B1 形成了策略规则与完整策略产品之间的正式边界。

- `publish_strategy_product` 按需发布一个完整、不可变的产品身份；
- 产品固定 Model Specification、Strategy Variant、Universe、Schedule 和 Execution Policy；
- 产品不绑定具体 Model Dataset、Data Bundle、Eligibility、成本、基准或区间；
- 模型输出类型必须满足 Strategy Input Contract；
- 复合模型允许进入当前横截面产品；Single-Signal Model 还必须引用 `product_eligible` Signal；
- event-only 等不合格 Single-Signal Model 会被明确拒绝；
- CLI 新增 `style-rotation strategy publish-product`；
- 目标仓位纯计算器实现普通 Top-K、Post-selection Trend Overlay 和 Pre-selection Trend-Eligible Top-K；
- 所有候选资产都产生决策记录，包括零权重资产；
- 边界并列按比例分享剩余 slot，不使用 ticker 顺序；
- 趋势缺失直接阻止计算，不会变成 reserve。

## 为什么按需发布产品

当前 9 个 Strategy Variant、2 个 Schedule 和数十个兼容 Model 会形成上千种组合。它们是可生成空间，不代表每个组合都有现实研究用途。按需发布既保留自动化批量研究能力，也避免仅因笛卡尔积存在就制造大量无使用场景的正式产品。

同一组输入再次发布会复用原 Product Artifact；任一组成版本变化都会形成不同身份。

## 下一步

M6B2 将增加 Strategy Target Engine、Target Path 及逐日决策持久化。它会验证 Product 与 Model Dataset 的 Specification/Universe 完全一致，并为趋势策略绑定同一上下文的辅助 Signal Dataset。

执行、交易、成本与净值仍不属于 Target Path；这些内容在 M7 处理。
