# M6B2 实施报告：不可变 Strategy Target Path

## 交付结果

M6B2 将 Strategy Product 与确定性目标仓位计算接入正式数据链。

- 新增版本化 `strategy_target_engine`；
- 新增 Portfolio Target Path、Model Strategy Target Path 与 Benchmark Target 占位表；
- Target Path 固定 Product、Model Dataset、Universe、Data Bundle、Eligibility 和 Engine；
- 趋势产品必须额外固定同一上下文、正确 Signal Version 的辅助 Signal Dataset；
- 周频和月频仅选择完整周期的最后共同交易日；
- 若数据范围内不存在下一交易日，不生成无法执行的末端决策；
- 每个决策保存 K、实际持仓数、边界并列数和 reserve target weight；
- 每个候选资产都保存 Model score、平均 rank、selection rank、趋势状态、资格、是否选择、目标权重和原因；
- 数据库触发器验证 Product、Model、Signal 与 Target 上下文一致，并保护发布后不可修改；
- CLI 新增 `strategy bootstrap-target-engine` 和 `strategy publish-target`。

## 分层含义

Target Path 回答“在决策日希望持有什么”，不回答“实际以什么价格成交、产生多少换手和成本、净值如何变化”。因此本阶段不保存执行日期、成交、成本、gross NAV 或 net NAV。

执行政策虽然已经属于 Product 身份，但由 M7 Gross Path 将决策日期映射到下一共同交易日 adjusted open。这样同一 Target Path 可以被不同成本场景复用，也不会把目标决策与组合会计混为一层。

## 验证

端到端合成行情链完成 Data → Factor → Signal → Model → Strategy Product → Target Path。测试覆盖精确上下文、趋势辅助输入、调仓日生成、重复发布复用、全部候选行、预算守恒、迁移降级/升级及数据库不可变约束。
