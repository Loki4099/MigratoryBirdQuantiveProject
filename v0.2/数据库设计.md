## 3. v0.2重建原则

1. v0.2使用全新数据库基线，不对v0.1表进行原地升级。
2. 不迁移或保留v0.1运行数据和288次历史回测。
3. v0.2可以自由替换v0.1的表、API和代码结构。
4. v0.2内部所有正式发布物必须版本化、可追溯、不可静默覆盖并可确定性重算。
5. Git历史负责保留v0.1实现，不在新schema中为旧结构设置兼容层。

## 4. 顶层数据链路

```text
Asset / Universe / Data
→ Factor Dataset
→ Signal Dataset
→ Model Dataset
→ Strategy Target Path
→ Gross Portfolio Path
→ Net Cost Path
→ Experiment Interval Result
```

定义层描述通用数学、金融或组合逻辑；dataset/path/result层将定义绑定到具体资产、数据、日期和实验环境。

## 5. PostgreSQL Schema

数据库使用以下实际PostgreSQL schema：

| Schema | 责任 |
| --- | --- |
| `catalog` | 资产、标识、上市信息、分类、资产池、成员、分组、交易日历和资格快照 |
| `data` | 数据序列、原始快照、清洗版本、规范/衍生数据发布、覆盖、质量、数据包 |
| `factor` | 因子定义、版本、参数实例、数据集、数值和本层诊断 |
| `signal` | 信号定义、版本、方向/变换/阈值、数据集、数值/状态和本层诊断 |
| `model` | 模型方法、定义、版本、维度、组件、权重、数据集、数值和评价 |
| `strategy` | 策略族、版本、变体、输入契约、规则和目标组合路径 |
| `experiment` | 比较队列、日程、执行、成本、benchmark、实验套件、路径、结果、指标和排名 |
| `lineage` | artifact注册、依赖边、manifest、supersession和invalidation历史 |
| `ops` | 运行尝试、任务状态、错误日志、质量日志和引擎/代码/依赖血缘 |

## 6. 研究对象的统一结构

因子、信号和模型遵循：

```text
Definition
→ Version / Specification
→ Dataset Publication
→ Values
```

示例：

```text
factor definition: total_return
→ formula version: v1
→ variant: window=120
→ dataset: universe U1 + data bundle D1
→ values: asset_id × observation_date × value
```

定义和版本不绑定具体资产；dataset publication绑定universe、data bundle、覆盖区间和计算引擎。

尽管factor、signal和model values都具有资产—日期—数值形态，仍分别存储在：

```text
factor.factor_value
signal.signal_value
model.model_value
```

不建立通用EAV式`feature_value`表，因为三个层级的单位、状态、约束、质量和诊断语义不同。

## 7. 中央血缘与业务外键

所有正式发布物注册到：

```text
lineage.artifact
lineage.artifact_dependency
```

典型依赖图：

```text
Data Bundle
→ Factor Dataset
→ Signal Dataset
→ Model Dataset
→ Strategy Target Publication
→ Gross Simulation Publication
→ Net Cost Publication
→ Experiment Result Publication
```

血缘图用于统一查询和生成不可变lineage manifest，但不是业务完整性的唯一来源。例如signal dataset必须直接通过外键引用factor dataset；不能只依靠一条多态artifact dependency表示该关系。

## 8. 发布生命周期

### Draft

- 可以编辑；
- 不得进入正式下游计算；
- 不保证保存每次微小编辑。

### Published

- 语义字段不可修改；
- 只能创建新版本；
- 不允许硬删除；
- 可以进入正式下游计算。

### Retired / Superseded

- 不再推荐新研究引用；
- 旧依赖仍然有效；
- 原记录和结果永久保留。

### Invalidated

- 后来确认存在数据、代码或定义错误；
- 保存原记录、原因、时间和操作者；
- 相关下游结果退出正式排名；
- 不进行级联物理删除。

已发布内容的不可修改和不可硬删除必须由数据库约束或触发器保护，不能只依赖应用层约定。

## 9. 连续路径和区间结果

数据库将组合计算拆分为：

```text
Strategy Target Path
→ Gross Portfolio Path
→ Net Cost Path
→ Experiment Interval Result
```

- target path由模型数据、策略、资产池和调仓日程决定，与成本无关；
- gross path由target、执行政策、价格和储备收益决定，保存可跨线性成本场景复用的权重路径和标准化交易比例；
- net path引用gross path并应用一个明确的cost model/bps，使用本net path自己的执行前NAV计算美元交易名义金额和成本；
- interval result引用完整连续路径和固定区间，保存区间指标及上下文诊断。

最近10/5/3/1年的carry-in结果必须引用同一条连续路径，不能各自复制和重新启动每日NAV。不同成本场景共享target和gross路径。

## 10. Benchmark

SPY Buy-and-Hold以及四ETF研究benchmark都使用与主动策略相同的target、execution、cost和portfolio accounting框架。

benchmark只使用不同的target generator，不建立特殊的净值算法：

- SPY：首次买入并持有；
- 四ETF被动等权：首次各25%并持有；
- 四ETF同频等权：按指定schedule恢复各25%。

## 11. 存储范围

v0.2只实现少量资产上的日频数据。PostgreSQL负责保存元数据、市场数据、factor/signal/model values、目标组合、NAV、持仓、交易、指标和血缘。

当前不引入对象存储、Parquet data lake、ClickHouse、TimescaleDB或外部feature store。分钟数据或大规模股票横截面出现后，再根据真实规模重新评估。

## 12. JSONB使用边界

JSONB适合：

- 公式和规则参数；
- 供应商响应元信息；
- 质量问题详情；
- manifest快照；
- 不参与关键筛选和约束的扩展信息。

明确列和外键用于：

- 资产和版本引用；
- dataset关系；
- 日期、频率和区间；
- 方向和状态；
- 权重和成本；
- 发布状态；
- 唯一约束、排序和高频查询字段。

数据库不得退化为“主要数据都在JSON中”的弱约束结构。

## 15. 阶段6B-1：Catalog具体表（已确认）

### 15.1 Asset和Listing

- `catalog.asset`：稳定金融工具身份，ticker不得作为主键；
- `catalog.asset_identifier`：ISIN/CUSIP等带有效期的资产标识；
- `catalog.asset_listing`：资产、交易场所、币种、时区和交易日历关系；
- `catalog.listing_symbol`：带有效期的ticker历史。

同一标识或listing symbol的有效期不得产生冲突。资产ticker变化不创建新asset。

### 15.2 Classification

- `catalog.classification_scheme`；
- `catalog.classification_value`；
- `catalog.asset_classification`。

国家、地区、资产类别、风格、行业和研究标签通过版本化分类表达，不建立强制market层。

### 15.3 Trading Calendar

- `catalog.calendar_definition`；
- `catalog.calendar_version`；
- `catalog.calendar_session`。

calendar session保存交易日、UTC开闭市时间和early-close状态。calendar version注册artifact并作为data bundle成员。

### 15.4 Universe和Group

- `catalog.universe_definition`；
- `catalog.universe_version`；
- `catalog.universe_member`；
- `catalog.universe_group_set`；
- `catalog.universe_group`；
- `catalog.universe_group_member`。

universe version成员不可变，角色包括candidate、benchmark和auxiliary tradable。group结构属于明确的资产池能力，但v0.2首轮不实现方向分组策略，也不预填没有实际用途的分组。

### 15.5 Eligibility

- `catalog.eligibility_snapshot`绑定universe、data bundle、requirement set和请求区间；
- `catalog.eligibility_item`保存每项资产的资格和实际有效区间；
- `catalog.eligibility_issue`保存一个资产的多个不合格原因。

数据缺失不得静默修改universe membership。

## 16. 阶段6B-1：Data具体表（已确认）

### 16.1 定义、原始数据和清洗

- `data.data_series_definition`；
- `data.data_series_version`；
- `data.source_provider`；
- `data.source_snapshot`；
- `data.cleaning_definition`；
- `data.cleaning_version`。

source snapshot保存不可变请求元信息、获取时间、media type、parser version、payload hash和压缩原始payload。当前日频小数据量允许直接使用PostgreSQL bytea，不引入对象存储。

v0.2.0首个Yahoo价格publication使用`auto_adjust=false`取得raw OHLC、Adj Close、volume、dividend和split，并以当日`Adj Close / raw Close`因子统一调整当日OHLC。cleaning version必须记录供应商字段映射、复权算法、获取as-of和算法版本。该publication保证固定抓取快照内可复现，但不是逐历史日期保存的vendor vintage；后续供应商修订只能产生新的source snapshot/dataset publication，不能覆盖旧发布。

正式价格因子必须是对统一比例复权不敏感的收益、比率或标准化量；raw dollar volume明确使用raw close和raw volume。拆股、现金分红、除权日前后、决策日收盘和下一开盘必须有golden fixture，验证公司行动不会产生虚假信号或错误成交收益。

### 16.2 Dataset Publication

- `data.dataset_publication`作为canonical/derived发布头；
- `data.dataset_input`保存直接source snapshot或上游dataset输入；
- `data.daily_bar`保存资产日频价格；
- `data.corporate_action`保存公司行动；
- `data.rate_observation`分开保存observation date和available at；
- `data.reserve_return`保存DGS3MO现金代理的区间累计因子；
- `data.dataset_coverage`；
- `data.quality_issue`。

source raw不进入正式因子链路；canonical/derived dataset均不可变发布。质量severity为info/warning/error，极端值只产生诊断，不自动删除。

### 16.3 Data Bundle

- `data.data_bundle_definition`；
- `data.data_bundle_version`；
- `data.data_bundle_member`。

bundle member通过明确role引用具体dataset publication或calendar artifact。正式实验固定版本，不使用运行时latest。

## 17. 阶段6B-1：Lineage具体表（已确认）

- `lineage.artifact`：统一注册不可变语义版本和发布物；
- `lineage.artifact_dependency`：保存直接依赖、role和有意义的输入顺序；
- `lineage.lineage_manifest`：保存根artifact展开后的不可变依赖快照和哈希；
- `lineage.artifact_status_event`：保存状态变化历史；
- `lineage.artifact_invalidation`：保存错误原因、时间、操作者和替代artifact。

依赖图不得自引用或形成循环。各业务表仍使用明确外键；artifact graph只提供跨层追溯，不替代关系完整性。

## 18. 真实防御资产与Synthetic Reserve（已确认）

真实可交易防御工具属于 `catalog.asset`，拥有listing、价格、执行和交易成本。DGS3MO只是 `data.data_series`，不是asset。

当前策略未使用预算进入synthetic reserve sleeve：

```text
DGS3MO observations
→ versioned reserve return model
→ derived reserve return dataset
→ reserve target/position
```

策略目标和实验持仓分别保存asset position与reserve position；二者权重共同加总为1。reserve不参与排名，也不产生ETF交易成本。

未来加入BIL、SHY、IEF、GLD等真实防御资产时，它们正常进入universe和asset position，并通过新strategy version处理；不得通过替换DGS3MO数据偷偷改变旧储备语义。

## 19. 阶段6B-2：Factor表（已确认）

- `factor.factor_definition`：稳定测量概念和measurement family；
- `factor.factor_definition_version`：公式、输入、单位、时间语义、implementation和精确历史需求；
- `factor.factor_variant`：参数、preset type、parameter hash和resolved history；
- `factor.factor_dataset`：variant在universe/data bundle/engine上的不可变发布；
- `factor.factor_value`：dataset × asset × observation date的非空正式数值；
- `factor.factor_evaluation`；
- `factor.factor_distribution_summary`；
- `factor.factor_pair_correlation`；
- `factor.factor_quality_issue`。

定义版本号在definition内唯一；variant参数哈希在definition version内唯一；value唯一键为dataset、asset和date。暖机期不插入null，暖机后异常通过quality issue表达。

Factor没有经济方向，不保存正IC、正IC比例或有方向Top-Bottom；本层诊断限于覆盖、质量、分布、参数稳定性和因子值相关性。

## 20. 阶段6B-2：Signal表（已确认）

- `signal.signal_definition`：稳定经济解释、economic family和rationale来源；
- `signal.signal_version`：精确factor variant、方向、标准化、极值、missing、输出类型、阈值和期限说明；
- `signal.signal_dataset`：直接引用实际factor dataset，并绑定universe/data bundle/engine；
- `signal.signal_value`：score以及可选state/event，唯一键为dataset、asset和date；
- `signal.signal_evaluation`；
- `signal.signal_evaluation_period`；
- `signal.signal_evaluation_metric`；
- `signal.signal_pair_diagnostic`；
- `signal.signal_research_assessment`。

一个signal version只引用一个factor variant。相反经济方向若分别成立，建立不同signal definition。正式missing不插补为0；neutral、event absence和abstain由明确定义表达。

Signal evaluation绑定forward-return dataset、comparison cohort、区间、频率、共同样本和engine，保存Rank IC、正IC比例、IC IR、Top-Bottom、覆盖、事件频率和相关性等本层诊断。

## 21. Forward Return Dataset（已确认）

在data层增加：

- `data.forward_return_definition`；
- `data.forward_return_version`；
- `data.forward_return_dataset`；
- `data.forward_return_value`。

定义明确预测期限、起止价格、schedule、执行延迟、重叠规则和交易日历。Signal和Model评价共同引用已发布数据集，不在各自任务中临时生成标签。

## 22. 阶段6B-2：Model表（已确认）

- `model.model_method_definition`；
- `model.model_method_version`：算法、输入变换、权重、neutral/abstain、平票和输出缩放；
- `model.model_definition`；
- `model.model_definition_version`：模型族的一版结构和经济假设；
- `model.model_specification`：具体不可变配置；
- `model.model_dimension`：specification内的活跃经济维度、方法和正权重；
- `model.model_component`：dimension内的signal version、输入变换和正权重；
- `model.model_dataset`；
- `model.model_dataset_input`：component到实际signal dataset的显式映射；
- `model.model_value`：dataset × asset × date的score及可选direction/confidence；
- `model.model_evaluation`；
- `model.model_evaluation_period`；
- `model.model_evaluation_metric`；
- `model.model_pair_diagnostic`；
- `model.model_ablation_comparison`；
- `model.model_research_assessment`。

五维结构形成31个非空`dimension subset pattern`。它们不是系统全部model specification的固定总数：不同代表性维度模型、聚合方法或预登记固定权重会形成不同具体specification。M0机器目录必须分别报告subset pattern数量和按生成规则得到的具体specification数量。零权重维度不落入canonical specification。dimension属于specification，不是signal永久属性；同一signal version在一个specification内只能出现一次，权重非负且各层分别归一化。

Model dataset发布时验证所有component都有对应且兼容的published signal dataset，并禁止隐式latest解析。消融结果引用完整模型与消融模型的两次评价，不在单行中伪造增量。

## 23. 诊断Metric和Research Assessment（已确认）

时间序列值不使用通用EAV表。诊断汇总metric允许每层独立的受控窄表：evaluation、metric definition version、numeric value、status、reason和observation count。

Signal和Model的研究判断使用追加式assessment，状态为untested、exploratory、candidate、supported、inconclusive和rejected。publication lifecycle与research evidence严格分离。

## 24. 阶段6B-3：Strategy表（已确认）

- `strategy.strategy_definition`；
- `strategy.strategy_definition_version`；
- `strategy.strategy_input_contract`；
- `strategy.strategy_variant`：K、filter order、equal-slot allocation、proportional-boundary tie、reserve rule和辅助signal version；
- `strategy.strategy_product_definition`；
- `strategy.strategy_product_version`：model specification、strategy variant、universe、schedule和execution policy的完整对外策略身份。

Product version不绑定data bundle、区间、成本、benchmark或具体model dataset，这些由实验固定。

Schedule和execution policy由product version唯一拥有。Experiment specification不得独立选择与product不同的版本；可在manifest和fingerprint中展开两者的artifact id/hash用于审计，但发布验证必须证明它们来自所引用的product version。

## 25. Portfolio Target Path（已确认）

- `strategy.portfolio_target_path`：model strategy/benchmark通用基表；
- `strategy.model_strategy_target_path`：product version、model dataset、eligibility snapshot、data bundle和target engine；
- `strategy.benchmark_target_path`；
- `strategy.target_path_auxiliary_input`；
- `strategy.portfolio_decision`；
- `strategy.target_asset_position`。

所有候选资产均保存决策行，包括未选资产及reason。资产权重和reserve target weight共同为1。Decision只保存决策日；执行日期由execution policy在gross path产生。

## 26. Policy、Cohort和Interval（已确认）

Experiment schema包括：

- `rebalance_schedule_definition/version/event`；
- `execution_policy_definition/version`；
- `cost_model_definition/version`及`cost_scenario`；
- `reserve_return_model_definition/version`；
- `benchmark_definition/version`；
- `benchmark_set_definition/version/member`；
- `comparison_cohort_definition/version/member`；
- `interval_template`；

Comparison cohort固化universe、data bundle、warmup policy、共同data-ready/simulation/metric dates、benchmark set和metric set。Interval保存模板解析日期、as-of、carry-in/fresh-start及underlying simulation start。

## 32. 阶段6C：数值类型（已确认）

会计类数据使用NUMERIC：价格建议`NUMERIC(28,10)`，权重、收益和NAV建议`NUMERIC(38,18)`，rate/bps建议`NUMERIC(20,10)`，volume使用BIGINT。

原始统计研究值使用DOUBLE PRECISION，例如skewness、kurtosis、volatility、Amihud、factor value、Rank IC和correlation，并严格拒绝NaN和Infinity。

Signal score使用`NUMERIC(24,18)`，Model score/confidence使用`NUMERIC(28,18)`。Undefined通过status/reason表达，不存NaN。

## 33. Fingerprint、Hash和Serialization（已确认）

Semantic fingerprint只包含会改变语义的配置和依赖hash，不包含UUID、创建时间、日志和展示名。Content hash包含实际发布行、确定排序、状态和输入manifest hash。严格相同content hash只承诺在相同engine version、依赖锁、schema revision和数值环境内；数值环境变化形成新的engine artifact并进入下游fingerprint。

Canonical serialization版本化，规定key排序、UTF-8/NFC、ISO日期、小写UUID、Decimal规范字符串、float64规范编码、集合排序和ordinal语义。涉及浮点归约的算法必须固定输入排序，不能依赖线程完成顺序。相同fingerprint重算但content hash不同视为determinism failure；跨engine环境的数值接近性由独立容差测试判断，不伪装成相同发布内容。

## 34. 不可变和发布验证（已确认）

Draft parent及child可写；published后禁止payload和child的INSERT/UPDATE/DELETE。生命周期字段只能按允许状态转换并同步写artifact status event。

跨行权重和、输入完整性、共同覆盖、日期对齐、lineage无环等在publication validation procedure中统一验证。验证、hash、artifact、dependency、manifest和published状态切换位于同一原子事务。

上游invalidated后，通过lineage查找下游并标记tainted；tainted退出正式排名但保留内容，后续可重算、invalidated或经审计解除。

## 35. 外键、索引和存储（已确认）

- 业务外键默认`ON DELETE RESTRICT`；
- 状态使用text加CHECK，不使用PostgreSQL native ENUM；
- value表主键采用dataset、asset、date，增加dataset、date、asset反向索引；
- path和position使用path/date/asset复合索引；
- artifact dependency按depends-on建立索引；
- experiment fingerprint唯一；
- 第一轮不默认创建JSONB GIN索引；
- 第一轮不分区；
- 时间序列通过COPY或bulk insert写入。

## 36. 并发、迁移、权限和备份（已确认）

Fingerprint唯一约束、`INSERT ON CONFLICT`和必要的短advisory lock保证幂等；同一spec可有多个attempt但只有一个accepted result。

全新Alembic链建议为：schemas/lineage/ops、catalog/data、factor/signal/model、strategy/experiment、static constraints/views。研究定义通过bootstrap发布，不写进schema migration。重置命令必须严格校验数据库目标并要求显式确认。

权限模型可分为migration owner、application writer和read-only researcher/API，不引入RLS。

正式数据库使用custom-format dump；`ops.backup_record`保存schema revision、Git commit、dump checksum、storage reference和restore verification。备份文件不进入Git。
