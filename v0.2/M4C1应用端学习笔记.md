# M4C1 应用端学习笔记：为什么收益标签要单独发布

## 它负责什么

Forward Return 是“某个决策日之后，资产在明确未来期限内涨跌多少”的统一答案。Signal 评价和未来 Model 评价引用同一份答案，避免各页面或任务临时采用不同收益口径。

## 常见选择与取舍

- 收盘到收盘容易理解，但与本项目下一开盘执行不一致，可能包含实际上无法获得的收益；
- 下一开盘到下一开盘与执行规则一致，解释最干净，但必须具备可靠的复权开盘价；
- 固定 N 个交易日便于统计，周/月调度则更贴近实际产品。v0.2 选择周/月两套独立 target，不能混在同一排名中；
- 运行时临时算标签开发较快，却难以追溯。单独发布会多一些表和步骤，但评价结果可核查、可复用。

## 为什么候选资产和 SPY 都保存

候选 ETF 用于横截面 Signal 评价；SPY 是统一产品 benchmark，并不参与四 ETF 排名。现在把两类收益都按同一行情、日历和算法发布，可供后续研究比较，同时不会把 SPY 错当成候选资产。

## 如何检查实现是否合理

查看任意一条标签时，应能看到 decision date、start date 和 end date，且满足 `decision < start < end`。weekly 和 monthly 应分别展示，末尾尚无完整未来区间的日期不应出现。血缘中应能追溯到 target、资产池、数据包、行情、日历和计算引擎。

## 需要记住的词

- Target：评价预测所使用的未来结果定义；
- Label：某资产、某决策日在该 Target 下的实际数值；
- Horizon：从执行起点到终点的预测期限；
- Look-ahead bias：错误使用决策时尚不可知的未来信息；
- Incomplete tail：数据末尾尚未走完整个预测期限的区间。
