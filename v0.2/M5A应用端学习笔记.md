# M5A 应用端学习笔记：方法、规格和结果为什么要分开

## 三个对象分别是什么

- Method 是通用数学规则，例如加权平均或多数投票；
- Specification 是一次明确组合：启用哪些维度、引用哪些 Signal、采用什么变换与权重；
- Dataset 是未来把某个 specification 应用到特定资产、日期和 Signal Dataset 后产生的结果。

这类似“菜谱方法—具体配方—实际做出的一锅菜”。只保存最终分数，会失去配方；把配方绑定某四只 ETF，又会让数学逻辑无法复用。

## 为什么是 86 个规格

当前目录预先登记了 51 个单信号规格、五个维度的 31 个非空组合、2 个命名固定权重和 2 个投票规格。数量多不是为了自动挑选历史最好结果，而是完整保留计划中的候选全集，避免只发布赢家。

## 投票和加权平均的差别

连续加权保留分数大小：较强的正分可以抵消较弱的负分。投票只关心方向：每个维度先变为正、负或中性，再计算多数或加权多数。两者可以共享维度和权重结构，但经济含义不同，所以 method identity 必须分开。

## 这一步如何帮助检查系统

看到一个 Model 时，应能回答：它使用哪个方法、启用了哪些维度、每个维度包含哪些 Signal、两层权重分别是多少、平票和缺失如何处理。此时还不应看到 CAGR 或 Sharpe；那些属于完整策略实验，而不是配方本身。

## 何时需要重新评估设计

如果未来需要负权重、动态优化、同一 Signal 在多个维度重复贡献、缺失时动态降权或超过两层的组合图，就不能静默塞进当前结构，应新增 method/model version 并重新讨论其经济解释和比较公平性。
