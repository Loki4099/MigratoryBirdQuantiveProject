# M2B1 实施报告：数据契约与不可变原始快照

## 交付结论

M2B1 已建立真实数据进入系统前的证据层。系统现在可以版本化描述供应商、数据序列、请求和字段映射，压缩保存供应商原始响应，并确保发布后无法修改。实际联网抓取和 canonical 数值将在 M2B2/M2B3 接入。

## 已交付

- `data_contracts.v0.2.0.json`：Yahoo/yfinance、FRED 和 exchange_calendars 的机器契约；
- `20260803_04_v02_data_contracts`：数据契约、snapshot、清洗版本和日历版本迁移；
- `data_contract_release`、`source_provider`、`data_series_definition/version`；
- `source_snapshot`：请求时间、抓取时间、as-of、媒体类型、请求参数、响应元数据、原始字节 SHA-256、zlib 压缩 payload；
- `cleaning_definition/version`；
- `catalog.calendar_version/session`；
- `style-rotation bootstrap data-contracts`；
- `SourceSnapshotService` 的幂等发布与原始 payload 恢复。

## 关键语义

1. 原始 payload hash 直接对供应商响应字节做 SHA-256，不经过 JSON 规范化。
2. Snapshot 的 semantic fingerprint 包含请求、时间和 parser；content hash 额外包含响应元数据与 payload hash。
3. 同一份原始字节可以服务于不同请求，payload hash 不被错误设为全局唯一。
4. DGS3MO 的 observation date 与 available-at 语义在契约中分离。
5. Yahoo/yfinance 明确标注为非官方 wrapper，冻结快照不等于拥有历史 vendor vintage。
6. Published 的 definition、version、snapshot 和 calendar session 均由数据库触发器冻结。
