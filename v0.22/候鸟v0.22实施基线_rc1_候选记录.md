## 0. 这次修订解决了什么

三层加工与单聚合层的核心设计保持不变。本次 RC1 主要修正旧计划中会造成返工的部分：

1. 建立唯一权威契约，停止多份草案互相覆盖；
2. Processing 首版只允许人工发布的固定输入图，Solver 不猜测线路；
3. 确定性 Aggregator 不再被强制展开 Target/训练参数轴；
4. v0.21 迁移范围从“四个 Workspace 聚合方式”补全为 51 个 Signal 与 86 个 Model Specification；
5. Target 改为能够表达“下一计划调仓”的 tagged union，并补全退市、停牌和缺失价格政策；
6. Graph 配置、Run 执行和 Result Evidence 三类身份分离；
7. 补全 DAG 原子发布、失败传播、增量执行、对象存储和导出闭环；
8. Product 从“只展示冻结配置”扩展为可以持续生成下一次正式决策；
9. LightGBM 与 RV20 不再阻塞 v0.22.0 核心切换，分别进入 v0.22.1 和 v0.22.2；
10. 前端代表链切片提前，在全量迁移前提供一次可见验收点。

## 2. 不可变的产品与研究语义

### 2.1 图结构

```text
Raw Input
  → Processing Stage 1
  → Processing Stage 2
  → Processing Stage 3
  → one Aggregation Layer
  → Final Signal
  → one Cross-Section Strategy
  → optional Defense Package
  → Experiment / Product
```

规则：

1. Raw Input 位于三个加工层之前，不占加工层。
2. v0.22.0 的 `processing_stage_count=3` 由 Catalog Release 冻结，用户不能修改；前端按层描述动态渲染，避免未来增加 Stage 4 时重构 API/数据库身份。
3. 真实 Processing 计算边只允许跨相邻层；禁止同层边和跳层计算边。
4. 每层允许上一层输出通过 Layer Projection 原封不动到达下一层，因此任一 Raw 或中途 Feature 都能逐层抵达 Stage 3。
5. Projection 不计算、不复制 Payload、不改变 Contract、hash、known-at、方向或经济身份。
6. 每个 Feature Variant Version 恰好有一个人工发布的 Producer；反向祖先闭包必须唯一。
7. 首版 Processing Binding 只允许 `required`。不支持 `one_of`、`optional`、用户选边或 Solver 猜边；不同输入组合发布为不同 Recipe/Node Version。
8. 所有线路由研究者人工设计并经 Catalog 发布，系统不生成随机线路。
9. “模型”不是 Aggregation 专属概念；Processing Node 可以引用已发布的 Frozen Model State、tokenizer、taxonomy 或 calendar 资源，但资源必须通过独立 `node_version_resource_binding` 冻结并进入 execution fingerprint。v0.22.0 不提供 Processing 在线训练。

### 2.2 双向选择

- 正向：用户从 Raw/上游逐层选择；上游选择影响下游合法性，不合法项置灰并显示原因。
- 反向：用户可以直接选择 Stage 3 中要进入聚合的最终 Feature；系统自动点亮完整祖先和逐层 Projection。
- 下游已选择时，必要祖先不可直接取消；只能先取消下游，或执行带精确影响预览的级联取消。
- Draft 只保存显式用户 Intent。祖先、锁、Projection、灰置和合法性均由纯 Solver 派生。
- 只有 Stage 3 的显式选择进入 Aggregation。祖先是否显式、在何处产生，与是否进入 Aggregation 无关。
- 同一 Workspace 中所有候选 Aggregator 接收同一个完整、有序的 Stage 3 显式输入集合；不允许各自静默删列。
- 若没有 Aggregator 能合法接受完整集合，组合不可运行；原始或中间 Feature 可以抵达 Stage 3，但不因此自动可聚合。

前端不是互斥“三状态”枚举，而是四个正交字段：

```text
is_explicit
required_by[]
availability = available | unavailable
lock_state = unlocked | locked_by_descendant
```

已选项始终前置，并使用明确颜色、图标和文字区分 explicit 与 derived。

### 2.3 Family、Variant、Version、Preset 与 Instance

- Family：同一公式/算法、相同输入角色、输出语义、方向和研究假设。
- Variant：同一 Family 下研究参数不同，例如窗口、阈值。
- Version：同一 Variant 的实现或契约版本，不允许偷偷改变研究参数。
- Preset：聚合/训练/策略等被冻结的参数政策。
- Instance：精确输入集合、顺序、Target/Preset 与运行上下文的绑定。

因此：

- `body`、`range`、`shadow` 是不同公式，不属于同一 Family；
- 相同公式的不同窗口属于同一 Family 的不同 Variant；
- 多个输出进入同一个下游不会使它们成为同一 Family；
- LightGBM 使用不同 future-return 窗口、训练窗口或超参数时，只要算法、Objective 和输出语义不变，仍属于同一 Family 的不同 Target/Preset/Instance；
- Objective、输入角色或输出语义改变时必须拆分 Family。

### 2.4 一个实验分支的含义

一个 Experiment Cell 恰好包含：

```text
one exact Stage 3 direct-input set
+ one Aggregation Instance
+ one Strategy
+ zero or one Defense Package
+ one frozen execution/evaluation context
```

用户选择多个 Aggregator、Target/Preset、Strategy 或 Defense 时，编译器生成多个独立 Branch/Cell；不会在一个 Cell 中同时执行多个模型或策略。

## 4. Payload 与数值契约

### 4.1 共享 Payload 基础设施

Payload 属于共享 `data` schema，至少包含：

```text
data.payload_contract_family
data.payload_contract_version
data.payload_contract_compatibility
data.physical_encoding_version
data.payload_object
data.payload_manifest
data.payload_partition
data.payload_manifest_partition
data.payload_publication_lease
data.payload_quality_summary
```

Raw、Processing、Aggregation、Experiment、Model State 和 Export 共用同一基础设施。中间层允许标量、表格、向量、文本、事件、Pattern、文档引用和 Model State 等异构 Payload；端口必须声明精确 Contract 与兼容方向。

三类 hash 不得混用：

```text
logical_payload_fingerprint  # 规范化逻辑内容、Contract、Producer 和输入身份
manifest_hash                # 稳定 ordinal 下全部 partition descriptor
object_content_hash          # 实际存储字节 SHA-256
```

Run input/output 只引用精确 `payload_manifest_id`，不得用裸 `storage_uri + hash + schema` 代替 Manifest 外键。重编码产生新 Manifest，不能修改旧 Manifest。

一个 Node Run 有多个输出端口时，所有输出 Manifest 必须在同一事务中全有或全无地发布；部分输出成功不能成为可复用 Run。

### 4.2 禁止隐式数据加工

除 Layer Projection 和按已发布 Encoding Contract 解码外，Runtime 不允许隐式：

- join、resample、fill、drop；
- dtype coercion、单位/币种变换；
- 实体映射、日历对齐；
- 文本/向量压缩为标量；
- 对缺失列静默删列。

这些行为必须是显式 Processing Node，并进入血缘与 fingerprint。

### 4.3 聚合前与聚合后的数值接口

开放数值 Aggregator 首版只接受共同 `(decision_date, asset_id)` 键上的普通数值标量，并检查 unit、scale、PIT/vintage、方向和覆盖政策。

统一逻辑接口是 `numeric_scalar`，但物理精度必须显式声明：

- v0.21 deterministic parity 路径保留 Decimal 18 位语义；
- ML Feature Assembly 若需要 float64，必须使用已发布、版本化的显式 `decimal_to_float64` Processing Adapter Node occurrence；该 occurrence 进入图、血缘和 execution fingerprint，并冻结舍入/溢出/非有限值规则，不能作为 Feature Assembly 内部步骤隐式 coercion；
- ML raw prediction 保存 float64；
- LightGBM Final Signal 在 Family 内执行版本化的横截面 average-rank centering 到 `[-1,1]`，使“越大越好”和符号方向稳定；
- Strategy 只消费声明 `higher_is_better` 的 Final Signal，不假定所有上游数值拥有同一 dtype。

LightGBM rank-centering 的 v1 公式固定为：在合法推断截面内按 `raw_prediction` 降序排名，ties 使用 average rank；`n=1` 时输出 `0`，`n>1` 时输出 `1 - 2 × (average_rank - 1) / (n - 1)`，因此最佳为 `+1`、最差为 `-1`。非有限 prediction 保持 missing 且不参与 `n`；剩余截面必须满足已发布的 minimum-assets 与 coverage policy，否则该 decision group 失败。

### 4.4 发布、GC 与备份

```text
写临时对象
→ 回读验证 byte hash
→ 获取带 fencing token 的 publication lease
→ 单事务发布 Artifact、Manifest、Partition、Object 引用和 Run Output
→ commit 后释放 lease
→ 延迟清理无引用临时对象
```

Object 状态至少包含 `staging/published/quarantined/deleting/deleted`。GC 使用 mark-sweep，但“不可变血缘元数据”与“物理对象保留”分离：Product/Evidence/Model State、active 或显式 pinned Run、未过期 Export 和 legal hold 是强 root；普通 Compiled/Run binding 只永久保留元数据，不自动永久保留可重算对象。

Manifest/Run 增加 `retention_class` 和 `materialization_state = materialized | evicted | rehydrating`。缓存对象只有在无 read lease、超过 grace period 且不属于强 root 时可两阶段 evict；元数据、logical fingerprint 和血缘仍保留。`evicted`、`quarantined` 或 object 缺失的 Run 禁止缓存命中，必须按冻结图重新物化。备份与恢复同时覆盖数据库和 Object Store，并通过逐强-root Manifest 回读 hash 的 restore drill。

## 5. Aggregation 契约

### 5.1 四个确定性 Family

| Family | 稳定语义 | v0.21 映射 |
|---|---|---|
| `single_signal_identity` | `final = x` | 51 个 single-signal specification |
| `flat_equal_weight_mean` | 所有直接 Stage 3 信号等权 | Workspace `signal_equal_v1` |
| `hierarchical_weighted_mean` | 组件内加权，再按维度加权 | 31 个 dimension subset + 2 个 fixed-weight |
| `directional_weighted_vote` | 维度内先按组件加权形成连续分数，再取维度方向并按维度权重投票；零为 neutral | majority vote + weighted vote |

旧名 `dimension_equal_hierarchical_mean` 改为 `hierarchical_weighted_mean`；equal-dimension 与固定权重只是不同 Preset。旧名 `directional_majority_vote` 改为 `directional_weighted_vote`；majority 是 equal-weight Preset。

每个 Family Version 都发布独立 Input Policy：`single_signal_identity` 只接受一个合法数值输入；均值与投票 Family 只接受方向、尺度、missing/tie 语义兼容的预聚合信号；LightGBM 的“开放数值”只表示可接受人工发布且通过 unit/scale/PIT 门禁的普通数值 Feature，不表示无条件接受任意 Payload。

v0.21 vote parity 的精确运算顺序冻结为：

```text
Q18(x) = Decimal quantize 1e-18, ROUND_HALF_EVEN

dimension_score_d
  = Q18(Σ_i component_weight_di
            × published_component_transform_di(signal_i))

dimension_direction_d
  = sign(published_dimension_transform_d(dimension_score_d))

final_vote_score
  = Q18(Σ_d dimension_weight_d × dimension_direction_d)

direction = positive if score > 0
          | negative if score < 0
          | neutral  if score = 0
confidence = Q18(abs(final_vote_score))
```

dimension score 与 final score 都在上述位置量化；不得先对每个组件直接投票，也不得动态重标权重。majority Preset 的 dimension 权重相等，weighted-vote Preset 使用 legacy 冻结权重。

### 5.2 条件轴与数据库约束

编译器只展开 Family 声明适用的轴：

```text
deterministic instance
  = Aggregation Version × applicable parameter Preset
  target/training policy/model state = NULL

supervised instance
  = Aggregation Version × Target Version × Training Preset Version
  target/training policy = REQUIRED
  fitted model state is NOT part of instance identity
```

数据库必须以 CHECK/trigger 保证上述 nullability/XOR。不得为确定性 Aggregator 伪造 `target=none`，也不得无条件做 Target × Preset 笛卡尔积。

每个 Instance fingerprint 至少覆盖：

```text
Aggregation Family/Version
+ exact ordered Stage 3 occurrences
+ taxonomy/dimension membership Artifact
+ component transforms/weights
+ overall transforms/weights
+ parameter/target/training preset if applicable
+ missing/tie/output policy
```

- 28/28 Factor、51/51 Signal、86/86 Model、Workspace `signal_equal_v1` 以及所有 active Product 引用链均有不可变 Evidence。

## 7. Graph 编译、运行与增量执行

### 7.1 配置与执行身份分离

```text
Research Draft
  → Compile Attempt
  → reusable Compiled Research Graph
  → Graph Run
      → Graph Run Node/Aggregation Binding
          → reusable Node/Aggregation Run
              → exact Payload Manifest
```

- Compiled Graph 不归属于单一 Draft；`workspace.compile_attempt` 记录 Draft/revision/context/diagnostics 到 Graph 的绑定。
- Node/Aggregation Run 不归属于单一 Graph；以 execution fingerprint 寻址。
- `graph_run_*_binding` 记录本次 Graph Run 是 executed 还是 reused，不复制 Run。
- Graph fingerprint 包含精确 Catalog component、Occurrence/Edge/Projection、解析后的 Data Binding、Universe/Calendar/Schedule、Aggregation/Strategy/Defense 和 Compiler Contract Version。
- 瞬时 `data_availability_revision` 只参与合法性校验和 View cache；若实际 Data Binding 未变，不进入配置 fingerprint。精确 Manifest 只进入 Run/Evidence。

Node/Aggregation execution fingerprint 使用 canonical ordering，至少覆盖：

```text
component/instance version
+ resolved parameter/preset values
+ ordered input port identities and exact input Manifest IDs/hashes
+ frozen resource bindings
+ requested range/partition/watermark/checkpoint
+ executor version and environment contract
+ determinism/cache policy
+ payload/encoding reader contract
+ target/fold identity when applicable
```

只有 Run 已完成、所有 output Manifest/Object 均 `published + materialized + readable + not_invalidated`、资源仍有效且环境兼容时才可复用。复用资格检查与新 `graph_run_*_binding`/retention pin 必须在同一事务内完成，避免检查后对象被 GC。

所有写命令通过统一 Command Result 保存：

```text
authenticated actor + command kind + idempotency key + request fingerprint + response
```

Compile 产生不可变 Compile Attempt，不用可覆盖的 `last_compiled_*` 充当审计记录。

### 7.2 DAG 原子发布和失败传播

Graph Run 状态：

```text
planning → ready → running → completed | failed | cancelled
```

Scheduler 在一个事务内创建 Work Item、consumer binding、全部 dependency，验证 DAG 后才把 Graph Run 置为 `ready`。Worker 只能 claim `ready/running` Graph Run 的任务。

Required upstream 失败或取消后，下游必须原子进入：

```text
blocked_upstream_failed
blocked_upstream_cancelled
```

不得永久 queued。每次 claim 产生 lease generation/fencing token；Run/Manifest/任务完成发布时再次验证 lease、token 和 cancel 状态。共享 Work Item 只有在最后一个 consumer 解除后才允许取消。

### 7.3 增量执行

每个 Node Version 必须声明：

```text
execution_mode = full_recompute | append_safe | windowed | stateful
partition_key
lookback/lookforward
revision_impact_policy
watermark_policy
checkpoint_contract
determinism_mode/cache_policy
```

默认 `full_recompute`；未声明增量语义时 Runtime 不得自行推断。每次执行发布新不可变 Manifest，可复用未变化的 partition/object，但不修改旧 Manifest。历史修订只失效声明范围内的输出和 fold。

### 7.4 导出

未物化 Feature 的导出拆成：

```text
Export Intent
  = compiled occurrence + frozen context/time/assets/encoding/policy
→ materialization
→ Resolved Export Request
  = exact Payload Manifest
→ immutable Export Package
```

页面必须先显示预估行数、字节数和运行成本；导出受数据许可、用户权限、审计和过期策略约束。

## 8. Target 与 LightGBM（v0.22.1）

### 8.1 Target Horizon

Target 使用 tagged union：

```text
fixed_sessions(sessions, calendar)
next_scheduled_execution(schedule, calendar)
```

weekly/monthly 首版使用 `next_scheduled_execution`：

```text
decision close
→ next common-session open entry
→ following scheduled decision 后的 next common-session open exit
```

它不得伪装成 H5/H21。每个 Target Version 还必须冻结 entry/exit execution policy、calendar、decision cutoff、overlap、known-at、rank population 和 outcome policy。

### 8.2 Outcome、Purge 与样本资格

`target_outcome_policy_v1` 必须覆盖 PIT Universe、新上市、缺 entry、entry 后退市、停牌/缺 exit、terminal event 和硬失败 reason。不得根据未来 outcome 是否存在来静默删除资产。

首版政策冻结为：

- rank population 是决策时 PIT strategy-eligible 且所选 Feature 在 cutoff 时完整的资产集合；
- Feature 完整性只使用决策时可知信息，不能用未来是否有 exit/terminal outcome 筛选；
- 任一资产缺少合法 entry open 时，formal Target 的整个 decision group 失败，不只删除该资产；
- entry 后发生已解析退市时，使用已发布 Terminal Event total return；
- 缺少 exit open 且没有已解析 terminal outcome 时，整个 decision group 失败；
- unresolved terminal event 阻止 formal publication；
- `target_known_at` 取 entry、exit、corporate action 与 terminal outcome 中最晚的合法可得时间；
- 所有失败保留 asset/date/reason code，不静默缩短样本。

`terminal_event_total_return_v1` 是从最后一个合法 pre-terminal total-return value 到最终 settlement 的增量收益，只包含此后尚未计入 adjusted series 的现金、证券或其他分配。计算固定为：

```text
terminal_value_index
  = last_legal_preterminal_total_return_index
    × (1 + terminal_event_total_return)

forward_return
  = terminal_value_index / entry_total_return_index - 1
```

entry 与 pre-terminal index 必须来自同一 total-return basis 和数据快照；已进入 adjusted series 的股息/公司行动不得在 Terminal Event 中重复计入。Terminal Outcome Artifact 必须保存 basis、最后合法估值时点、settlement 组成和 known-at。

Fold Planner 按每个 label 的真实：

```text
decision_cutoff, entry_time, exit_time, target_known_at
```

判断成熟、区间重叠 purge 和 embargo，不用固定 H 近似。每个 Fold 物化 included/purged/embargo/prediction group IDs 和边界时间。

### 8.3 训练状态与门禁

```text
planned
→ exploratory_available
→ formal_eligible
```

`conservative_v1` 在以下内容全部冻结前保持 `planned`：

- 完整 LightGBM resolved parameters 和默认值；
- PIT Universe、terminal outcome 与 feature vintage；
- 支持的 Asset Context/frequency；
- 最小 train/validation/locked-test groups、每期资产数和 coverage；
- maximum feature count 与 feature/effective-group ratio；
- sample weight、missing、retrain、early-stop 和 freshness policies。

极小 ETF 截面默认不允许 formal。程序“能训练”不等于模型“可发布”。

对象关系固定为：

```text
Aggregation Instance
  → Walk-forward Run
      → Fold Plan
          → Fold
              → Training/Validation Matrix Manifest
              → Model State
              → Prediction Run
      → stitched OOS Final Signal
```

Aggregation Instance 不保存单一 `fitted_model_artifact_id`。Fold 失败不得回退到全样本、旧模型或等权；Product 是否在重训失败时继续旧批准状态由显式 freshness policy 决定。

### 8.4 比较与研究治理

训练首版按日期等权：`n_t` 是该 Aggregation Instance 冻结 Training Label View 在日期 `t` 的实际训练行数，`w(t, asset)=1/n_t`。权重作为 Artifact 冻结；controlled baseline 必须复用完全相同的 row mask 和权重 Artifact。诊断先按日期计算，再跨日期等权；页面同时报告 group 数和 row 数。

Controlled comparison 必须共享精确 `Common Evaluation Panel Artifact`，即有序 `(decision_date, asset_id)` mask。仅区间和行数相同不够。

每个 LightGBM Result 必须在同 Fold/Target/Panel/权重上产生：

1. `target_mean_zero_v1`；
2. `last_matured_rank_persistence_v1`；新上市资产没有成熟历史 rank 时输出 `0` 并记录 `cold_start_zero`，不得删行，同时单列 cold-start coverage；
3. `ridge_same_features_v1`；
4. 输入有合法方向时的 equal-weight baseline。

指标边界固定为：训练和 early-stopping L2、calibration diagnostics 使用 `raw_prediction`；Rank IC、Top-K 与 Strategy 使用 rank-centered Final Signal。Evidence 字段分别命名 `raw_prediction_l2` 与 `final_signal_rank_ic`，不得用笼统的 model score 混合二者。

Evidence 必须区分：

```text
walk_forward_backtest
locked_historical_test
prospective_oos
```

系统记录 Research Attempt、candidate-set fingerprint、trial count 和 selection event。Product 晋级需要不确定性报告、locked evidence 和独立 prospective Enrollment，不能只看最佳点估计。

不确定性至少按 decision date 聚类，使用已发布的 moving-block bootstrap 或 HAC Policy 报告 Rank IC、spread、Sharpe 与 drawdown 差异的区间估计；不能只发布点估计。

## 9. Strategy 与 Defense

### 9.1 v0.22.0 parity

- `multi_etf_top_k`；
- `us_large_cap_top_k`；
- `none`；
- `fixed_20`；

- Timing 与 Allocation 后端分离、前端以 Defense Package 选择；
- risk/defense/reserve 三个袖套保留 attribution，按 asset_id 合并后只计一次交易成本。

### 9.2 v0.22.2 RV20 exploratory

```text
rv20 = sample_std(last 20 complete SPY log returns) × sqrt(252)
if rv20 <= 0 or not finite: hard failure
risk_budget = clip(0.15 / rv20, 0.25, 1.00)
defense_budget = 1 - risk_budget
allocation = reserve_only
```

冻结名称为 `spy_rv20_proxy_target15_floor25_reserve_v1`，UI 显示“SPY RV20 代理波动率预算”。它只支持 Package Version 预先枚举的 long-only、正 SPY beta Asset Context；兼容性由 `supported_asset_context_keys` 冻结，禁止用完整评价期 realized beta 做未来条件筛选。weekly/monthly 只在计划日更新，不宣称日频紧急保护。

除 `none` 外必须提供预注册 Defense `calibration_window` 内平均风险预算的静态 reserve baseline，用来区分“动态择时价值”和“长期平均降仓”。该窗口严格结束于 evaluation/OOS 开始前，进入 baseline fingerprint，且与 Aggregator 是否训练无关。Synthetic Reserve 只能用于 exploratory accounting；formal Product 必须绑定可交易现金/短债工具、真实成本与收益规则。

Package Version 必须冻结：

```text
price_field = vendor_total_return_adjusted_close
return_kind = log_total_return_proxy
decision_cutoff = scheduled_session_close_after_price_finalization
available_at_policy = close_must_be_final_by_decision_cutoff
calendar_key = published_us_equity_calendar
required_price_count = 21
sample_std_ddof = 1
staleness_limit_sessions = 0
execution_policy = next_common_session_raw_open
```

上述字段与精确数据绑定均进入 Package fingerprint。若当前数据源无法证明 adjusted close 的 PIT/vintage 与 available-at，Package 保持 `planned`。

Adjusted open 只能作为总收益核算基准，不等于真实可成交价格。formal Product 执行必须同时绑定 raw open、corporate-action/share accounting 和数据快照，并单独报告 signal-to-execution latency 与 gap loss。

## 10. Experiment 与 Product 连续运行

### 10.1 三类冻结身份

| 对象 | 含义 | 是否重启 OOS |
|---|---|---|
| Product Execution Version | 实际信号、权重和执行路径 | 是 |
| Qualification Version | benchmark、Evaluation Target、指标和晋级证据 | 否，除非同时改变决策 |
| Monitoring Policy Version | 告警、健康度和监控计算 | 否 |

Configuration Snapshot 拆为：

- `semantic_identity_document`：进入 configuration fingerprint；
- `provenance_document`：Draft/Suite/branch 来源，不进入语义 fingerprint；
- `display_document`：名称、翻译和摘要，不进入语义 fingerprint。

Execution Version 必须冻结 Compiled Graph、direct Stage 3 inputs、Aggregator/Target/Preset、Strategy、Defense、Universe、执行/决策成本；训练型 Family 还必须冻结重训与 Model State 激活政策。v0.22.0 确定性 Product 的 `active_model_state_id` 固定为 NULL。

Catalog Release ID 保留在 provenance 中；configuration fingerprint 只包含实际使用的精确 component versions。仅 Release 标签或未使用组件变化，不得重启 Product/OOS。

### 10.2 Product Decision 链

```text
scheduled trigger
→ freeze Data/Availability Snapshot
→ materialize Processing Graph
→ [v0.22.1 trainable only] optional retrain candidate + validation + atomic activation
→ Aggregation
→ Strategy
→ Defense
→ merge sleeves
→ immutable Product Decision
→ OOS Evidence + Monitoring Snapshot
```

每次 Decision 绑定精确 input Manifest、active Model State（确定性时为空）、Aggregation Run、Strategy Target、Defense Decision、merged target、cutoff/session、环境和质量结果。

唯一约束：

```text
(Product Execution Version, decision_session)
```

v0.22.1 的重训失败不得静默 fallback。训练型 Execution Version 必须选择 `suspend_on_retrain_failure` 或 `continue_last_approved_until_freshness_deadline`；超过 freshness deadline 必须暂停。该 activation/freshness runtime 属于 M9，不反向阻塞确定性 v0.22.0 Product。

Enrollment 必须冻结：

```text
oos_anchor_cutoff_at
activation_effective_at
first_eligible_decision_session_id
schedule_version_id
```

`first_eligible_decision_session_id` 是冻结 Schedule 中满足 `decision_cutoff_at > max(oos_anchor_cutoff_at, activation_effective_at)` 的最早 session。只有绑定同一 Enrollment/Execution Version、session ordinal 不早于该 ID 且 Evidence Class 为 `prospective_oos` 的 Decision 才可计入。qualification bridge、historical backfill 和旧版本历史不计入；计划 session 缺口必须保存 reason，不得静默沿用上一决策，也不得跨 Execution Version 拼接 OOS。

### 10.3 版本变化

- Signal/Aggregator/Target/Preset/Training/Strategy/Defense/执行政策变化：新 Execution Version、新 Enrollment、OOS 重启；
- 会改变目标、订单、容量或准入的成本/滑点政策：新 Execution Version、新 Enrollment、OOS 重启；仅用于结果重算的评价成本场景：新 Qualification Version；
- 冻结重训政策下的新 Model State：activation event，不新建 Execution Version；
- 日常数据追加：不新建版本；
- benchmark/评价指标变化：新 Qualification Version；
- 监控阈值变化：新 Monitoring Policy Version；
- 数据修订若改变历史 Feature/Model State/决策：暂停并创建新 Execution Version；若只改变指标，则仅新 Qualification Version。

## 15. 发布与回退

```text
hidden → shadow → explicit_eligible → default
```

v0.21 对象政策：

- 历史 Artifact/Result/Product 永久只读可查；
- 已完成 Suite 可 exact replay；
- 旧 Draft 只读且只能 legacy replay，不再扩展新研究；
- in-flight Suite 使用 pinned v0.21 runtime drain 或显式取消；
- active v0.21 Product Enrollment 继续由 pinned runtime 决策，直到显式迁移或退休；
- v0.21 Product 不自动升级，迁移会创建新的 v0.22 Execution Version/Qualification/Enrollment。

Work Item 冻结 compiler/executor/environment/capability；Worker 只能 claim 自己精确支持的版本。

Rollback 后 Workspace/API 进入 `maintenance_read_only`：禁止新建 v0.21 或 v0.22 Draft、Compile、Suite 和 Product promotion；允许读取/导出历史对象，以及经 operator 批准的 pinned exact replay。active v0.21 Product 继续走 pinned v0.21 runtime；受影响 v0.22 Enrollment 进入 `suspended`，不得偷换成 v0.21 calculator。共享 Work Item 按 consumer 引用决定是否取消。

恢复 v0.22 提交必须完成 incident impact analysis、修复对应 Gate、重跑 parity/restore/rollback drill，并由 Release Gate 显式从 `maintenance_read_only` 切回 `explicit_eligible` 或 `default`。Rollback 不 drop 新表、不重写 Artifact/Result/Snapshot，也不重新开放 legacy 研究创建。

## 16. 资源、安全与部署边界

v0.22.0 首发边界是受信任的单用户本地/私有研究环境，不承诺多租户或公网部署。即使如此：

- actor 必须来自本地认证上下文，不能由请求体自报 `researcher`；
- Draft/Suite/Product/Export 保存 owner 与审计 actor；
- worker 使用受限 service principal；
- Export 在下载时重新检查许可/entitlement，并使用短期 token；
- 日志不记录受限正文、凭据或完整文档内容。

若未来进入多人或网络环境，RBAC、tenant isolation、RLS 和跨租户 cache 隔离是发布阻断项，不作为本轮暗含能力。

Compile 必须返回节点、祖先、Branch/Cell、fold、预计 cache hit、CPU、内存、存储、导出字节与耗时。后端冻结 `max_nodes/max_ancestors/max_branches/max_cells/max_export_bytes/max_solver_cpu`，超限拒绝或要求有权限的显式 override。
