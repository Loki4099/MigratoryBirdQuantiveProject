## 1. 执行摘要

当前故障不是单一前端按钮问题，也不是数据库内容损坏，而是以下问题叠加：

1. 本地后端进程、后端提供的静态前端、数据库迁移处于不同版本；
2. Graph Draft 的恢复把浏览器 `localStorage` 当成权威，换端口或清空缓存后无法找回服务器已有 Draft；
3. 最新前端曾向加工层目录发送 `limit=100`，而后端契约上限是 50，导致 Stage 1/2/3 首屏 422；
4. 变更按钮没有统一只读/错误状态，事件被拒绝时表现为“点击没有反应”；
5. 现存旧 Graph Suite 只有身份、没有 Graph Run/Runtime Plan，却被包装成 `materializing 0/0`，进度详情进一步因响应约束返回 422；
6. 现有组件测试模拟了 API，没有覆盖真实端口、真实响应、空浏览器存储和静态构建，因此不能证明前端可用。

修复目标不是重新建库，而是原地恢复健康数据、建立唯一运行入口，并增加一条真实浏览器验收链。

## 4. 目标状态与核心不变量

### 4.1 单一运行版本

用户只访问：

```text
http://127.0.0.1:8000
```

该入口必须同时满足：

- 后端源码提交 = 构建前端所用提交；
- 数据库 revision = 当前 Alembic head；
- 静态前端是本次构建结果；
- actor、release admission 和数据库连接在启动时明确输出；
- 不依赖 Vite、8001、5174、5175 或 `.codex_work` 临时服务器。

### 4.2 服务器状态权威

- Graph Draft 的权威身份为可信 actor + server-side `draft_key`；
- current revision 是唯一已保存研究状态；
- `localStorage` 只是缓存 Draft ID，丢失缓存不得丢失研究；
- 页面重开、换端口、无痕浏览器或清空缓存后，应恢复服务器现有 Draft；
- 创建、读取、修改、重置均执行统一 owner 校验。

### 4.3 可观察失败

- 查询失败时显示结构化错误、恢复动作和不可操作原因；
- 所有 mutation 控件共享同一只读条件；
- 被拒绝的事件必须向调用方失败，不能静默 resolve；
- 没有 Runtime Plan 的 Suite 显示为“尚未启动”，不能伪装成运行中。

### S2：实现 Graph Draft restore-by-key

相关文件：

- `src/style_rotation/v022/draft_service.py`；
- `src/style_rotation/api/app.py`；
- `src/style_rotation/api/schemas.py`；
- `frontend/src/api/client.ts`；
- `frontend/src/workspace/GraphDraftContext.tsx`；
- 对应 unit/integration/frontend tests。

后端：

1. 新增按可信 actor + exact `draft_key` 查找当前 Draft 的只读入口，例如：

   ```text
   GET /api/v2/workspace/graph-drafts/by-key/{draft_key}
   ```

2. 该入口是只读恢复，不得经过 mutation admission；维护只读状态下仍应能找回 Draft；
3. 路由必须放在 `/{graph_draft_id}` 动态 UUID 路由之前，或改用无歧义的 query endpoint，避免 `by-key` 被解析为 UUID 后返回 422；
4. 返回 200（唯一 Draft）、404（不存在）或 409（身份不唯一/不一致）；禁止 `latest`、`LIMIT 1` 或 created_at 猜测；
5. GET、event、compile、reset、rebase 全部统一验证 owner；
6. `POST create` 的幂等身份只能比较不可变的创建身份，不能拿 current revision 已变化的 frequency/Asset Context/Data Binding 判断；
7. 并发首次打开时，两次请求必须收敛到同一个 actor/key Draft；
8. 不修改已存在 revision 内容，不回填 revision 16。

前端恢复算法：

1. localStorage 有 ID：先按 ID GET；
2. ID 无效或没有缓存：按 `browser_default_v1` 查询服务器；
3. 找到：恢复 current revision，并回写 localStorage；
4. 只有服务器明确返回 404 才 POST create；
5. create 冲突后重新 by-key GET 一次，处理并发首次创建；
6. 网络、owner、release admission 等错误不得自动创建替代 Draft。

完成条件：清空 localStorage、换浏览器 Origin 或打开无痕窗口后，仍恢复同一个 Draft/revision，而不是创建默认 4 ETF 替代品。

建议提交：

```text
fix(v0.22): restore graph drafts from server identity
```

## 8. 明确不在本轮扩展的事项

- 新因子、更多参数 Variant、LightGBM、RV20；
- Universal Raw passthrough 或改变已经冻结的人工 Catalog 路径；
- Defense 能力模型的新设计；
- 结果归因/IC/消融指标扩展；
- v0.21 数据和运行兼容的清理；
- 大规模性能、并发、故障注入或边际测试；
- 删除旧 Suite、旧 Draft、历史 Artifact 或用户资料。

发现上述问题时记录为后续任务，不在稳定化提交中顺手修改。

## 9. 停止条件与升级规则

遇到以下任一情况必须停止并向用户报告：

1. 修复需要删除或覆盖 revision 16；
2. 需要修改 v0.21 语义、架构或历史数据；
3. 冻结 v0.22 规范与本修复发生语义冲突；
4. 独立测试数据库无法建立，只能使用共享数据库；
5. 发现 Catalog/Registry/Artifact 身份漂移；
6. 需要将 `hidden/explicit_eligible/default` 发布状态改为更高等级；
7. 单一 8000 仍无法证明源码、前端构建与数据库 revision 一致。

## 10. 最终交付格式

Medium 完成后应提交一份简短记录：

1. 每个提交 hash 与文件范围；
2. 修复前后的准确行为；
3. 使用的独立测试数据库名及已删除确认；
4. 聚焦测试、typecheck、build、真实浏览器 smoke 结果；
5. 最终唯一 URL；
6. source commit、frontend build commit、database revision；
7. 尚未处理但不阻塞前端检查的问题；
8. 明确声明没有删除/重建 Draft、没有改动用户文件、没有未经确认修改 v0.21。

只有 S1–S6 全部通过后，才能向用户声明“前端可检查”。
