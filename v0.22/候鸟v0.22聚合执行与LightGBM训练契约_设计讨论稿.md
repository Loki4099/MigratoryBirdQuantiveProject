# 候鸟 v0.22 聚合执行与 LightGBM 训练契约（设计讨论稿）

> 文档等级：`historical/non-normative`  
> `superseded_by`：[`候鸟v0.22最终开发计划.md`](候鸟v0.22最终开发计划.md) 第 5、8、10、14 节；LightGBM 现属 v0.22.1，Target、Purge、Model State 与 Evidence 契约已修订。

> 日期：2026-08-10  
> 状态：核心决定已于 2026-08-10 确认  
> 依赖：三层加工网络、Stage 3 显式聚合输入、严格 Family 身份、共享 Payload Contract、Catalog Release 与不可变 Compiled Graph 已确认。

## 1. 本轮要解决什么

本轮把“聚合层不等于模型，但可以由模型实现”落实为统一运行契约，并回答四个问题：

1. v0.21 的确定性 Model 如何迁移为 v0.22 Aggregation Family；
2. 训练型与非训练型聚合器如何共享同一个 Final Signal 输出边界；
3. 首个 LightGBM 数值聚合器如何构造 Target、训练、验证和严格样本外输出；
4. Target、超参数、策略和防御如何形成实验分支，而不制造无意义组合。

本轮不研究 LightGBM 是否能产生超额收益，也不通过回测挑选最优参数；这里只设计一个可研究、可复现、无前视偏差的基础设施。

## 2. 统一聚合语义

### 2.1 聚合实例的唯一直接输入

一个 Workspace 编译后的所有 Aggregation Instance 均接收完全相同的 Stage 3 显式输入集合：

```text
aggregation_input_set
  = exact ordered set of explicit Stage 3 Feature Occurrences
```

- Stage 0—2 的选择只形成加工闭包，不自动成为聚合输入；
- 一个聚合器若不能接受完整集合，则该 Workspace 组合不可编译；
- 聚合器不得静默删除、替换或新增列；
- 所有输入的 occurrence、output port、Payload Manifest 和列顺序进入实例指纹；
- 树模型在已选列中学习分裂和交互，不等于系统自动生成新的 Catalog Feature 或线路。

### 2.2 两种执行模式

```text
deterministic
  Stage 3 Payloads + frozen preset
    → Aggregation Run
    → Final Signal Payload

walk_forward_supervised
  Stage 3 Payloads + Target + Training Policy + preset
    → Training Matrix / Fold Plan
    → Fitted Model State per retrain fold
    → strictly OOS prediction
    → stitched Final Signal Payload
```

两种模式必须输出相同的 Final Signal 逻辑契约；区别只存在于内部运行和血缘。

### 2.3 Final Signal Contract

首版 Final Signal 是有方向和横截面排序意义的数值标量：

```text
primary_key       = (decision_date, asset_id)
value             = finite float64
higher_is_better  = true
direction         = sign(value), neutral when value == 0
available_at      = 生成本次决策所需全部输入均已可得之后
```

建议不再把 `abs(value)` 命名为 `confidence`。在 weighted mean 和树模型中，绝对值通常不是校准概率或可信度。若为兼容 v0.21 必须保留该字段，应改名为 `score_magnitude`，并将 `confidence` 标记为 deprecated compatibility projection。

Final Signal 不强制落在 `[-1, 1]`。横截面策略应对 Final Signal 执行稳定的 average-tie 排序；若某聚合器承诺归一化范围，则由该 family 的输出契约单独声明，不能由运行时静默裁剪。

### 2.4 Aggregation Family 能力字段

```text
execution_mode
input_policy_version
accepted_payload_kinds
input_cardinality
requires_target
allowed_target_families
training_policy_family
missing_policy_version
feature_assembly_policy_version
final_signal_contract_version
determinism_contract
```

Target 不是所有 Aggregator 的必选字段。`requires_target=false` 的确定性聚合器不得伪造 `target=none` 来参与 Target 笛卡尔积。

## 3. v0.21 确定性聚合器的 Family 重划分

依据“同一公式/算法和语义，仅参数不同才属于同一 Family”，v0.21 Workspace 的四种可用聚合方式应映射为四个 Family，而不是继续把两个 weighted preset 放在同一个宽泛 family 下。

### 3.1 `single_signal_identity`

- 输入：恰好一个满足 directional rank 语义的标量信号；
- 公式：`final = input`；
- Target：无；
- 缺失：保留缺失，不能填零；
- 用途：单信号基线与 v0.21 parity。

### 3.2 `flat_equal_weight_mean`

- 输入：一个或多个同频率、同资产域、方向一致的数值信号；
- 公式：`final = mean(x_1, ..., x_n)`；
- 每个信号等权；
- Target：无。

### 3.3 `dimension_equal_hierarchical_mean`

- 输入：一个或多个具有已发布 economic dimension 映射的方向型信号；
- 公式：先在 dimension 内等权，再对非空 dimension 等权；
- Target：无；
- dimension 映射来自冻结 Catalog Taxonomy Artifact，不能由名称、Feature Family 或本次输入临时推断。

它与 `flat_equal_weight_mean` 不是参数差异。当各 dimension 的信号数量不同，两者公式和结果均不同，因此必须拆分 Family。

### 3.4 `directional_majority_vote`

- 输入：一个或多个方向/事件型信号；
- 显式执行已发布的 sign/state 映射；
- 正负票数相同输出 neutral；
- Target：无；
- 任何从连续值到投票状态的阈值都属于该 family 的明确 Variant/版本，不能隐式采用 `> 0`。

### 3.5 v0.21 parity 处理

旧 Model Artifact 和旧 family key 保持只读不变。迁移表明确记录：

```text
v0.21 model family / preset
  → v0.22 aggregation family / version / preset
  → parity evidence artifact
```

若 v0.21 的 `linear_weighted` 同时容纳 flat equal 与 dimension equal，v0.22 不继承这一过宽 family，只通过 compatibility alias 和迁移证据保持历史可读性。

## 4. Feature Assembly

训练型开放数值聚合器在进入引擎前必须经过显式、可追溯的 Feature Assembly：

```text
rows    = canonical (decision_date, asset_id)
columns = canonical selected occurrence + output field/dimension
values  = exact PIT values from referenced Payload Manifests
```

规则：

1. 列顺序按编译后的 `aggregation_input_ordinal`，向量维度按 Output Contract 顺序展开；
2. 列名使用稳定 occurrence/port/dimension identity，不依赖可变展示名；
3. 不自动标准化、去极值、行业中性化、填充或频率转换；这些若需要，必须在前三层成为显式 Processing Node；
4. 树模型首版只接受普通有限数值标量；向量可在未来由明确的 flatten adapter 和新 input policy 开放；
5. Feature Matrix Manifest 保存 schema、row key、列映射、输入 payload、缺失统计、PIT 截止和 logical fingerprint。

## 5. 首版 LightGBM Family 建议

### 5.1 建议首发：连续横截面排名回归

```text
family_key             = lightgbm_cross_section_rank_regression
engine                 = LightGBM GBDT regression
objective              = regression_l2（首版冻结）
target_family          = future_cross_section_rank
input                  = open numeric scalar set
output                 = continuous higher-is-better Final Signal
execution_mode         = walk_forward_supervised
```

这里模型预测的是连续横截面排名标签，不是原始未来收益金额，也不是 LambdaRank relevance label。选择它作为首版的原因是：

- 不需要人为决定 relevance 分箱和 `label_gain`；
- 不同资产数量的截面可以使用同一连续 Target Contract；
- 模型输出天然可作为横截面策略排序分数；
- 训练、PIT、walk-forward 和模型状态基础设施可先稳定下来。

### 5.2 LambdaRank 是后续独立 Family

```text
family_key    = lightgbm_cross_section_lambdarank
objective     = lambdarank
group/query   = one decision_date cross-section
label         = published integer relevance encoding
metric        = NDCG@k
status        = planned
```

官方契约要求 ranking label 为整数相关度，且每个训练/验证集合提供 group；`label_gain`、NDCG cutoff 和 truncation level 会改变目标的实际含义。它不能作为 regression family 的普通 Preset。

### 5.3 Family、Target、Preset、Fitted State 的边界

```text
Aggregation Family
  = algorithm + objective + input/output semantics

Target Variant
  = future_cross_section_rank + horizon(H5/H21/H63)

Hyperparameter Preset
  = frozen tree complexity / learning rate / regularization / early stopping

Aggregation Instance
  = family version + exact Stage 3 input set
    + one target variant + one preset + asset/frequency context

Fitted Model State
  = one instance + one training cutoff/fold + exact training data/environment
```

H5/H21/H63 与普通树超参数不拆 Family；Objective 从 regression 改为 LambdaRank、Huber、分类等则拆 Family。

## 6. `future_cross_section_rank` Target Contract

### 6.1 时间锚点

Target 必须和可交易执行时间一致。代码核对显示，v0.21 当前使用的是：

```text
decision_date = 策略产生信号的公共决策日 t
entry_time    = t 之后的下一个公共可执行开盘价
exit_time     = 下一次计划调仓决策之后的公共可执行开盘价
forward_return = exit_open / entry_open - 1
overlap_policy = non_overlapping_schedule_intervals
```

这不是严格的 H5/H21：周频区间通常接近 5 个 session、月频区间通常接近 21 个 session，但会随日历变化。若 v0.22 继续使用 H5/H21/H63 命名，则应另行定义固定 session horizon：

```text
exit_time = 从 entry_time 起向后恰好 H 个公共交易 session 的开盘价
```

固定 horizon 在预测窗口大于调仓间隔时会产生重叠标签，必须由 purge 处理。两种窗口都可以属于同一 `future_cross_section_rank` Target Family 下的不同 Variant，但 Variant 必须冻结 `horizon_rule`，不能把“下一调仓开盘”和“固定 H sessions”视为同义。首版建议优先复用 v0.21 的 execution/schedule policy 建立可验证 baseline；若同时发布 H5/H21/H63，则作为新增 Target Variant 单独验收。

### 6.2 横截面变换

在每个 decision date、当前 PIT 可投资资产集合内：

1. 计算合法 forward return；
2. ties 使用 average rank；
3. 映射为连续 percentile rank；
4. 再中心化到 `[-1, 1]`，最高预期收益接近 `+1`，最低接近 `-1`。

冻结公式建议：

```text
n == 1: target = 0
n > 1 : target = 2 * (average_rank - 1) / (n - 1) - 1
```

Target Payload 同时保留 `forward_return`、`rank`、`rank_target` 和 `target_available_at`，但训练只读取契约声明的 `rank_target` 字段。

### 6.3 PIT 与标签成熟

预测决策日 `T` 的模型只能训练于满足以下条件的样本：

```text
feature.available_at <= historical decision cutoff
target.exit_time < T decision cutoff
target data known_at <= T decision cutoff
```

不是仅检查 `decision_date < T`。尚未走完 H 个 session 的历史标签属于未成熟标签，必须排除。

### 6.4 资产集合与生存偏差

- 每个历史截面使用该历史时点的 PIT eligible universe；
- 不能用当前成分股名单回填历史；
- 退市、停牌和缺少合法 exit price 必须由已发布 target outcome policy 处理；
- 首版若 Data Bundle 尚不具备 PIT universe/delisting 证据，LightGBM 保持 `planned`，不能用静态幸存者样本升级为正式 Product。

## 7. Walk-forward 与严格样本外输出

### 7.1 基本规则

- 只允许按时间扩张或滚动训练，不允许随机 train/test split；
- 每个正式 Final Signal 行必须引用当时已经冻结的 Fitted Model State；
- 训练区间内的 fitted prediction 不能混入策略回测；
- 重训之间的决策日使用最近一个合法 Model State 推断；
- 任何 fold 失败都不能静默回退到全样本模型、上一目标模型或等权聚合。

### 7.2 建议的首版训练策略

具体数值先作为 Catalog Preset，而不是硬编码系统常量：

```text
window_mode                = expanding
minimum_train_groups       = preset value
validation_groups          = trailing contiguous block
retrain_schedule           = calendar-based, preset value
label_purge_sessions       = target horizon H
embargo_sessions           = preset value
maximum_boosting_rounds    = preset value
early_stopping_rounds      = preset value
```

一个 fold 的顺序固定为：

```text
historical eligible samples
  → remove labels not matured by fold cutoff
  → time-ordered train/validation split
  → purge overlapping labels at boundary
  → fit with early stopping on validation
  → freeze best iteration and Model State
  → predict only subsequent decision dates
```

初版建议仅发布一个 `conservative_v1` Preset，先验证机制；`balanced_v1`、`deeper_tree_v1` 可存在于 Catalog 草案但保持 planned。这样支持未来多 Preset 分支，又不在本轮无研究依据地制造参数搜索空间。

### 7.3 Early stopping

Early stopping 必须有独立的时间连续 validation block，并保存 `best_iteration`。首版 regression family 建议以 validation L2 作为停止指标，同时记录每日 Spearman rank IC、top-bottom spread 等研究诊断；暂不让自定义绩效指标参与训练停止，避免策略回测逻辑反向渗入模型拟合。

## 8. Missing、异常与覆盖率

LightGBM 技术上可以处理 NaN，但候鸟不能因此默认允许所有缺失。建议首版采用：

```text
missing_policy = complete_case_asset_date_v1
```

- 某 `(date, asset)` 任一已选输入缺失，则该行不进入训练或推断；
- 不执行均值/零值/前值填充；
- 每个截面必须满足 `minimum_assets_per_group` 与 `minimum_coverage_ratio`；
- 不达标的截面整体排除并记录 reason code，不能在不同列间拼接不同样本；
- Target 缺失与 Feature 缺失分别统计；
- 推断期资产缺行时，Final Signal 对该资产保持 missing，由策略的 eligible-universe contract 决定能否运行，不得把 missing 当 neutral。

未来可以发布 `lightgbm_native_missing_v1` input/missing policy；它必须形成新的 Aggregation Version 或明确兼容 Variant，并重新完成研究验收。

## 9. 训练产物与血缘

建议新增以下不可变 Artifact/投影：

### 9.1 `aggregation.training_matrix_manifest`

- exact feature schema and order；
- feature/target Payload Manifest refs；
- row/group counts and coverage；
- PIT cutoff；
- missing/drop diagnostics；
- logical matrix fingerprint。

### 9.2 `aggregation.fold_plan`

- train/validation/prediction date ranges；
- label maturity cutoff；
- purge/embargo boundaries；
- retrain identity；
- expected output dates。

### 9.3 `aggregation.model_state`

- family/version/instance/preset/target refs；
- exact training matrix and fold refs；
- engine name and exact version；
- full resolved parameters and all seeds；
- feature names/order；
- best iteration and validation metrics；
- native booster Artifact and independent JSON metadata；
- environment/lock/compiler/platform refs；
- deterministic declaration and model byte hash。

### 9.4 `aggregation.prediction_run`

- Model State ref；
- exact inference Feature Matrix Manifest；
- prediction interval；
- row coverage and rejected rows；
- Final Signal Payload Manifest；
- run implementation/version/log refs。

### 9.5 `aggregation.walk_forward_run`

将多个 retrain fold 的 OOS prediction 原子拼接为一个 Final Signal Payload；重叠日期必须按已发布 ownership rule 唯一归属，缺口不得由相邻 fold 静默填补。

完整血缘为：

```text
Raw / Processing Payloads
  → Stage 3 Feature Occurrences
  → Feature Matrix Manifest
  + Target Payload
  + Fold Plan
  → Model State
  → Prediction Run
  → Final Signal Payload
  → Strategy / Defense / Experiment / Product
```

## 10. 可复现性约束

首版建议只支持 CPU formal run：

- 精确锁定 LightGBM 与 Python 依赖版本；
- 固定所有显式 seed；
- `deterministic=true`；
- 显式二选一固定 `force_col_wise=true` 或 `force_row_wise=true`；
- 保存 `num_threads`、平台、编译器和依赖锁；
- GPU/不同编译环境只作为 exploratory，不与 formal Artifact 宣称 byte-identical；
- 同一环境重跑必须通过 prediction tolerance/hash 验收。

即使设置 deterministic，不同 LightGBM 版本、编译器或系统仍可能产生不同结果，因此环境身份是 Model State 血缘的一部分，而不是日志附注。

## 11. 诊断、门禁与失败策略

### 11.1 每个 fold 至少记录

- train/validation/prediction 日期与 group 数；
- 每组资产数、覆盖率、drop reason；
- Target 分布、ties、常数截面；
- best iteration 和完整 metric history；
- validation L2、每日 rank IC 分布、top-bottom spread；
- prediction 的均值、标准差、分位数、常数率；
- feature importance（gain/split）及跨 fold 稳定性；
- 训练耗时、资源、软件环境和 seed。

Feature importance 只用于解释和诊断，不代表经济因果，也不能自动删除/新增输入。

### 11.2 Hard failure 示例

- 输入列集合或顺序与实例不一致；
- PIT/available-at 违规；
- 训练或验证 group 不足；
- purge 后没有合法样本；
- 全部 Feature 或 Target 为常数；
- 非有限值违反 input policy；
- Model State 与推断 schema/hash 不匹配；
- fold 输出日期重叠或缺口违反 Fold Plan；
- 依赖/引擎版本不符合 formal policy。

### 11.3 Warning 示例

- 某些截面因覆盖不足被排除但仍高于发布门槛；
- feature importance 极度集中；
- prediction dispersion 过低；
- validation 与 OOS 的 rank IC/coverage 明显漂移；
- early stopping 过早。

Warning 是否阻止 Product 发布由版本化 Acceptance Policy 决定，不能由操作人员临时忽略。

## 12. 分支展开规则修正

不同 Aggregation Family 只展开自己适用的轴：

```text
deterministic aggregator branch
  = Aggregation Version × applicable Preset
    × Strategy × Defense

trainable aggregator branch
  = Aggregation Version × Target Variant × Hyperparameter Preset
    × Strategy × Defense
```

因此若同一 Workspace 选择：

- 2 个 deterministic aggregator；
- 1 个 LightGBM aggregator；
- LightGBM 的 3 个 Target Variant 和 1 个 Preset；
- 2 个 Strategy；
- 2 个 Defense（含 `none`）；

分支数是：

```text
2 × 2 × 2 + 1 × 3 × 1 × 2 × 2 = 20
```

不是把 Target 强行乘到 deterministic aggregator 上得到 36。编译预览必须按 family 分项展示计算过程。

一个实验分支仍然只含一个 Aggregation Instance、一个 Strategy 和一个 Defense；一个训练型分支还冻结一个 Target、Preset、Walk-forward Run 及其逐 fold Model State。

## 13. Experiment 与 Product 展示

摘要区直接展示：

- Aggregation Family / Version；
- 若为训练型：Target Variant、Preset、walk-forward policy、fold/model state 数；
- 直接进入聚合的全部 Stage 3 Feature Occurrences；
- Final Signal Contract 与覆盖率；
- Strategy；
- Defense；
- OOS 区间和 Acceptance 状态。

更上游三层加工细节仍从血缘入口展开，不挤占实验摘要。Product 只能引用已冻结且通过门禁的 walk-forward Final Signal，不允许在页面读取时训练。

## 14. 本轮建议冻结的决定

1. 聚合层统一支持 `deterministic` 与 `walk_forward_supervised` 两种执行模式，并输出同一 Final Signal Contract。
2. v0.21 的 identity、flat equal、dimension equal、directional vote 在 v0.22 成为四个独立 Aggregation Family。
3. Target 只对 `requires_target=true` 的聚合器展开；确定性聚合器不参与 Target 笛卡尔积。
4. 首版训练型聚合器为 `lightgbm_cross_section_rank_regression`；LambdaRank 独立建为 planned family。
5. H5/H21/H63 属于同一 Target Family 的 Variant；普通树超参数属于同 Aggregation Family 下 Preset。
6. Target 使用与策略执行一致的 next-open 到 future-open 收益，在历史 PIT eligible universe 内转换为连续中心化横截面排名；`next scheduled execution` 与固定 `H sessions` 是不同 Target Variant。
7. 训练采用时间有序 walk-forward、标签成熟检查、purge/embargo 和严格 OOS 拼接；禁止随机切分。
8. 首版缺失策略为 complete case，不隐式填充；LightGBM 原生缺失另行发布。
9. 首版只发布一个保守 Preset；其他 Preset 先 planned，待专项研究。
10. 正式训练限定 CPU、锁定版本/环境、固定 seed 与 deterministic/column-wise policy。

## 15. 本轮确认结果

### Q1：首版 Objective（已确认）

已确认先做“LightGBM 回归连续的未来横截面排名”，不在首版实现 LambdaRank。LambdaRank 未来作为独立 family，不影响现有结构。

### Q2：四个确定性 Family（已确认）

已确认 signal equal 与 dimension equal 因公式不同而拆成两个 family，加上 identity、directional vote 共四个；这与严格 family 原则一致。

### Q3：首版 Target 窗口规则（已确认）

已确认首版先复用 v0.21 的“下一次计划调仓执行开盘”形成 weekly/monthly 非重叠 Target；后续可发布严格 H5/H21/H63 固定 session Target，两者不再混用。

### Q4：首版 Preset 数量（已确认）

已确认 v0.22 可用状态只开放一个 `conservative_v1`，其他超参数预设先保持 planned。这不会限制未来同时选择多个 Preset 回测，并避免在防泄漏与训练框架尚未跑通前把参数搜索混入本轮。
