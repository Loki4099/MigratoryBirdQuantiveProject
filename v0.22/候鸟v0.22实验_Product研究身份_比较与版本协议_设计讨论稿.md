# 候鸟 v0.22 Experiment / Product 研究身份、比较与版本协议（设计讨论稿）

> 文档等级：`historical/non-normative`  
> `superseded_by`：[`候鸟v0.22最终开发计划.md`](候鸟v0.22最终开发计划.md) 第 8.4、10、11.2、14 节；Product 已拆分 Execution/Qualification/Monitoring Version，并补充连续运行协议。

> 日期：2026-08-10  
> 状态：核心决定已于 2026-08-10 确认  
> 目标：让 Experiment 和 Product 直接、完整、不可漂移地展示最终 Aggregator、直接输入信号、Target/Preset、Strategy 与 Defense，并保证结果比较和 Product 升级具有严格语义。

## 1. 用户首先应该看到什么

Experiment Result 和 Product 页面最先展示的不是完整加工图，而是最终研究决策：

```text
Final Aggregator
  + 直接进入 Aggregation 的 Stage 3 Signals
  + Training Target / Hyperparameter Preset（若适用）
  + Cross-Section Strategy
  + Defense Package
```

Raw Input 和三个加工层仍全部可追溯，但默认只通过“查看上游血缘”展开。这落实此前已确认的要求：详细显示最终使用的模型/聚合器、策略及进入聚合的信号，更上游加工层不占据结果页主视图。

## 2. v0.21 现状与缺口

现有系统已经具备：

- Suite / Cell / Attempt / immutable Result；
- 指标、NAV、质量检查、运行事件和 Artifact 链接；
- Comparison Cohort 和 controlled / side-by-side 分类；
- Product qualification、promotion、生命周期、冻结回测和 OOS 监控；
- Decision Explorer。

但当前页面和 API 主要依赖：

```text
model_specification_key
variant_key
strategy_preset_key
```

在 v0.22 中这些压缩 key 不再足够，因为：

- 同一 Aggregation Family 可绑定不同的完整输入集合；
- 同一训练型 Aggregator 可使用不同 Target Variant 与 Preset；
- 一个 walk-forward Result 可引用多个 fold Model State；
- 同一 Strategy 可配不同 Defense Package；
- 同名 Family 在新 Catalog Release 中可能已有新 Version；
- Product 必须永远显示当时冻结版本，不能从 latest Catalog 重建说明。

## 3. Experiment 层级

建议将 v0.22 统一为：

```text
Research Suite
  ├─ Research Branch
  │    ├─ Predictive Evaluation Cell（按 Evaluation Policy 可选/必需）
  │    ├─ Portfolio Cell: window × cost × benchmark/context
  │    └─ ...
  └─ ...

Cell
  ├─ Attempt 1
  ├─ Attempt 2
  └─ one accepted immutable Result at most
```

### 3.1 Research Suite

冻结：

- Workspace Draft revision；
- Catalog Release；
- Compiled Graph；
- 全部明确选择；
- 分支展开规则；
- Experiment Matrix Policy；
- common market/evaluation context。

### 3.2 Research Branch

每条 Branch 恰好包含：

```text
one Aggregation Instance
one Cross-Section Strategy Variant
one Defense Package（含 none）
one schedule / frequency
```

训练 Target 与 Aggregation Instance 绑定；Portfolio 的比较窗口、成本和 benchmark 仍由 Cell 展开。

### 3.3 Cell

Cell 是一次具体的可运行问题：

```text
Branch
+ evaluation window
+ cost scenario
+ benchmark version
+ accounting / execution / metric context
```

Cell Specification 不保存运行结果；Attempt 不改变 Cell 身份；只有通过门禁的 Attempt 能发布 Result。

## 4. 冻结的 Research Configuration Snapshot

### 4.1 为什么需要 Snapshot

Experiment 和 Product 不应在读取页面时跨十几张表并结合最新 Catalog 重新解释配置。编译 Branch 时应发布一个不可变：

```text
experiment.research_configuration_snapshot
```

它既是机器可验证身份，也是 UI 的权威展示来源。

### 4.2 Snapshot 内容

```text
identity
  configuration_snapshot_artifact_id
  configuration_fingerprint
  catalog_release_artifact_id
  compiled_graph_artifact_id
  workspace_revision
  branch_key

aggregation
  family_id / family_key / display_name
  version_id / version_number
  execution_mode
  input_policy_version
  target_variant nullable
  hyperparameter_preset nullable
  training_policy nullable
  final_signal_contract

direct_inputs[]
  aggregation_input_ordinal
  feature_occurrence_id
  feature_family / variant
  stage_3_output_port
  original_stage
  projection_kind
  payload_contract
  display_name / parameters

strategy
  family / version / preset
  K / buffer / sector cap
  schedule / execution
  tie / missing / empty-slot policy

defense
  package / timing / allocation versions
  timing input signal summaries
  budget bounds
  none flag

static_context
  asset context / universe policy
  currency
  calendar
  execution policy
```

Snapshot 保存显示所需的名称和参数副本，同时引用权威 Artifact。展示副本防止名称随新 Catalog 改变；Artifact 引用保证可核验。二者若不一致属于 corruption，不读取 latest 值覆盖。

### 4.3 直接输入与上游输入的边界

`direct_inputs[]` 必须严格等于编译图中 Stage 3 显式聚合输入集合，按 Aggregation Instance 的冻结顺序排列。

它不包含：

- 仅用于生成这些 Signals 的 Raw/Stage 1/2 输入；
- Defense Policy 自己的 SPY/RV20 等输入；
- Benchmark 数据；
- 自动诊断 Feature。

这些通过独立分类和血缘查看，不能混入“进入聚合的信号”。

## 5. Result Evidence Snapshot

Research Configuration Snapshot 描述“计划运行什么”；Result 还需要冻结“实际使用了什么”：

```text
experiment.result_evidence_snapshot
```

至少包含：

- Cell Specification / accepted Attempt；
- exact Data Bundle、Universe、Eligibility、Calendar；
- 实际 Final Signal Payload；
- 训练型 Aggregator 的 Walk-forward Run 与全部 Model State refs；
- 实际 Strategy Target Path；
- Defense Decision Run 与 Sleeve Targets；
- execution、cost、reserve accrual、benchmark；
- resolved interval / warm-up；
- metric catalog 与 metric values；
- quality/acceptance policy 与结果；
- environment/engine versions；
- output Payload Manifests。

Result 必须同时引用 Configuration Snapshot 与 Evidence Snapshot。这样可以区分：

```text
selected intent / compiled identity
vs
resolved runtime evidence
```

## 6. 三种 Target 必须分名

v0.22 页面和 Schema 中不得继续用一个模糊的 `target` 表示三件事。

### 6.1 Aggregation Training Target

仅适用于 `requires_target=true` 的训练型 Aggregator，例如：

```text
future_cross_section_rank / weekly next-scheduled-open
```

它决定模型训练身份。

### 6.2 Predictive Evaluation Target

用于评价 Final Signal 的 Rank IC、分层收益等。确定性 Aggregator 虽然没有 Training Target，仍可在 Experiment Evaluation Policy 下使用一个冻结 Evaluation Target。

它不进入 Aggregation Instance 指纹，也不为 deterministic aggregator 制造新的生产分支；它属于评价 Cell 身份。

对于训练型 Aggregator，Evaluation Target 通常与 Training Target 的经济语义一致，但必须引用真正 OOS 的 Target Payload，不能拿训练标签内样本评价冒充预测证据。

### 6.3 Portfolio Benchmark

SPY 或其他财富路径基准只用于组合表现比较，不是模型 Target。页面必须分别显示：

```text
训练目标
预测评价目标
组合基准
```

## 7. Experiment Overview 信息架构

### 7.1 列表行

列表只显示足以区分分支的摘要：

```text
Aggregator
  family display name
  direct input count
  target/preset short label（若有）

Strategy
  family + K + frequency
  Defense Package

Cell assumptions
  window + cost + benchmark

Core metrics
Status / quality
```

鼠标悬停或展开显示前几个直接信号；输入很多时显示：

```text
6 个直接信号：Value · Momentum · Quality · +3
```

不能继续让 `model_specification_key` 独占标题。

### 7.2 筛选

建议增加：

- Aggregation Family；
- direct signal Family/Variant；
- Training Target；
- Hyperparameter Preset；
- Strategy Family/K/frequency；
- Defense Package；
- formal/exploratory；
- status/quality；
- window/cost/benchmark。

筛选只改变列表，不改变 Comparison Cohort 或结果身份。

## 8. Experiment Result 详情顺序

### 第一屏：研究身份摘要

固定显示：

1. Aggregator Family / Version；
2. 直接输入 Signals（完整、有序）；
3. 若为训练型：Training Target、Preset、Training Policy；
4. Strategy Family / Version / K / frequency；
5. Defense Package / Timing / Allocation；
6. formal/exploratory、Result 状态和区间。

第一屏必须能回答“这个结果到底是什么”，之后才展示收益指标。

### 第二屏：结果与公平基线

- NAV / benchmark / excess / drawdown；
- predictive diagnostics；
- portfolio metrics；
- matched `none` Defense baseline（若当前分支有 Defense）；
- matched deterministic Aggregator baseline（训练型 Aggregator 建议提供）；
- comparison classification。

若 matched baseline 不存在，显示 `matched_baseline_missing`，不能在页面临时选一条相近结果替代。

### 第三屏：运行证据

- 输入/输出覆盖率；
- quality checks；
- Attempt events；
- resolved Artifact 清单；
- cost/capacity；
- promotion eligibility。

### 可展开：血缘与决策解释

- 上游三层加工图；
- 一个决策日的 Feature → Aggregation → Strategy → Defense → Final Target；
- trainable Aggregator 的 fold/Model State；
- 导出 Configuration/Evidence Manifest。

## 9. Trainable Aggregator 的页面表达

LightGBM 不能只显示一个“模型文件”。Result 摘要显示：

```text
family / objective
target / preset
walk-forward policy
fold count
OOS coverage
latest model state cutoff
```

折叠的 Model State 表显示：

```text
fold / retrain date
train / validation / prediction interval
best iteration
validation metric
OOS prediction coverage
model state artifact
environment identity
```

默认不把几十个 Fold 全部铺开；支持筛选、下载 manifest 和打开具体 Artifact。Feature importance 明确标注为诊断，不解释为经济因果。

## 10. Comparison Identity

### 10.1 Comparison Scope

每次比较必须先声明范围：

```text
predictive
  比较 Final Signal 对冻结 Evaluation Target 的预测表现

portfolio
  比较最终组合在相同市场、执行、成本和 benchmark 下的表现

replication_audit
  比较同一配置的可复现性
```

不同 scope 使用不同 Protected Context。尤其：

- predictive comparison 必须使用相同 Evaluation Target 和 outcome policy；
- portfolio comparison 可把 Aggregation Training Target 当作 treatment dimension，但仍要求相同 Strategy、执行区间、成本与 benchmark 才能隔离该变化；
- H5 与 H21 模型若各自用不同 Evaluation Target 计算 Rank IC，其 Rank IC 不能直接 controlled comparison；
- H5 与 H21 模型若在相同组合执行上下文下产生 Portfolio Result，则可在 portfolio scope 中将 Training Target 作为唯一变化轴。

API、Cohort 和 UI 必须显示 `comparison_scope`，不能根据页面位置暗自推断。

### 10.2 Protected Context

受保护上下文字段必须完全相同，结果才有资格进入 controlled comparison：

```text
asset context / PIT universe
Data Bundle / Eligibility Snapshot
calendar / frequency schedule
decision cutoff / execution policy
evaluation target and target outcome policy（predictive scope）
resolved interval / warm-up / initialization
benchmark
cost / impact / initial capital
reserve accrual
accounting / metric / engine versions
currency
formal vs exploratory evidence class
```

若 Data Bundle 的 byte Artifact 不同但属于明确的同一冻结 comparison data view，必须由发布的 Common Evaluation Dataset Artifact 统一，而不是比较器自行判断“数据差不多”。

### 10.3 Treatment Dimensions

建议细分为：

```text
aggregation_algorithm
aggregation_direct_inputs
aggregation_training_target
aggregation_hyperparameters
strategy_selection
defense_package
```

window、cost、benchmark 和执行规则属于受保护上下文，不应被误称为策略效果维度。

### 10.4 比较分类

```text
replication
  configuration_fingerprint 与 protected context 完全相同；比较运行复现性

controlled
  protected context 相同，且恰好一个 treatment dimension 改变

multi_axis
  protected context 相同，但两个及以上 treatment dimensions 改变

incompatible
  protected context 不同，只能并排查看，禁止排名或归因
```

取代当前含义模糊的 `identical / side_by_side`。同一指纹若因相同内容去重，通常不会出现多个正式 Result；若出现，则按 replication audit 处理，不能当作不同策略候选重复排名。

### 10.5 Controlled 示例

合法：

- 相同 Aggregator/Strategy，仅 Defense 从 none 改为 RV20；
- 相同输入/Strategy/Defense，仅 Aggregator 从 equal weight 改为 LightGBM；
- 相同 Family/Target/Preset/Strategy/Defense，仅删去一个 direct signal 做人工 Feature ablation；
- portfolio scope 下相同全部组合上下文，仅 Aggregation Training Horizon Variant 改变。

非 controlled：

- 同时更换 Aggregator 和 Defense；
- 一个结果周频、另一个月频；
- 成本、区间或 Data Bundle 不同；
- 一个 formal、另一个 survivorship-biased exploratory。

### 10.6 排名 Cohort

Product Ranking 只能读取发布的 Comparison Cohort。Cohort 冻结：

- Protected Context Fingerprint；
- member Result Artifact IDs；
- metric definition and direction；
- eligibility rule；
- duplicate/replication exclusion；
- common observation interval and count。

同一 Protected Context 下的 multi-axis 候选可以进入 portfolio candidate ranking，但必须明确标注为“候选并列排序，不代表单变量归因”；incompatible Result 不得进入同一排名。新 Result 不自动进入旧 Cohort；需要发布 Cohort 新版本，防止排行榜历史漂移。

## 11. Matched Baseline Protocol

### 11.1 Defense baseline

每个非-none Defense 分支应寻找相同：

```text
Aggregation + Inputs + Target/Preset
Strategy + schedule
Protected Context
```

且仅 `Defense Package=none` 不同的结果。若存在，则记录 `matched_none_result_artifact_id`。

### 11.2 Trainable Aggregator baseline

LightGBM Result 建议至少匹配：

- 同 exact direct input set；
- 同 Strategy/Defense/Context；
- 一个已发布 deterministic baseline Aggregator。

但不同 Aggregator 对输入契约可能不同，不能自动假设 equal weight 可接受普通无方向 numeric Feature。只有编译器确认合法且 Suite 明确生成时才建立 baseline。

### 11.3 Baseline 缺失

缺失 baseline 不一定使 exploratory Result 失败，但：

- 页面显著提示；
- Product promotion gate 可要求 formal candidate 必须具备；
- 不允许查询层运行时“找最近似”的结果。

## 12. Product Version 冻结内容

Product Version 必须直接引用：

```text
selected Experiment Result
Research Configuration Snapshot
Result Evidence Snapshot
Qualification Bundle
source Suite / Branch / required Cells
Comparison Cohort version
OOS frozen anchor
monitoring policy version
```

Product 不是指向“某 Aggregation Family 的 latest”。Product 页面显示的配置永远来自其冻结 Snapshot。

## 13. Product 页面信息架构

### 13.1 Overview

标题下立即显示：

```text
Aggregator
Direct Signals
Training Target / Preset（若有）
Strategy
Defense
Lifecycle / Health / OOS status
```

随后展示资格摘要、选择理由、核心冻结回测和 OOS 摘要。

### 13.2 Configuration

默认仅显示最终配置：

- 完整有序 direct Stage 3 signals；
- Aggregator/Target/Preset/Training Policy；
- Strategy；
- Defense Package；
- execution/evaluation context。

不再默认绘制 `Asset → Factor → Signal → Model → Strategy` 的全部上游链。提供“查看完整上游加工血缘”入口，打开局部 Lineage Inspector。

### 13.3 Qualification

- 冻结的 matched cells；
- predictive evaluation；
- matched baselines；
- gate results and warnings；
- selection reason；
- Comparison Cohort。

### 13.4 OOS

- frozen bridge 与 prospective OOS 永久分段；
- 当前使用的 Product Version；
- Final Signal coverage/drift；
- trainable Aggregator Model State freshness；
- Strategy eligibility/turnover；
- Defense regime/budget；
- execution/cost/capacity；
- alerts and reviews。

### 13.5 Latest Decision

逐资产显示：

```text
Final Signal score / rank
risk sleeve contribution
defense sleeve contribution
reserve contribution
merged final target weight
selection / defense reason
recommended execution date
```

若同一资产跨 risk/defense sleeve，显示两项贡献而不是只显示一个 `allocation_role`。

## 14. Product 版本升级与 OOS 时钟

### 14.1 必须新建 Product Version 并重新资格审查

任何会改变决策或收益路径的内容变化：

- direct signal set / Feature Variant；
- Aggregation Family/Version/Target/Preset/Training Policy；
- Strategy Family/Version/K/buffer/sector cap/schedule；
- Defense Package/Timing/Allocation；
- execution、cost、reserve、benchmark/evaluation policy；
- 计算实现或 Contract 的语义变化。

新版本拥有新的：

- Qualification Bundle；
- frozen anchor；
- prospective OOS clock；
- monitoring snapshots。

旧版本历史不可拼接到新版本的 OOS 统计中。

### 14.2 不改变 Product Version 的变化

- 页面文案或翻译；
- 不影响决策的展示排序；
- Alert 展示修复；
- 按冻结 acquisition policy 到来的新日常数据；
- 不改变决策的监控计算 bugfix，前提是新 Monitoring Engine Version 单独追溯。

### 14.3 Product Definition、Version 与 Enrollment

建议：

- Product Definition 表示稳定的研究产品概念；
- Product Version 表示一个冻结可执行配置；
- Enrollment 表示某个 Version 的 OOS 观察生命周期。

替换配置时发布新 Product Version 和新 Enrollment，旧 Enrollment 进入 `superseded` 或 `retired`。UI 可把它们展示为同一产品的版本时间线，但指标不跨版本拼接。

## 15. 上游失效与重新评估

### 15.1 不自动迁移

新 Catalog Release、Node Version、LightGBM 版本或 Defense Policy 发布后，已有 Product 不自动升级。系统只生成：

```text
new_version_available
```

### 15.2 需要暂停/失效的情况

- 引用 Artifact invalidated；
- 数据修正改变历史决策；
- Contract/PIT 审计失败；
- Model State 无法读取或超出 freshness policy；
- Defense/资产篮子不再可执行；
- execution/capacity gate 失效。

系统按影响程度触发 `warning → suspended → retired`，但不得重写旧 Snapshot 或历史 Result。

### 15.3 数据更正

日常追加数据不改变历史。若供应商修订历史：

- 发布新的 Data/Payload Artifact；
- 标记受影响范围；
- 计算 Product impact analysis；
- 如历史决策或资格结果变化，必须新建 Result/Qualification/Product Version；
- 旧证据保留并标记 superseded/invalidated reason。

## 16. API 建议

### 16.1 共享摘要

Experiment list、detail 和 Product detail 复用：

```text
ResearchConfigurationSummary
  aggregation
  direct_inputs[]
  strategy
  defense
  training_target nullable
  evaluation_target nullable
  benchmark
  configuration_fingerprint
```

列表可以返回 compact direct input summary；详情必须返回全部有序输入。

### 16.2 详情资源

```text
GET /experiments/results/{id}/configuration
GET /experiments/results/{id}/evidence
GET /experiments/results/{id}/model-states
GET /experiments/results/{id}/matched-baselines
GET /experiments/results/{id}/decision/{date}

GET /products/{id}/configuration
GET /products/{id}/version-timeline
GET /products/{id}/impact
```

读取接口不得触发训练、物化、比较 Cohort 变更或 Product 升级。

### 16.3 导出

提供：

```text
configuration_manifest.json
result_evidence_manifest.json
comparison_manifest.json
```

均以 Artifact 发布并可 hash 验证。

新增或扩展：


## 18. 迁移与兼容

### v0.21 Result

- 保持当前 API 和只读展示；
- 生成 compatibility Research Configuration Snapshot；
- `model_specification_key` 映射到 v0.22 Aggregation 摘要；
- signal list 映射为 direct aggregation inputs；
- strategy preset 解析出 Strategy + Defense；
- 无法恢复的字段标记 `legacy_unknown`，不猜测。

### v0.21 Product

- 冻结现有 Research Chain 和 Qualification Bundle；
- 生成 compatibility Product Version Snapshot；
- 不重置已有 OOS 时间；
- 只有实际迁移到新配置时才创建新的 v0.22 Product Version/Enrollment。

## 19. 测试门槛

### Identity

- direct input set 与 Compiled Graph Stage 3 explicit set 完全一致；
- Snapshot hash 不受 latest Catalog 变化影响；
- Target/Preset nullable 条件正确；
- Product 与来源 Result 引用相同 configuration fingerprint。

### Comparison

- 每个 treatment dimension 单独变化均分类 controlled；
- 两轴变化分类 multi_axis；
- Protected Context 任一变化分类 incompatible；
- replication 不重复进入排名；
- Cohort 发布后成员不漂移。

### UI/API

- 第一屏完整显示 Aggregator、direct signals、Strategy、Defense；
- 大量输入时摘要与完整详情一致；
- trainable fold 分页；
- legacy_unknown 不伪装为确定信息；
- 页面读取不触发写入或训练。

### Product lifecycle

- 决策语义变化必建新 Version/Enrollment；
- 旧 OOS 不并入新版本；
- Artifact invalidation 触发影响分析；
- 日常新数据不会误建 Product Version。

## 20. 本轮建议冻结的决定

1. 编译每条 Branch 时发布不可变 Research Configuration Snapshot，作为 Experiment/Product 展示真相源。
2. Result 再发布独立 Evidence Snapshot，区分计划身份与实际运行证据。
3. Experiment/Product 第一屏展示 Aggregator、完整 direct Stage 3 inputs、Training Target/Preset、Strategy、Defense；上游加工图按需展开。
4. Training Target、Predictive Evaluation Target 与 Portfolio Benchmark 使用三个独立字段和标签。
5. Comparison 分为 replication / controlled / multi_axis / incompatible；只有相同 Protected Context 且仅一条 Treatment Dimension 变化才叫 controlled。
6. Defense Result 显式匹配 `none` baseline；训练型 Aggregator 在合法时匹配 deterministic baseline。
7. Product Version 直接冻结来源 Result、Configuration/Evidence Snapshot、Qualification、Cohort 与 OOS anchor，不引用 latest Catalog。
8. 任何改变决策路径的配置升级都建立新 Product Version 和新 Enrollment，并重启 OOS 时钟；旧版本证据不拼接。
9. 日常数据追加和纯展示变化不建立新 Product Version。
10. v0.21 Result/Product 通过 compatibility Snapshot 只读迁移，不重写历史身份。

## 21. 本轮确认结果

### Q1：Snapshot 是否作为展示真相源（已确认）

已确认 Experiment 与 Product 不再通过 latest Catalog 动态拼装研究配置，而是在 Branch 编译时冻结 Research Configuration Snapshot，作为长期展示与追溯的真相源。

### Q2：Product 配置变化是否重启 OOS（已确认）

已确认任何会改变实际决策路径的信号、Aggregator、Target/Preset、Strategy 或 Defense 变化，都必须新建 Product Version/Enrollment，并重新开始 OOS 计时；不同策略版本的样本外历史不得拼接。

### Q3：Comparison 分类（已确认）

已确认采用 replication / controlled / multi_axis / incompatible 四状态；频率、数据、区间、成本等 Protected Context 不同的结果不能进入同一排名或进行归因。

### Q4：确定性 Aggregator 的 Evaluation Target（已确认）

已确认 deterministic Aggregator 不拥有 Training Target，但 Experiment 可以通过独立 Predictive Evaluation Target 计算 Rank IC 等诊断；该评价 Target 不产生新的 Aggregation 生产分支。
