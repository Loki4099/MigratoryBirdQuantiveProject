## 1. 共同 v0.21 语义

三个样例共同使用：

```text
missing_policy = error_after_common_warmup
continuous tie_policy = average_rank
continuous normalization = cross_sectional_centered_rank_-1_1
extreme_policy = none
```

连续信号的精确归一化为：

```text
ascending average rank
centered = 2 × (rank - 1) / (asset_count - 1) - 1
score = direction × centered
score quantize = 1e-18, ROUND_HALF_EVEN
```

离散 crossover 信号不进行横截面排名；事件发生时为 1，否则为 0。新资产或暂时缺失资产如果不存在紧邻的前一有效截面观测，则跳过该点，不伪造事件。

## 2. 样例 A：return_continuation

### 2.1 v0.21 身份

Factor Family：`total_return`

```text
formula = close_adj[t] / close_adj[t-window] - 1
implementation = total_return_v1
```

Factor Variants：

```text
total_return__w5
total_return__w20
total_return__w60
total_return__w120
total_return__w252
```

Signal Family：`return_continuation`

```text
form = continuous
direction = higher_is_better
economic_family = momentum
dimension = momentum_trend
product_eligible = true
```

### 2.2 v0.22 三层图

```text
Raw Input Source
└─ canonical_market_bars.close_adj
          ↓
Processing Stage 1
└─ Family: total_return
   ├─ Variant: w5
   ├─ Variant: w20
   ├─ Variant: w60
   ├─ Variant: w120
   └─ Variant: w252
          ↓
Processing Stage 2
└─ 对所选 total_return Variant 做零拷贝 Layer Projection
          ↓
Processing Stage 3
└─ Family: return_continuation
   ├─ Variant bound to total_return__w5
   ├─ Variant bound to total_return__w20
   ├─ Variant bound to total_return__w60
   ├─ Variant bound to total_return__w120
   └─ Variant bound to total_return__w252
   Implementation: continuous_cross_sectional_signal_v1
          ↓
Pre-Aggregation Scalar Signal
```

Stage 3 执行平均排名、`[-1, 1]` 中心化、方向应用和 `1e-18` 量化。Stage 2 没有为了填满层数而制造计算节点。

### 2.3 端口草案

```text
RawInputPort:
  market.close_adj

Stage1 OutputPort:
  total_return.value
  payload = scalar_panel(asset, session_date, float64-compatible)

Stage3 OutputPort:
  return_continuation.score
  payload = scalar_panel(asset, observation_date, decimal_1e-18)
  direction = higher_is_bullish
  cross_sectionally_comparable = true
```

### 2.4 双向选择示例

反向选择 `return_continuation__total_return__w120` 时：

1. Stage 3 的精确 Variant 被选中并置顶；
2. Stage 2 点亮 `total_return__w120` 的透传投影；
3. Stage 1 点亮 `total_return__w120`；
4. Raw Input 点亮 `close_adj`；
5. 聚合器只收到 Stage 3 的 `return_continuation.score`。

## 3. 样例 B：price_cross_above_ma

### 3.1 v0.21 身份

Factor Family：`moving_average_ratio`

```text
formula = SMA(close_adj, short_window) / SMA(close_adj, long_window) - 1
short_window = 1 时使用当前 close
implementation = moving_average_ratio_v1
```

本信号使用：

```text
moving_average_ratio__s1_l50
moving_average_ratio__s1_l200
```

Signal Family：`price_cross_above_ma`

```text
form = crossover_event
previous <= 0
current > 0
event_score = 1
otherwise = neutral / 0
product_eligible = false
```

### 3.2 v0.22 三层图

```text
Raw Input Source
└─ canonical_market_bars.close_adj
          ↓
Processing Stage 1
└─ Family: moving_average_ratio
   ├─ Variant: s1_l50
   └─ Variant: s1_l200
          ↓
Processing Stage 2
└─ Family: price_cross_above_ma
   ├─ Variant bound to s1_l50
   └─ Variant bound to s1_l200
   Rule: previous <= 0 and current > 0
          ↓
Processing Stage 3
└─ 零拷贝 Layer Projection，保留 price_cross_above_ma Family/Variant
          ↓
Pre-Aggregation Event Signal
```

### 3.3 端口草案

```text
Stage1 OutputPort:
  moving_average_ratio.value

Stage2 OutputPorts:
  price_cross_above_ma.score   # 1 or 0
  price_cross_above_ma.state   # positive / neutral
  price_cross_above_ma.event   # boolean
```

三个输出来自同一次事件检测 Node Run。`score` 是聚合直接使用的主端口；`state/event` 是解释和诊断端口。Stage 3 投影引用同一 Node Run 和端口，不复制 Payload。

### 3.4 等价细节

- 事件从第二个可比较日期开始；
- `previous` 指排序后前一个共同有效截面日期；
- 单个资产缺少前一有效观测时只跳过该资产日期；
- 不对 0/1 事件做横截面排名；
- `s1_l50` 与 `s1_l200` 属于同一 Signal Family 的两个参数 Variant。

## 4. 样例 C：low_illiquidity_quality

### 4.1 v0.21 身份

Factor Family：`amihud_illiquidity`

```text
daily_return[t] = close_adj[t] / close_adj[t-1] - 1
dollar_volume[t] = close_raw[t] × volume_raw[t]
daily_impact[t] = abs(daily_return[t]) / dollar_volume[t]
factor[t] = mean(daily_impact, window)
```

Factor Variants：

```text
amihud_illiquidity__w20
amihud_illiquidity__w60
```

Signal Family：`low_illiquidity_quality`

```text
form = continuous
direction = lower_is_better
economic_family = liquidity_quality
dimension = volume_liquidity
product_eligible = true
```

### 4.2 v0.22 三层图

```text
Raw Input Source
├─ close_adj
├─ close_raw
└─ volume_raw
          ↓
Processing Stage 1
└─ Node: amihud_daily_primitives_v1
   ├─ OutputPort: simple_return
   ├─ OutputPort: dollar_volume
   └─ OutputPort: daily_price_impact
          ↓
Processing Stage 2
└─ Family: amihud_illiquidity
   ├─ Variant: w20
   └─ Variant: w60
   OutputPort: rolling_mean_impact
          ↓
Processing Stage 3
└─ Family: low_illiquidity_quality
   ├─ Variant bound to amihud_illiquidity__w20
   └─ Variant bound to amihud_illiquidity__w60
   Implementation: continuous_cross_sectional_signal_v1
          ↓
Pre-Aggregation Scalar Signal
```

### 4.3 精确计算边界

- `dollar_volume == 0` 时 `daily_price_impact` 为缺失；
- w20 首个输出需要 21 个价格观测，w60 需要 61 个；
- 滚动样本中任何 daily impact 缺失时，该窗口不产生值；
- Stage 3 先按原始 illiquidity 升序平均排名并中心化，再乘以 `-1`；
- 因而更低的 illiquidity 得到更高的 Final Score；
- 计算必须保留 v0.21 Decimal 运算和最终 float/Decimal 转换边界，不能因拆层改变数值。

### 4.4 多输出节点用途

该样例验证：

- 三个 Raw Input Port；
- 一次 Node Run 多个 Output Port；
- 下游只消费其中 `daily_price_impact`；
- 其他端口仍可导出、诊断或被未来节点复用；
- 必需端口共同接受原子质量门禁。

## 6. 聚合层纸面编译

假设用户在 Stage 3 选择：

```text
return_continuation__w120
price_cross_above_ma__s1_l200
low_illiquidity_quality__w20
```

聚合器必须验证：

- 是否接受连续信号和事件信号混合；
- 是否要求全部输入都是可横截面比较的连续标量；
- 事件信号是否需要先经过显式 Adapter 转换；
- Frequency、Asset Context、日期覆盖和 Known At 是否一致；
- 三个输入均不得被静默忽略。

如果某个 Aggregation Variant 只接受连续标量，则 `price_cross_above_ma` 使它进入 `aggregation_input_kind_incompatible` 状态；用户需要取消事件信号或选择明确支持事件输入的聚合家族。

## 7. 前端纸面交互

### 7.1 正向选择

用户在 Stage 1 选择 `moving_average_ratio / s1_l200`：

- 该 Family 和 Variant 置顶并标色；
- Stage 2 的 `price_cross_above_ma / s1_l200` 成为已满足、可直接选择；
- 依赖其他 MA Variant 的下游显示为可补齐祖先或不兼容，具体由目录关系决定；
- 选择 Stage 2 事件后，Stage 1 上游被锁定；
- Stage 3 显示其零拷贝透传项，可明确选择进入聚合。

### 7.2 反向选择

用户直接选择 Stage 3 的 `low_illiquidity_quality / w60`：

- Stage 3 Family/Variant 置顶；
- Stage 2 自动选择 `amihud_illiquidity / w60`；
- Stage 1 自动选择 `amihud_daily_primitives / canonical_v1`；
- Raw Input 点亮 close_adj、close_raw、volume_raw；
- 自动祖先显示不同颜色并锁定；
- 取消 Stage 3 选择后，未被其他信号使用的自动祖先自动清理。

## 8. Parity 验收

三个样例分别建立：

1. v0.21 原 Factor Dataset 与中间节点输出比较；
2. v0.21 Signal Dataset 与 Stage 3 Pre-Aggregation Signal 比较；
3. 主键集合、Coverage、Missing Mask、State/Event、数值和 Rank 比较；

## 9. 本次纸面编译暴露的待确认问题

### Q1：Family 应绑定 Node，还是绑定可选择的 Output Variant

一次 Node Run 可以产生多个语义不同的 Output Port，例如 `body`、`range`、`state`、`event`。用户实际选择和参数归纳的对象是输出元素，而不一定是计算节点本身。

推荐调整为：

```text
Processing Node Version：计算和执行身份
Feature/Signal Family：前端与研究分类身份
Feature/Signal Variant：精确参数实例
Feature Variant → producer node version + output port
```

这样一个多输出 Node 可以为一个或多个 Feature Family 提供端口，Family/Variant 不被计算打包方式绑死。

用户反馈已经明确否定“同一 Node Run 的输出自然属于同一家族”。`body`、`range`、`shadow` 使用不同公式，必须分别归类。更严格的 Family 判定转入 [`家族身份与开放输入聚合器设计讨论.md`](家族身份与开放输入聚合器设计讨论.md)。

### Q2：事件信号能否直接进入所有聚合器

推荐不设置全局自动转换。每个 Aggregation Family 明确声明是否接受：

- 仅连续标量；
- 连续标量与事件分数；
- 向量；
- 混合输入。

需要把事件转成连续强度时，使用显式 Processing/Adapter Node，不能由聚合执行器静默转换。

### Q3：Stage 3 是否只显示聚合前信号

推荐 Stage 3 同时显示：

- Stage 3 新生产的输出；
- 从 Stage 1/2 透传而来的、具备 Pre-Aggregation Signal Contract 的输出。

不具备聚合前契约的中间 Payload 即使技术上透传到 Stage 3，也不能出现在“进入聚合”选择区，只能作为 Stage 3 节点输入或在血缘中查看。

此建议已被后续讨论修正：所有 Raw/Feature Output 都能抵达并显示在聚合候选区；是否能选入聚合取决于当前 Aggregation Input Policy。没有兼容模型的输出置灰，但仍可查看、导出和追溯。
