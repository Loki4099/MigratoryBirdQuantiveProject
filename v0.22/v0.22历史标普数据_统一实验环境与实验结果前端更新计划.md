## 1. 本轮目标

本轮分为三个相互依赖、但必须按顺序交付的任务：

1. **更新数据库与数据发布链**
   - 本轮只建立按生效日变化的历史标普 500 成分 Universe；
   - 以稳定证券身份整合可证明来源的免费行情；优先审计 Nasdaq Data Link WIKI，并受控复用已冻结的 Yahoo/Tiingo 对象；
   - 对退市、并购、ticker 变更、缺失行情和公司行动给出显式证据、人工 resolution 和质量结论；
   - 由不可变 Source/Evidence 和确定性 reconciliation 发布唯一 Canonical Dataset，禁止在运行时联网修数据。
2. **冻结统一实验环境**
   - 冻结 504 个完整交易日的 v1 暖机政策；
   - 冻结统一 `evaluation_start / evaluation_end`；
   - 周频与月频分别形成不可混排的 Evaluation Cohort；
   - 禁止系统通过数据交集自动推迟回测起点；覆盖不足的因子或配置必须拒绝进入 Cohort。
3. **修改实验前端展示**
   - 一个 Portfolio Cell 对应排行榜中的一行；
   - 同一频率只排列共享完全相同实验环境的结果；
   - 支持按 Sharpe 等指标排序，并显示 CAGR、相对 SPY 的 CAGR 差、Sharpe、最大回撤等核心指标；
   - 点击行进入详细配置、曲线、诊断、质量和血缘；
   - 每个合格的具体 Cell 可以独立升级为 Product 研究候选。

这三个任务不是三套独立功能。前端排行榜只能读取已冻结 Evaluation Cohort 下的结果；不得在前端临时把不同区间或数据版本的结果拼在一起。

## 2. 已确认的产品决定

以下决定来自用户已确认的讨论，冻结后实施不得自行改写：

1. 回测 Universe 使用**历史时点有效的标普 500 成分**，不能用今天的成分名单覆盖过去。
2. 研究行情允许使用免费多源数据；已冻结的 Yahoo/yfinance 后复权日度数据可以复用，但不再被定义为唯一权威来源。
3. 数据证据必须诚实标注为：

   ```text
   historical constituent PIT membership
   + frozen reconciled retrospective price snapshot
   ```

   即 Universe 成分按历史时点处理，但免费源历史价格不是 provider-native PIT 发布版本，未来重新抓取可能修订。每个发布版本必须冻结全部来源、原始 hash、人工 resolution、统一排除和 reconciliation policy。
4. 后复权或其他已解释的数据质量警告不单独阻止研究结果升级为 Product 候选；Product 页面持续显示数据口径、来源和修复警告，正式决策与交易执行映射回实际市场价格。会破坏 Security 身份、持仓估值/结算、统一环境或确定性回放的问题仍是硬阻塞。
5. 同一排行榜中的所有配置必须拥有完全相同的回测起点、终点、Universe、数据版本、Benchmark、成本、日历、执行规则和指标版本。
6. 系统不得为了接纳短历史资产或因子自动推迟统一起点。覆盖不足的配置应被拒绝。
7. v1 暖机窗口为冻结起点之前 **504 个完整交易日**。当前 v0.22 Processing 最大累计依赖为 252 个交易日，MA200 防御需要 200 个交易日，因此 504 日覆盖当前全部已发布能力。
8. 新因子若需要超过 504 日历史，不能修改旧 Cohort；必须拒绝进入 v1，或在未来发布新的 Warmup/Evaluation Cohort 版本。
9. 周频与月频不得进入同一个排行榜；相同配置在两个频率下是两个独立 Portfolio Cell/Result。
10. 每个具体 Portfolio Cell 独占排行榜一行，并可独立升级为 Product 候选。
11. “年化收益”使用组合净值 CAGR；“年化超额”使用：

    ```text
    strategy_net_cagr - spy_benchmark_net_cagr
    ```

    稳定指标键沿用 `cagr_spread`。
12. 排名和元素消融只用于历史研究辅助，不声称因果归因或未来收益保证。
13. 本轮只建设标普 500 Universe；Nasdaq-100、Russell、Dow、VIX 及其他指数的成分与行情都不扩入本轮。
14. 实验启动默认同时创建周频与月频的独立 Cell；两者共享数据和起止日，但分属不同 Cohort 与排行榜。

## 4. 当前系统事实与缺口

### 4.1 可以复用的现有能力

现有数据库与服务已经提供：

- 稳定证券和发行人身份：`catalog.security / catalog.issuer`；
- 带有效期的证券标识：`catalog.security_identifier`；
- Universe 历史与快照：`catalog.universe_history / universe_snapshot / universe_snapshot_member`；
- 冻结源数据：`data.source_snapshot`；
- Dataset、Daily Bar 和公司行动：`data.dataset_publication / daily_bar / corporate_action`；
- 退市终值身份：`catalog.security_terminal_event`；
- Warmup 与运行后 Comparison Cohort：`experiment.warmup_policy_version / comparison_cohort_version`；
- v0.22 Graph Suite、Portfolio Cell Result、指标、路径、诊断、血缘和 Product 候选升级。

因此本轮不另造第二套 Security Master、行情体系或 Result 系统。

截至 2026-08-16 的本地主库只读基线为：181 个 Security、164 个已桥接 Asset、810,499 条 `daily_bar`、183 个 Source Snapshot；但 issuer、Universe Methodology/History/Snapshot/Member 和 Terminal Event 均尚未正式发布。该基线只用于规划，不是发布 Gate 证据。

本次还完成了对同级项目 `FactorMachineLearning/MomentumRversionMethod` 的只读核对。其本机外置运行目录保存了可用的数据种子：

- 冻结版本 `sp500-pit-free-research-2013warmup-2018eval-2026-v3-final-candidate`；
- 历史成分原始文件为 MIT 许可的 `fja05680/sp500` 日度完整 Snapshot，覆盖 1996-01-02 至 2026-06-30；
- 原始文件有 2,718 个数据行；修复后产物有 745 个稳定 Security、754 个成员区间；
- 行情有 2,527,785 行，但只覆盖 2013-01-02 至 2026-06-30；
- 610 个 Security 使用 Yahoo、71 个使用 Tiingo，64 个仅有明确 `unavailable` 结论而没有有效价格；
- 已审计 58 条公司行动、162 个成员退出、ticker/identity 修复、交易性例外和 terminal resolution；
- 该数据被原项目明确标记为 `free_research_candidate / formal_eligible=false`，不能直接改名为正式 PIT 数据。

因此已确定的路线是“**复用并扩充**”，而不是全量重抓或直接复制最终 Parquet：保留原始成分文件、哈希、身份/终止/公司行动修复台账作为导入种子；已验证的 2013–2026 对象按 hash 复用；主要新增抓取 2004-12-31 至 2012 年末的缺口，然后在 v0.22 身份、血缘和 QA 下重建整个新 Dataset Release。

### 4.2 必须修复的核心缺口

1. v0.22 动态 Universe 当前主要冻结并消费单个 Snapshot，不能在历史回测中按 decision session 切换标普成员。
2. 现有 provider 发布路径仍可能通过当前 ticker 字符串反查 Asset；ticker 改名、复用、退市和 share class 变化可能绑定错误证券。
3. 当前 Eligibility 主要是每资产静态结论，缺少 Cohort 共享的“证券 × 日期”资格区间。
4. Suite command 和 Planner 会取多个输入覆盖区间的交集，并通过 `max(starts) / min(ends)` 动态修改有效区间。
5. Strategy 与 MA200 运行时目前允许跳过早期未暖机日期；这会导致不同配置的真实首个决策日不同。
6. 现有 Comparison Cohort 是完成结果发布后的集合，不能承担运行前冻结实验环境的职责。
7. 当前实验页以 Suite/结果卡片为主，没有 Cohort 级排行榜、按频率切换、完整结果详情入口和逐行 Product 操作。
8. 当前 Common Panel 近似为“结果日期 × Asset Context 全部成员”的笛卡尔积，不能表达历史成分加入前、退出后的不可投资区间。
9. 当前 v0.22 Product promotion 主要发布候选身份，但 Product 主页面从 Enrollment 读取；存在“升级成功但新 Product 在主页面不可见”的断链。
10. 可复用数据种子的价格始于 2013，不能覆盖 2007–2009 完整危机周期；早期退市股的免费行情缺口会明显高于现有 64 个 unavailable 结论。

## 5. 目标身份链

```text
Security Master Release
  → Security Identifier Intervals
  → Historical S&P 500 Universe History
  → Multi-source Source Snapshots + exact Security Subjects
  → Identity / Lifecycle Resolution Evidence
  → Frozen Canonical Dataset Release
  → Dataset Gate Assessment (ranking eligibility + product eligibility)
  → Cohort-wide Eligibility Intervals
  → Warmup Policy Version (504 sessions)
  → Evaluation Cohort Version (pre-run)
  → Graph Suite / Portfolio Cells
  → Immutable Cell Results
  → v0.22 Ranking Cohort Release (post-run leaderboard membership)
  → Product Candidate / Qualification / Enrollment
```

`Evaluation Cohort` 与 `Ranking Cohort Release` 必须分开：

- Evaluation Cohort 在运行前冻结环境，决定一个 Suite 是否可运行；
- Ranking Cohort Release 在运行后冻结排行榜成员，防止新结果自动改变旧排行榜。

现有 legacy `comparison_cohort_version` 还把 strategy template/K 等配置轴放入 protected context，并限制旧 K 范围，不适合作为“同环境下比较不同策略配置”的 v0.22 主榜。应新增 v0.22 ranking identity；旧表继续可读，不用伪装复用。

## 6. 任务一：数据库与数据发布更新

### DB-1：稳定证券标识和多源抓取对象

继续复用 `catalog.security` 与 `catalog.security_identifier`：

- 每个历史标普成分，包括已退市、被收购和改名证券，都拥有永久 `security_id`；
- identifier 至少支持：`exchange_ticker`、provider-scoped ticker（Yahoo、WIKI 等）、`CIK` 和 FIGI；有可靠授权来源时再加入 CUSIP；
- ticker 区间采用半开区间 `[valid_from, valid_to)`；
- 用 provider scope + identifier value + `[valid_from, valid_to)` 的排他/等价 overlap guard，禁止同一 provider identifier 在同一时间映射到不同 Security；
- 单纯 ticker 改名在有 rename-chain 证据时不创建新 Security；换股重组、share-class conversion、ticker reuse 必须独立审查，不得仅按字符串合并；
- 现金收购、换股、破产、清算等由 terminal/reorganization evidence 表达。

建议新增最小投影：

```text
data.source_snapshot_security_subject
  source_snapshot_id
  security_id
  provider_symbol
  security_identifier_id
  fetch_status
  failure_reason
  created_at
```

发布器必须由该投影把 Source Snapshot 精确绑定到 Security，禁止继续用 ticker 字符串猜测。

### DB-2：现有标普数据种子的受控导入

不直接复制另一项目的最终 Parquet 作为新系统权威表，而是做一次 content-addressed import：

1. 对原始历史成分 CSV、`SOURCE_README`、MIT License 和 source hash 发布 Source Snapshot；
2. 将 51 条 identity override、membership boundary override、tradability override、corporate action 和 terminal resolution 台账作为独立 Evidence；
3. 将 745 个 canonical SID 只作 Security Master 候选，重新发布为 v0.22 稳定 Security 和带有效期 Identifier；
4. 对已有 2013–2026 raw/canonical 对象重新验 hash 和语义，通过者可重用物理内容，但发布新的 v0.22 Artifact/Dataset 身份；
5. 先审计 Nasdaq Data Link `WIKI/PRICES` 对历史 source symbol 的覆盖及 2013–2018 重叠期差异；通过 provenance 与字段语义审查后，才可成为 2004–2018 早期行情候选；
6. 为候选的 2007 评价起点优先补齐 2004-12-31 至 2012 年末的价格缺口，并重跑全区间 QA；
7. 旧实验 Result、NAV 和排名不导入 v0.22 排行榜，只作交叉验证证据。

旧 manifest 中含有工作站绝对路径；新导入器只按 content hash 和受控 object root 解析，不把绝对路径带入新 Artifact 语义。

### DB-3：历史标普 500 Universe

使用现有 `universe_history / universe_snapshot / universe_snapshot_member`：

1. 导入一个可证明的初始完整成员 Snapshot；
2. 将每次全量 Snapshot 差分为 source-backed `universe_change_batch / universe_membership_event` 或等价 Artifact 投影；
3. 事件至少冻结 `seed|add|remove`、announcement time（来源可用时）、正式 effective session、source URI/hash/row、`confirmed|estimated|unresolved` 和 reason code；
4. 以每个成分变更的**正式生效交易日**发布新的完整 Snapshot；
5. 保存 added/removed 列表和 Security 映射报告；
6. 由事件账本派生完整 Snapshot 和半开成员区间；Snapshot 是运行时物化结果，不是丢失来源的手工真值；
7. 回测时按冻结的 effective session 解析当日成员，不查 `latest` 发布版本。

年度名单或当前名单不能替代完整变更历史。现有公开源为事后整理的全量快照，没有当时可知的完整 announcement timestamp；因此它能提供成员生效日的回溯重建，但不声称为 provider-native PIT。无法确认的成员或有效日期必须进入 unresolved 报告。

### DB-4：免费多源历史行情、公司行动与人工 Resolution

每个来源分别抓取并冻结：

- raw open/high/low/close/volume；
- provider adjusted close（仅作来源证据，不能跨来源直接拼接）；
- dividends；
- stock splits；
- provider symbol、抓取参数、抓取时间、adapter 版本、许可/使用条件和原始响应哈希；
- 每个 Security 的覆盖范围和抓取状态。

Canonical 层优先以 raw OHLCV 与 corporate actions 按同一确定性规则重建后复权序列，同时永久保留每个来源的原始事实。备用源只能补经审核的精确区间，不能直接混合不同供应商的 adjusted close。重新抓取或人工 resolution 必须产生新的 Source Snapshot/Evidence 和 Dataset Release，禁止覆盖旧版本。

退市与复杂公司行动规则：

- 任一主源找不到的历史成员不得静默跳过；系统应生成身份、缺口和生命周期审查项；
- 按 identifier 有效区间逐段抓取；
- 多 ticker 段重叠时必须人工或规则化核对；
- 缺失最后交易价、并购对价或退市终值时标记 `unresolved`；
- 普通指数调出不是 terminal event；成员资格在 effective removal session 结束，存量持仓的平仓/结算另读 execution/terminal policy；
- 纯 ticker 改名沿同一 Security 分段抓取；现金并购、换股、拆分资产必须保存 successor Security、exchange ratio、cash component、last-trading/settlement session 证据；
- 停牌不改变成员身份，但使 `selectable/tradable=false`；既有持仓按冻结 valuation policy 处理，禁止用供应商缺 bar 自动推断停牌；
- 人工结论只能作为 append-only Evidence/Resolution Artifact，不能直接改写原始对象、Canonical Bar 或旧 Dataset；结论必须经新 Dataset Release 生效；
- 冻结后的 Graph Suite/Portfolio Runtime 不联网，不根据回测结果临时搜索或修复数据。

### DB-5：数据质量与发布 Gate

每个候选 Dataset Release 必须生成聚合报告，而不是输出数十万行日志：

- 每个交易日的成分数量与异常变化；
- identifier 未解析、冲突、重用和重叠；
- 无行情、短历史、异常空洞和重复日期；
- OHLC 合法性、非正价格、负成交量、极端收益；
- splits/dividends 与 adjustment factor 一致性；
- terminal event 和最后可执行价格覆盖；
- confirmed halt、provider gap、未上市、成员调出和 terminal event 的分类对账；
- Benchmark 与 Calendar 覆盖；
- 每项 unresolved 的稳定 reason code。

Dataset 可以携带已知质量警告发布，但必须同时生成不可变 `Dataset Gate Assessment`，分别给出 `ranking_eligibility` 与 `product_eligibility`。以下计算正确性条件仍必须满足：

- 历史成分在声明覆盖期内可完整重建；
- 所有 Security 映射唯一；
- 所有会进入共同资格掩码或已有持仓路径的资产拥有确定性行情、估值或结算政策；
- Dataset Artifact、Source Snapshot、Universe History、Calendar 和 Cleaning Version 血缘完整；
- 数据语义明确标注为 historical-membership PIT + frozen reconciled retrospective prices；
- 所有人工 resolution、备用源补段、统一排除和 reconciliation policy 均有可重放 Evidence 与 fingerprint。

### DB-6：排行榜与 Product 的独立准入

免费数据不可能靠一个 `formal_eligible` 布尔值解决全部问题。本轮冻结两个相互独立的准入维度：

1. **`ranking_eligibility`**
   - `rankable_research`：成员身份、生效日和共同排除规则确定且有 source evidence，可进入同环境主榜；
   - `exploratory_only`：存在会削弱横向可比性的 estimated/unresolved 证据，只进入独立探索结果列表，不与主榜混排。
2. **`product_eligibility`**
   - `eligible`：数据证据完整；
   - `eligible_with_warnings`：可以创建研究 Product，但 Product 页面必须持续显示免费源、回溯复权、人工 resolution、备用源、统一排除和已知偏差；
   - `ineligible`：存在会改变 Security 身份、持仓估值/结算、统一环境或确定性回放的未解决问题。

`ranking_eligibility` 与 `product_eligibility` 不互相推导。一个 `exploratory_only` Result 若计算身份和持仓路径确定，仍可为 `eligible_with_warnings` 并升级研究 Product；反之，一个可排名 Result 也可能因持仓结算缺口而暂时 `ineligible`。

以下问题不能用警告或 exploratory 开关绕过：Security 身份碰撞、成员账本自相矛盾、无 Benchmark、空 Panel、日期顺序损坏，或持仓必经但无任何确定性估值/终止政策的路径。每个 Evaluation Cohort 和 Product Qualification 必须绑定 exact Gate Assessment Artifact/fingerprint，不读全局“当前最新状态”。

### ENV-2：504-session Warmup Policy

发布：

```text
policy_key = sp500_shared_504_completed_sessions_v1
required_observations = 504
resolution_method = frozen_cohort_requirement
```

现有通用 `experiment.warmup_policy_version` 可复用，但 migration 必须把旧的单值 method check 扩展为同时允许 `dependency_max_required_history` 和 `frozen_cohort_requirement`；旧 row 身份与语义不得漂移。

对照项目使用了约五个日历年的暖机，是因为其后期风险状态最多需要约 1,137 个先前交易日。该要求不属于当前 v0.22 Catalog：当前最大 Processing 累计依赖为 252 个 session，MA200 为 200 个 session。因此 v1 仍冻结 504 个完整 session；任何未来因子、模型或防御方案若声明的 `required_input_history_sessions > 504`，必须被 v1 admission 拒绝，并在未来发布新的 Warmup/Evaluation Cohort，不能暗中延长或移动现有 Cohort。

要求：

- `warmup_start` 由 XNYS Calendar 向前数 504 个完整 session 得出；
- 暖机期不计入收益和指标；
- 第一 evaluation session 必须已经产生合法的全部选择信号；
- MA200 在第一决策日必须拥有精确 200-session window；
- Strategy 不得继续动态跳过不可排名的早期日期。

### ENV-3：共同 Eligibility Mask

在现有 Eligibility Snapshot 下新增或等价实现：

```text
catalog.eligibility_interval
  eligibility_snapshot_id
  security_id
  valid_from
  valid_to
  is_member
  is_warmup_ready
  is_selectable
  is_tradable
  valuation_state = live | stale_confirmed | terminal | unavailable
  reason_codes
  evidence_artifact_ids
```

规则：

- 标普加入前的历史价格可以用于暖机，但加入生效日前不可投资；
- 加入时已有 504 个有效完成 session 的证券可从生效日开始进入候选池；
- IPO/新上市证券不足 504 session 时仍可为 `is_member=true`，但 `is_warmup_ready/is_selectable=false`；满足共同政策后才统一开放；
- 普通标普移除只终止成员资格，不等同于证券退市；成员移除日、最后交易日和最终结算日必须分别表达；
- 纯 ticker 改名在有证据时保持同一 Security 并按标识有效期分段；ticker 复用或换股重组不得仅按字符串判断为同一身份；
- 已确认停牌不改变成员身份，但应使 `is_selectable/is_tradable=false`；存量持仓估值按冻结的 `valuation_state` 处理。任一 provider 缺 bar 不能自动解释为停牌；
- 现金并购、换股、合并或拆分必须绑定 successor/allocation/cash/settlement Evidence；无法解释的持仓估值或终止路径不得进入主排行榜；
- 同一 Evaluation Cohort 的所有策略共享完全相同的 asset-date mask；
- 不得因某个策略缺值而临时从截面删除资产；
- 活跃可选择/可交易成员在所需决策、执行或估值日缺关键行情时，应使 Cohort 或配置 fail closed。

### ENV-4：固定区间 Admission

必须移除以下运行语义：

- 从数据输入自动选择“最长共同历史”；
- 用 `max(starts) / min(ends)` 缩短 requested range；
- Strategy 跳过早期日期直到资产足够；
- MA200 跳过不足 200 日的早期日期。

替换为：

1. Suite 提交时必须选择 exact Evaluation Cohort；
2. Planner 逐项验证所有输入覆盖 `[warmup_start, evaluation_end]`；
3. 任何输入覆盖不足，使用稳定 blocker/reason code 拒绝；
4. Result 的 `effective_start/end` 必须精确等于 Cohort 的 `evaluation_start/end`；
5. Runtime 输出若缺少首日、末日或共同 decision sessions，禁止发布；
6. 前端不能提供“自动调整起点”开关。

Result Evidence 的 Common Panel 必须直接引用 Evaluation Cohort 的历史成员/Eligibility Panel；禁止再用“所有结果日期 × 全部成员”的笛卡尔积重建。成员加入前、退出后不得出现在可投资 panel 中，加入前行情最多作为暖机证据。

### ENV-5：起点冻结程序

基于对照项目和当前 v0.22 依赖图，本轮先提出以下 **v1 候选日期**，但在真实覆盖报告和用户最终确认前不得发布：

```text
warmup_start       = 2004-12-31
evaluation_start   = 2007-01-03
evaluation_end     = 2026-06-30
warmup_sessions    = 504 completed XNYS sessions
last_warmup_close  = 2006-12-29
```

`2007-01-03` 是 2007 年首个 XNYS 交易日，可覆盖危机前信贷恶化、2007 年高点和完整 2008 峰谷；比从 2008 年直接起算更适合作为回撤压力样本。程序如下：

1. 以候选日期对历史成分、标识、停牌/退市/重组、行情、公司行动和终值运行覆盖报告；
2. 以冻结 XNYS Calendar 验证从 `warmup_start` 到 `evaluation_start` 之前恰好具备至少 504 个完整 session；
3. 对缺口优先补数据，特别是现有种子未覆盖的 2004-12-31 至 2012 年末，不自动向后移动；
4. 若仍无法以可接受成本解决，向用户呈现具体资产、日期、事件和备选方案；程序不得自行改动候选起点；
5. 用户根据覆盖报告明确确认 exact dates 后发布 Evaluation Cohort v1；
6. 发布后任何日常数据追加都不得改变 v1 的 start/end、Universe、Eligibility Mask 或历史数据版本。

未来扩展 `evaluation_end` 时发布新的 Dataset/Evaluation Cohort 版本，并重跑全部配置。不同 Cohort 版本不得混入同一个已发布排行榜。

### ENV-6：周频与月频

- 周频、月频使用相同 Universe History、Dataset、Eligibility、Benchmark、成本和 evaluation start/end；
- 日程/频率不同，因此是两个 Evaluation Cohort；
- 排行榜以 frequency tab 切换，不允许跨频率排序；
- 所有正式进入主排行榜的策略能力必须明确声明 weekly/monthly；
- 当前只支持 weekly 的策略若要进入双频率主榜，必须先发布月频兼容 Catalog Version，不能由前端伪造。

实验启动页建议支持：

```text
运行频率：周频 / 月频 / 两者（默认）
```

选择“两者”时创建两个精确 Suite 或一个明确含两种 schedule Cell 的受控批次；实现必须保证两个频率分别绑定各自 Evaluation Cohort，不能混为一个 Ranking Cohort Release。

### ENV-7：运行后 Ranking Cohort Release

新增 v0.22 专用的不可变排行榜发布身份：

```text
experiment.v022_ranking_cohort_release
  ranking_cohort_release_id
  artifact_id
  evaluation_cohort_version_id
  metric_catalog_version_id
  default_metric_key / direction
  context_fingerprint
  version_number
  member_count
  status / published_at

experiment.v022_ranking_cohort_member
  ranking_cohort_release_id
  result_evidence_snapshot_id
  result_artifact_id

```

规则：

- 一个 Release 只能引用一个 exact Evaluation Cohort；
- weekly/monthly 必然属于不同 Release；
- factors、Aggregator、Strategy/K、Defense 可以在 member 行之间变化；

- 浏览器无 console error，API 无意外 4xx/5xx。

### 10.4 真实数据验收

- 输出历史成员覆盖起止、Snapshot 数和成员变化数；
- 输出抓取成功/失败/未解析/退市终值缺失数量；
- 输出最终候选 start/end 和 504-session warmup_start；
- 用户确认 exact Evaluation Cohort 日期；
- 用相同 Cohort 运行至少两个不同配置，证明区间、Universe、Benchmark、成本一致；
- 用 weekly/monthly 各运行代表 Cell，证明排行榜隔离。

本轮不先扩张成大规模 edge-case 矩阵；先证明正常主链和上述会破坏实验公平性的关键失败语义。完整压力、并发和长时间数据恢复测试在主链完成后单独安排。

## 11. 数据与磁盘治理

- 大型 Source Snapshot、原始 CSV/Parquet 和 Payload Object 应放在 OneDrive 外的内容寻址对象目录；
- 项目数据库只保存 URI、hash、size、Manifest 和 Artifact lineage；
- 导入脚本支持 checkpoint/resume，失败后不重复下载已验证对象；
- 不把完整 provider 数据、数据库 dump 或临时下载目录提交 Git；
- `.gitignore` 只管理 Git，不承担 OneDrive 排除；环境/对象根通过 `.env` 配置；
- 每个 Dataset Release 有保留策略，但未经用户批准不得删除旧 Release。

## 12. 回滚与兼容

- 所有新身份 append-only；旧 Result、旧 Suite、旧 Dataset 可读，不回填伪造身份；
- 新 Evaluation Cohort 未通过验收前不设为默认；
- migration downgrade 遇到已发布新身份必须 fail closed，禁止静默丢数据；
- 新前端可在未选择 Cohort 时回到运行历史，但不得回退到混合 v0.21 排行逻辑；
- 若真实数据导入失败，只撤销未发布 draft/import batch，不修改旧发布物；
- 任何需要修改 v0.21 设计或运行语义的步骤必须先向用户报告并确认。

## 14. 已确认并冻结的最终决定

以下事项由用户于 2026-08-16 至 2026-08-17 确认：本轮只建设 S&P 500 Universe；使用已找到并核验的本地历史成员/行情种子执行“复用并扩充”；周频和月频默认同时创建、分属独立 Cohort 和排行榜；免费数据质量问题可以警告形式进入研究 Product，但不能掩盖计算正确性问题。

1. 以 `warmup_start=2004-12-31`、`evaluation_start=2007-01-03`、`evaluation_end=2026-06-30` 作为覆盖审计候选；审计不得自动移动日期，最终发布前仍向用户提交具体缺口报告。
2. 少量、有明确证据且对所有策略统一排除的 provider-unavailable Security 可以进入 `rankable_research`，但主榜和 Product 候选必须显示排除数量与偏差警告。
3. 成员日期或一般数据证据为 estimated/unresolved 时只能进入隔离的 `exploratory_only` 排名环境；若 Security 身份、持仓估值/结算和确定性回放仍完整，可以 `eligible_with_warnings` 升级研究 Product。影响计算正确性的 ambiguity 必须为 `ineligible`。
4. Provider provenance 与使用条件是发布 Gate；无法证明的对象不能作为权威输入，可按固定的统一排除或备用源 resolution 进入新 Gate Assessment，不得由 Product 开关直接绕过。
5. 本轮采用免费多源路线：先审计 WIKI，受控复用已冻结 Yahoo/Tiingo，并用 SEC/OpenFIGI/交易所/公司公告补身份和生命周期证据；不把购买付费数据设为 Product 前置条件。
6. `eligible_with_warnings` Product 必须永久显示 historical membership、retrospective price、来源、人工修复、统一排除、Gate 与 Dataset fingerprints；警告不阻止运行，新的正确性 blocker 会停止新决策。
