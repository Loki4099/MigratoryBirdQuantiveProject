# v0.22 clean-green G0/G1 执行清单

状态：代码准备完成，等待 Docker Desktop 恢复后执行。本文不授权删除 blue。

## 1. 边界

- blue 只读导出；不得更新、失效或删除任何旧 Artifact。
- transfer contract 固定为 `migratory_bird_v022_green_transfer_v2`。
- 包只承载 v5/v6 行情值与重建 Security、Calendar、历史 S&P 500 成员和生命周期所需的 source facts。
- 旧 Dataset publication、Gate、Cohort/Runtime、Product、Draft、Round、Suite、Result、Evidence、Ranking、Work、cache、payload manifest 与 lineage projection 不得进入 green。
- metadata CSV 是重发新身份的事实输入，禁止直接 `COPY` 到对应业务表。

## 2. 启动隔离 green PostgreSQL

```powershell
docker compose -f compose.green.yaml up -d
```

固定隔离项：Compose project `migratorybird-green`、端口 `55433`、数据库 `style_rotation_green`、volume `migratorybird-green_style_rotation_postgres_green`。

## 3. 空库迁移

对 green `DATABASE_URL` 运行 `alembic upgrade head`。不得复用 blue 的数据库名、volume 或端口。

## 4. 导出并验证 transfer package

transfer package 必须放在 OneDrive 外，例如：

`%LOCALAPPDATA%\MigratoryBird\green_transfer_v2`

```powershell
python scripts/export_v022_green_transfer.py `
  --database-url <BLUE_READ_ONLY_URL> `
  --output <TRANSFER_PACKAGE_DIRECTORY>
```

导出在 `REPEATABLE READ READ ONLY` 事务中执行，并自动验证全部文件 SHA-256、Parquet 行数、树结构和四个冻结总行数。

## 5. green 写入前门禁

```powershell
python scripts/preflight_v022_green_database.py `
  --database-url <GREEN_URL> `
  --expected-database style_rotation_green `
  --package <TRANSFER_PACKAGE_DIRECTORY> `
  --report <PREFLIGHT_REPORT_PATH>
```

门禁要求：

- migration 为 `20260821_136_v022_calc_ctx`；
- Dataset、Draft、Suite、Result、Evidence 与 Product 业务表均为 0；
- v4 Dataset UUID 与两个旧 Product enrollment UUID 命中数均为 0；
- transfer package 为 v2 且 metadata 文件精确等于 source-fact allowlist。

任何一项失败均停止，不得开始 baseline import。
