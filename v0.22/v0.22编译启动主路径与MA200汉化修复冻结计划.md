# v0.22 编译启动主路径与 MA200 汉化修复冻结计划

状态：**FROZEN / APPROVED**
冻结日期：2026-08-14
适用范围：v0.22 Graph Draft → Compile → Experiment Launch → Suite Worker → Progress/Result 主路径
产品决定：用户已确认；实施不得自行扩大范围。

## 1. 本轮目标

本轮只解决两个直接阻断前端验收的问题：

1. 中文界面完整展示当前 MA200 分档防御方案。
2. 用户可以从当前研究配置明确、稳定地完成：

   `选择因子 → 编译 → 确认 → 启动回测 → 查看真实进度 → 查看结果`

修复完成前，不继续扩展因子、策略、Product、诊断指标或其他边际能力。

## 2. 已冻结的产品决定

### 2.1 编译与启动保持两步

- “编译”只验证并冻结当前 Graph Draft revision，生成不可变 Compiled Research Graph；不启动计算。
- 编译成功后，前端**自动进入实验确认页**。
- 实验确认页展示资产范围、最终信号、聚合器、策略、防御、分支数、Cell 数和编译身份。
- 只有用户再次点击“启动回测”后，系统才提交 Suite。
- 启动成功后立即进入该 Suite 的进度页；后台异步执行，HTTP 请求不得同步跑完整回测。

### 2.2 当前遗留失败测试直接清理

精确目标：

- `research_suite_id = f862db7c-320c-5e95-8a3b-b899f477f451`

- 当前状态：`not_started`
- 当前工作项：0

该记录属于开发过程中的失败测试，不需要保留。实施时允许物理删除其专属身份和无共享价值的专属依赖。

清理前必须只读确认：

## 3. 已确认的根因

### 3.1 MA200 汉化断链

- Catalog 当前稳定键是 `ma200_tiered_defense`、`spy_ma200_tiered_budget` 和 `standard_defensive_basket_long_history_v1`。
- 前端翻译表仍主要覆盖旧键 `ma200_defense`。
- 防御卡片直接展示 Catalog 英文 `name`，导致中文模式泄漏英文主标题。
- Catalog/API 已提供完整语义，无需修改 Catalog、发布身份、数据库或 API schema。

### 3.2 编译状态只保存在浏览器临时状态

- 当前 Compile response 仅保存在 `sessionStorage`。
- 刷新、换标签页、关闭后重开或直接进入“实验”页后，前端无法恢复当前 revision 的已编译身份。
- 后端已有 `last_compiled_research_graph_id`，但未提供服务器验证过的 current compile 读取契约。

### 3.3 启动入口与实验导航断开

- “前往实验确认”只在策略页编译成功后条件出现。
- 侧栏“实验”直接进入历史列表，绕过确认页。
- 因此用户按正常导航进入实验页时看不到当前已编译研究的启动动作。

### 3.4 Suite Worker 未纳入本地运行协议

- `POST /api/v2/workspace/graph-suites` 当前快速发布 Suite identity。
- 真正的 Materialization、Runtime Plan、Work Spec、Strategy/Defense/Merge/Portfolio Cell 执行由独立 `style_rotation.cli.v022_suite_worker` 完成。
- 当前本地前端/API 启动流程没有可靠启动和监管该 Worker，导致 Suite 长期停留在 `not_started / 0 work items`。

### 3.5 状态和失败语义不完整

- `not_started` 是“已提交、等待 Worker 规划”，不是完成态，也不是永远静止的历史身份。
- 前端当前会停止轮询 `not_started`，Worker 后续接手时页面不会自动更新。
- 未启动时读取 Results 应返回结构化业务状态，不应暴露原始响应模型 422。
- Draft 锁定与 Suite 发布必须形成安全提交边界，不能出现“启动失败但 Draft 已归档锁定”。

## 4. 实施工作包

### WP-1：MA200 中文展示

修改范围：

- `frontend/src/components/ResearchText.tsx`
- `frontend/src/pages/GraphWorkspacePage.tsx`
- `frontend/src/test/GraphWorkspacePage.test.tsx`

要求：

- 补齐当前 MA200 package、timing policy、allocation policy 及可见规则字段和值的中英文映射。
- 中文模式以中文名称和金融解释为主；稳定 key、版本和精确公式作为次要技术信息保留。
- timing/allocation 标题按稳定 `variant_key` 本地化，不直接把 Catalog 英文名称作为中文主标题。
- 英文模式保持原有英文语义。
- 不修改 Catalog JSON、Artifact fingerprint、数据库或发布版本。

### WP-2：服务器端 Current Compile 契约

新增只读契约，二选一实现：

- `GET /api/v2/workspace/graph-drafts/{draft_id}/current-compile`；或
- 在 Graph Draft snapshot 中增加 nullable `current_compile`。

契约必须：

- 仅返回 actor 自己的 Draft；
- 只接受当前 revision；
- 精确匹配 `last_compiled_research_graph_id`、成功 Compile Attempt、Graph Artifact、Risk Execution Context 和全部已选 Defense Execution Context；
- 任何 revision mutation/reset 后立即视为未编译；
- 不使用 `latest`、时间排序或浏览器 idempotency key 猜测身份；
- 返回足以直接提交 Suite 的精确 `compiled_research_graph_id`、Draft ID/revision、Graph fingerprint 和 Context 身份。

前端恢复 Draft 时必须从服务器恢复 current compile；`sessionStorage` 最多作为缓存，不再是权威来源。

### WP-3：Compile → Confirm → Start 用户路径

- Compile 成功后自动导航到 `/experiment-launch`（或等价稳定路由）。
- 不自动提交 Suite。
- 确认页无 current compile 时显示明确返回路径，不允许提交陈旧 revision。
- “实验”历史页顶部增加“当前研究已编译、尚未启动”卡片及启动入口。
- 启动按钮双击/重试使用同一幂等命令，不得生成重复 Suite。
- 启动成功后导航到 `/experiments?graph_suite=<id>`。
- 当前 Draft 在 Suite 被可靠接受后进入只读；失败时保持可编辑并显示可恢复错误。

### WP-4：异步 Suite Worker 纳入本地运行协议

- 保持 API 快速提交，禁止在 HTTP 请求线程同步跑完整回测。
- 新增唯一的 v0.22 本地启动/停止方案，同时托管：
  - FastAPI（含当前 production frontend build）；
  - `python -m style_rotation.cli.v022_suite_worker --forever`。
- 两个进程使用同一代码版本、数据库、Payload 目录和环境 fingerprint。
- 启动器必须精确记录自身 PID 和日志；端口或已有进程冲突时 fail closed，不得复用未知旧进程。
- 停止命令只能停止由该启动器创建并记录的进程。
- API/前端提供可读的 Worker readiness；Worker 不可用时，启动按钮应明确提示“运行服务未就绪”，不能创建永久 `not_started` 记录。

### WP-5：状态、轮询与结果错误

- `not_started` 文案改为“已提交，等待运行时规划”。
- `not_started` 不显示伪进度条、不请求 Results，但继续低频轮询 Status。
- 进入 materializing/targeting/merging/evaluating 后按正常频率轮询。
- completed 后停止轮询并加载 Results；failed/cancelled 显示终态原因。
- Results 在尚未可读时返回结构化业务错误，例如 `suite_not_started` / `suite_not_complete`，不得由 Pydantic 校验漂移形成原始 422。
- 进度页必须展示 Suite ID、Graph ID、真实 total/terminal、当前阶段和失败原因。

### WP-6：遗留失败测试清理

按 2.2 的精确目标执行一次性清理：

1. 输出 dry-run 依赖闭包和预计删除行数；
2. 断言不存在 Product/Result/Run 依赖；
3. 在单事务中按 FK 逆序删除该失败 Suite 的专属行；
4. 删除后验证 Suite list 不再返回该 ID；
5. 验证共享 Compiled Graph、Catalog、Dataset 和当前 Draft revision 17 未受影响；
6. 单独提交维护变更/脚本，不提交数据库导出或用户数据文件。

## 5. 最小测试矩阵

### 5.1 前端定向测试

- 中文完整 composed MA200 fixture：包名、择时政策、防御篮子、规则标签和值均为中文主显示；不出现三项 Catalog 英文主标题。
- 英文模式仍显示英文名称。
- 点击 Compile 成功后自动进入确认页，但不会调用 Suite submit。
- 点击“启动回测”只提交一次，携带当前 Draft ID/revision 和精确 Compiled Graph ID；成功后进入对应 Suite 进度页。
- 清空浏览器临时状态并重新挂载后，服务器 current compile 能恢复确认/启动入口。
- revision 变化后旧 compile 失效。
- `not_started` 不请求 Results、继续 Status 轮询；状态变化后自动刷新。

### 5.2 后端/API 定向测试

- current compile：owner/current revision 成功；other actor、missing、stale revision 拒绝。
- Compile response 与 current compile response 的 Graph/Context 身份完全一致。
- Submit 幂等 replay 不重复创建 Suite。
- 提交失败不得把 Draft 留在只读/archived 状态。
- `total=0` 永不判定 completed。
- 未启动/未完成 Results 返回结构化业务错误。

### 5.3 Runtime 集成测试

- 小型代表配置（建议 ETF K2 + none）执行：submit 后 Worker 至少创建 Runtime Plan 和 `total > 0`，状态离开 `not_started`。
- 同一代表配置继续执行到 completed，并发布一个可读 Portfolio Cell Result。
- 单独覆盖 MA200：能够加载 200-session timing window 并生成 Defense Decision；不需要用 13 Cell 用户配置作为每次 CI 测试。

### 5.4 真实浏览器验收

在唯一的 `127.0.0.1:8000` production build 上执行：

1. 打开当前研究；
2. 中文 MA200 防御卡无英文主标题泄漏；
3. 选择合法因子/聚合/策略/防御；
4. Compile 后自动进入确认页；
5. 点击“启动回测”；
6. 跳转到精确 Suite；
7. 状态从 `not_started` 进入真实运行阶段，且 `total > 0`；
8. 小型代表 Suite 最终完成并可读结果；
9. 浏览器无 console error，API 无意外 4xx/5xx。
