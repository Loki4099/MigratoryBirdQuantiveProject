## 1. 与 v0.21 基础设施的关系

v0.22 不建立第二套血缘系统，继续复用：

- `lineage.artifact`：不可变发布物身份；
- `lineage.artifact_dependency`：Artifact 级有向依赖；
- `lineage.lineage_manifest`：完整祖先 Manifest；
- 现有数据库触发器：禁止依赖环、禁止发布后修改；
- `ArtifactService`：Semantic Fingerprint、Content Hash、幂等发布和失效传播；
- `workspace.research_draft`：带 revision 的可变草稿；
- `workspace.component_catalog`：版本化组件目录；
- `workspace.research_materialization_cache`：内容寻址缓存的设计基础。

v0.22 在这些基础上新增端口、节点运行、层投影、聚合实例和编译图语义。v0.21 的 Factor、Signal、Model、Experiment 和 Product 发布物保持不可变、只读兼容。

## 4. Payload 契约

### 4.1 PayloadContract

```python
class PayloadContract(StrictModel):
    payload_kind: PayloadKind
    media_type: str
    schema_key: str
    schema_version: int
    entity_scope: EntityScope
    temporal_grain: TemporalGrain
    value_semantics: str
    unit: str | None
    shape: tuple[int | str, ...] | None
    known_at_policy_key: str
    missing_policy_key: str
    compatibility_tags: frozenset[str]
```

要求：

- `schema_key + schema_version` 唯一确定字段、类型、Shape 和顺序；
- `known_at_policy_key` 明确事件何时可用于决策；
- `missing_policy_key` 明确缺失、空集合、不可映射和质量失败；
- `compatibility_tags` 只能用于快速筛选，不能代替完整契约验证；
- 未经显式 Adapter Node，不允许执行器静默改变频率、实体范围、时间窗口或 Shape。

### 4.2 聚合前标量信号

```python
class ScalarSignalContract(StrictModel):
    direction: Literal["higher_is_bullish", "lower_is_bullish"]
    cross_sectionally_comparable: bool
    normalization_key: str
    frequency: Literal["weekly", "monthly"]
    known_at_policy_key: str
    minimum_coverage_ratio: float
```

### 4.3 聚合前向量信号

```python
class VectorSignalContract(StrictModel):
    vector_schema_key: str
    vector_schema_version: int
    dimensions: int
    dimension_order_hash: str
    frequency: Literal["weekly", "monthly"]
    known_at_policy_key: str
    minimum_coverage_ratio: float
```

向量本身不要求可以直接横截面排名，但消费它的 Aggregation Method 必须明确如何把向量转换为 Final Signal。

### 4.4 普通数值 Feature 也可以成为聚合输入

Pre-Aggregation Signal Contract 不是进入聚合层的唯一通行证。所有 Output 都可以抵达聚合候选区；某个 Aggregation Method 可以明确接受普通数值 Feature，即使该 Feature 没有预定义方向或横截面排名意义。

```python
class AggregationInputCapability(StrictModel):
    accepted_payload_kinds: frozenset[PayloadKind]
    requires_signal_contract: bool
    requires_direction: bool
    requires_cross_sectional_comparability: bool
    requires_fixed_numeric_schema: bool
```

例如：

- `flat_equal_weight_mean` 要求定向、可横截面比较的标量 Signal；
- `dimension_equal_hierarchical_mean` 还要求冻结的 economic dimension 映射；
- `directional_majority_vote` 要求方向/事件输入；
- `lightgbm_cross_section_rank_regression` 可以接受固定 Schema 的普通数值标量，不要求输入预先拥有多空方向；
- 没有任何兼容 Aggregation Method 的文本、图像或中间对象仍可到达、查看和导出，但不可选入当前聚合实例。

## 5. Processing Node 目录契约

### 5.1 ProcessingNodeFamily 与 ProcessingNodeVariant

> 修订提示：同一 Node Run 的多个 Output Port 不构成同一研究家族。`body`、`range`、`shadow` 等不同公式必须属于不同 Feature Family。当前 `ProcessingNodeFamily` 类名已标记为待替换；最终模型应采用 `FeatureFamily/FeatureVariant → producer node version + output port`，详见 [`家族身份与开放输入聚合器设计讨论.md`](家族身份与开放输入聚合器设计讨论.md)。

三个加工层都使用与 v0.21 一致、但更通用的家族归纳：

```python
class ProcessingNodeFamily(StrictModel):
    family_key: str
    stage: ProcessingStage
    name: str
    description: str
    hypothesis: str
    research_references: tuple[str, ...]
    parameter_axes: tuple[str, ...]
    implementation_status: Literal["available", "planned"]

class ProcessingNodeVariant(StrictModel):
    variant_key: str
    family_key: str
    parameter_preset_key: str
    parameters: dict[str, JsonValue]
    node_version_key: str
```

身份层级为：

```text
Family：稳定的经济含义或加工方法家族
  ↓
Variant：该家族下的精确参数实例
  ↓
Node Version：精确实现、引擎和契约版本
  ↓
Output Port：一次节点计算产生的具名输出
```

规则：

- 仅参数不同但经济含义和算法角色相同，归入同一个 Family；
- 参数、实现、输入绑定和 Schema 仍进入 Variant/Version 的精确身份；
- Family 不能直接运行，也不能作为 Artifact Dependency；
- 下游合法性在 Variant/Version/Port 级验证；
- 同家族诊断可以比较不同参数 Variant 的稳定性、相关性和覆盖差异；
- 透传保留原 Family 和 Variant，不因出现在后续层而改变身份。

### 5.4 FixedInputBinding

```python
class FixedInputBinding(StrictModel):
    input_port_key: str
    source_node_version_key: str | None
    source_output_port_key: str
    source_kind: Literal["raw_input", "processing_node"]
```

普通加工节点的输入绑定由目录冻结。连接只能来自直接上一加工层；较早信号必须先通过 Layer Projection 透传到上一层。

加工层 1 是例外的边界入口：其输入来自 RawInputPort。RawInputPort 不占用 Processing Stage，也不缩减三个加工层的可用深度。

### 5.5 ProcessingNodeVersion

```python
class ProcessingNodeVersion(StrictModel):
    node_version_key: str
    node_key: str
    family_key: str
    variant_key: str
    version_number: int
    stage: ProcessingStage
    name: str
    description: str
    hypothesis: str
    research_references: tuple[str, ...]
    implementation_key: str
    engine_artifact_id: UUID
    parameters: dict[str, JsonValue]
    input_ports: tuple[InputPortDefinition, ...]
    input_bindings: tuple[FixedInputBinding, ...]
    output_ports: tuple[OutputPortDefinition, ...]
    supported_asset_context_kinds: frozenset[str]
    supported_frequencies: frozenset[Literal["weekly", "monthly"]]
    quality_policy_key: str
```

验证规则：

- Node Version 不允许零输出；
- Input/Output Port Key 在节点内唯一；
- 每个必需 Input Port 必须且只能绑定一次；
- Processing Node 不能绑定同层或后层节点；
- 目录解析后，真实节点图必须无环；
- 参数属于 Node Version 身份，用户只选择已发布 Preset，不在前端任意编辑公式或参数；
- 一个 Node Version 的输入来源、算法或参数变化时，必须产生新版本。

## 6. Layer Projection：零拷贝透传

```python
class PortAddress(StrictModel):
    node_version_key: str
    output_port_key: str

class LayerProjection(StrictModel):
    source: PortAddress
    source_stage: ProcessingStage
    visible_in_stage: ProcessingStage
    projection_kind: Literal["identity_reference"] = "identity_reference"
```

Layer Projection：

- 不执行计算；
- 不发布新 Payload；
- 不生成新的经济血缘节点；
- 不改变 Artifact ID、Content Hash、Schema 或 Known At；
- 只表达某个较早层输出在后续层仍可作为输入或最终候选信号；
- 可以逐层建立投影，使所有合法连接在形式上都来自直接上一层。

Raw Input 到加工层 1 使用同样的零拷贝原则，但单独命名为 `SourceProjection`：

```python
class SourceProjection(StrictModel):
    raw_input_port_key: str
    visible_in_stage: Literal[1] = 1
    projection_kind: Literal["source_identity_reference"]
```

Source Projection 使某个 Raw Input 可以作为加工层 1 输出继续透传，但不会把 Raw Input 伪装成一次加工计算，也不会消耗一个 Processing Stage。

## 7. Node Run 与多输出原子性

### 7.1 NodeRunArtifact

推荐把一次节点运行作为一个不可变 Artifact。Artifact 依赖包括：

- Processing Node Version Artifact；
- 所有精确输入 Node Run/Raw Input Artifacts；
- Asset Context、Data Bundle、Eligibility；
- Engine、依赖锁和 Numerical Environment；
- 训练目标和 Fitted Model Artifact（如适用）。

领域记录建议为：

```python
class NodeRunRecord(StrictModel):
    node_run_id: UUID
    artifact_id: UUID
    node_version_artifact_id: UUID
    compiled_graph_artifact_id: UUID
    asset_context_artifact_id: UUID
    data_bundle_artifact_id: UUID
    status: Literal["published", "quality_failed"]
    output_ports: tuple[OutputPayloadRecord, ...]

class OutputPayloadRecord(StrictModel):
    output_port_key: str
    storage_uri: str
    media_type: str
    schema_key: str
    schema_version: int
    content_hash: str
    row_or_object_count: int
    byte_size: int
    quality_status: str
```

下游依赖指向 Node Run Artifact，并在 Dependency Role/领域绑定中注明所消费的 Output Port。Node Run 的 Content Hash 包含所有端口的独立 Content Hash。

### 7.2 失败原则草案

默认把多输出节点视为原子计算：任何必需 Output Port 失败质量门禁，整个 Node Run 不得发布为可消费状态。可选诊断输出失败不应影响必需输出，但必须在运行证据中记录。

约束：

- `layer3_aggregation_inputs` 是聚合直接输入的唯一来源；
- 每个地址必须在加工层 3 可见，并至少被一个已选 Aggregation Method 的 Input Policy 接受；
- 上游选择不能在存在下游依赖时被普通取消；
- 显式级联取消必须由后端返回精确影响集，再由用户确认；
- 草稿可以编辑，提交实验前必须编译成不可变 Graph Artifact。

### 8.1 前端 Family 分组规则

- 页面默认以 Family 为一级卡片、Variant 为二级选项；
- 已选 Family 置顶，Family 内已选 Variant 再置顶并使用明确颜色；
- Family 的合法状态由其 Variant 聚合：至少一个 Variant 合法则可展开，全部不合法才整体置灰；
- 具体 Reason Code 保留在 Variant，不以 Family 的概括状态掩盖差异；
- 反向选择点亮精确 Variant，并自动展开其 Family；
- 前端可显示 `已选 2 / 可用 5`，但不能用 Family 选择替代精确 Variant 选择；
- Product、Experiment 和导出同时显示 Family 名称、Variant 参数和精确版本。

## 13. 本轮待确认

### Q1：第一加工层如何表示原始字段（已澄清）

原始数据 Artifact 是三个加工层之前的 Source Domain。第一加工层真实节点可以直接读取 RawInputPort；需要原样向后传递的原始字段通过零拷贝 Source Projection 出现在第一层输出。RawInputPort 和 Source Projection 都不产生 Node Run，也不占用加工层。由此完整保留三个真实加工层。该边界已经澄清。

### Q2：多输出节点是否采用整次运行原子发布

推荐：所有必需输出共同成功，Node Run 才能发布；其中一个必需输出失败时不允许其他必需输出单独进入正式下游。纯诊断性可选输出可以失败，但必须记录。

### Q3：普通节点参数是否全部采用已发布 Preset

推荐继续沿用 v0.21 逻辑：用户选择参数实例，不在 Workspace 任意输入窗口、阈值或模型参数。新的参数组合必须先进入目录、测试和版本化发布。

### Q4：Processing Catalog 是否允许 Planned 节点

v0.21 目录允许 `available/planned`。推荐 v0.22 保留 Planned 节点用于展示研究路线，但它们永远不可进入可运行图，前端置灰并明确显示缺少的实现、数据或契约。

### Q5：Family 是否改为绑定可选择的输出元素

代表信号映射建议把计算身份与研究分类身份拆开：Node Version 负责运行，Feature/Signal Family 负责前端分组，Feature/Signal Variant 精确引用 `producer_node_version + output_port`。这样多输出节点不会被迫让所有端口共享一个不准确的信号家族。

### Q6：事件、连续值和向量是否由聚合器显式声明兼容性

推荐不提供全局隐式转换。Aggregation Family 必须声明接受的输入种类；任何事件转连续强度、向量池化或频率对齐都由显式 Adapter Node 完成。

### Q7：Stage 3 的聚合选择区是否只显示拥有 Pre-Aggregation Contract 的输出

推荐是。普通中间 Payload 可以透传到 Stage 3 供 Stage 3 节点使用，但不能因此自动成为可聚合信号。
