# 候鸟 v0.22：Workspace 前端信息架构与交互协议

> 文档等级：`historical/non-normative`  
> `superseded_by`：[`候鸟v0.22最终开发计划.md`](候鸟v0.22最终开发计划.md) 第 2.2、11、13、14 节；选择状态按正交轴实现，不使用互斥“三状态”。

> 状态：设计讨论稿  
> 目标：让 Raw Input、三个加工层、聚合、策略和防御在大量 Family/Variant 及复杂血缘下仍然可操作、可解释、可访问。

## 1. v0.21 前端现状与迁移判断

当前前端已经具备一些可以保留的基础：

- React Query 请求和缓存；
- Family card + Variant checkbox；
- 搜索、折叠、参数展示；
- 不合法选项保留但变灰；
- Draft revision、409 冲突暂停；
- save → submit 的顺序保护；
- Compile preview 和 Suite 状态；
- 中英文文本框架。

但当前选择逻辑存在四个不适合 v0.22 的边界：

1. `WorkspaceSelectionContext` 在浏览器维护完整 selection，并用通用 toggle 修改数组；v0.22 的自动祖先、锁和投影只能由后端求解。
2. Factor、Signal、Model 分散在独立页面，Workspace 首页只是计数入口；用户无法在一个稳定上下文中观察三层之间的联动。
3. `selected/selectable/disabled` 三个布尔概念不足以表达显式选择、自动需要、锁定、选择后补齐祖先和硬不兼容。
4. 全量 options 随每次选择重新请求；Catalog 增大、出现新闻和 Pattern Variant 后不能继续一次返回全部卡片。

因此 v0.22 不直接扩展现有 toggle context，而新增 Graph Workspace Shell；旧页面在迁移期继续服务 v0.21。

## 2. 总体页面结构

### 2.1 单一 Workspace Shell + 分层子路由

建议用户始终停留在同一个 Workspace 外壳内，仅切换当前编辑层：

```text
/workspace/{draftId}/context
/workspace/{draftId}/raw
/workspace/{draftId}/stage-1
/workspace/{draftId}/stage-2
/workspace/{draftId}/stage-3
/workspace/{draftId}/aggregation
/workspace/{draftId}/strategy
/workspace/{draftId}/review
```

现有 `/factors`、`/signals`、`/models` 页面未来恢复为研究诊断和已发布对象查看，不再承担 v0.22 Draft 的主要编辑职责。

### 2.2 桌面布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Draft / Catalog / Revision / Save state / Branch count / Run         │
├──────────────────────────────────────────────────────────────────────┤
│ Context │ Raw │ L1 │ L2 │ L3 │ Aggregation │ Strategy │ Review      │
├─────────────────────────────────────────────┬────────────────────────┤
│ Active stage                                │ Current selection       │
│ ┌ Search / filters / counts ──────────────┐ │ Stage 3 inputs          │
│ ├ Pinned selected families ───────────────┤ │ Aggregators             │
│ ├ Available family catalog ───────────────┤ │ Strategies / Defense    │
│ └ Pagination / load more ─────────────────┘ │ Blockers / branch count │
├─────────────────────────────────────────────┴────────────────────────┤
│ Bloodline inspector / impact drawer（按需打开）                       │
└──────────────────────────────────────────────────────────────────────┘
```

右侧摘要栏在各层保持稳定，让用户随时知道最终 Stage 3 输入、Aggregation、Strategy 和 Defense，而不必来回翻页确认。

窄屏时摘要栏变为底部可展开 drawer；Stage navigation 横向滚动，但一次仍只显示一个层级。

### 2.3 为什么不默认显示完整神经网络画布

完整 Catalog 图会随 Pattern、新闻和参数 Variant 快速膨胀。把所有节点和边同时画在可编辑 canvas 中，会产生：

- 大量交叉边；
- Family/Variant 难以归纳；
- 键盘操作和搜索困难；
- 用户容易误以为可以自由接线；
- 与“所有链路由系统人工部署”冲突。

因此主操作界面继续使用 Family/Variant Catalog；图形只用于查看某个元素的局部血缘或选择影响，不提供拖线和节点创建。

## 3. Stage Navigation

每个 Stage tab 显示：

- 显式选择数；
- 自动需要数；
- 当前 blocker 数；
- 是否有未确认的 context/rebase 影响。

UI 文案使用：

```text
研究上下文 → 原始输入 → 加工层 1 → 加工层 2 → 加工层 3
→ 信号聚合 → 策略与防御 → 检查并运行
```

Raw Input 不编号为“加工层 0”，避免用户误以为系统有四个加工层；内部 API 仍可使用 `stage_no=0`。

Tab 不强制按顺序访问。用户可以直接进入加工层 3 反向选择，也可以从 Raw 正向推进。

## 4. 选择状态模型修正

### 4.1 显式与依赖不是互斥状态

每个 Feature Occurrence 使用：

```text
is_explicit: boolean
required_by: DownstreamSelectionRef[]
is_present = is_explicit OR required_by.length > 0
```

示例：

| is_explicit | required_by | 含义 |
|---|---|---|
| false | 空 | 未选择 |
| true | 空 | 用户选择、可普通取消 |
| false | 非空 | 自动点亮的祖先、被锁定 |
| true | 非空 | 用户也明确想保留，同时被下游锁定 |

这比 `selection_origin=explicit|required_ancestor` 更准确。

### 4.2 可用性仍是独立维度

- `ready`
- `requires_ancestors`
- `hard_incompatible`

已存在的 occurrence 在外部数据可用性变化后也可能变成 blocked，因此 UI 不能假设 `is_present` 必然等于合法。

### 4.3 自动祖先可以提升为显式

当 `is_explicit=false, required_by非空` 时，Variant 行提供：

```text
保留为我的选择
```

执行普通 `select_feature_occurrence`，把它加入 Draft Intent。之后即使依赖它的下游被删除，它仍保留。

### 4.4 取消显式但仍被依赖

当 `is_explicit=true, required_by非空` 时，用户可以执行：

```text
取消主动保留
```

这只删除 explicit intent，不移除 occurrence；行仍显示为自动需要并保持锁定。若用户要求真正删除该上游，则进入级联影响预览。

## 5. Family Card

### 5.1 折叠态

每个 Family 只显示一张卡，包含：

- 人类可读名称和稳定 family key；
- Feature 类型：数值、向量、事件、文本、Pattern 等；
- 经济含义/研究假设摘要；
- 起源层；
- Variant 总数；
- 当前层显式数、自动需要数、可用数；
- product/research/deprecated 等标签；
- 展开按钮。

Family 本身没有 checkbox，不产生 Draft selection。

### 5.2 展开态

Variant 行显示：

- 参数摘要；
- variant key；
- 当前 visible stage；
- 状态文字和图标；
- 上游需求摘要；
- 当前选中 Aggregator 的兼容性；
- “选择/加入聚合输入/保留为我的选择”等主操作；
- 查看血缘；
- 导出输出。

实现 Version 和 Artifact ID 默认折叠在“技术信息”中；普通选择时不让版本噪音占据主要空间。

### 5.3 排序和前置

Family 分为两个连续区域：

1. `已选择与自动需要`：所有 present Family；
2. `可选目录`：其余 Family。

不是复制卡片，而是把卡片移动到第一区域。Family 内 Variant 顺序：

1. explicit + required；
2. explicit only；
3. required only；
4. ready；
5. requires ancestors；
6. hard incompatible。

选择成功后若卡片发生移动：

- 保持该卡片展开；
- 把键盘焦点移到同一 Variant 的新位置；
- 使用短暂位置过渡；
- 不把页面滚回顶部。

这实现“已选元素前置”，同时避免用户找不到刚才操作的对象。

## 6. 颜色、图标和文字

颜色只作为辅助，所有状态必须同时有文字和图标。

| 状态 | 建议视觉 | 必须显示的文字 |
|---|---|---|
| explicit | 深绿色边/浅绿底、check | 已选择 |
| required only | 蓝绿色边/浅青底、link | 下游需要 |
| explicit + required | 绿色底、check + lock | 已选择 · 被下游锁定 |
| ready | 中性白底 | 可直接选择 |
| requires ancestors | 琥珀色虚线、branch | 选择后自动补齐 N 项 |
| hard incompatible | 灰底、ban | 当前不可用；显示首要原因 |
| present but blocked | 红褐提示边、warning | 已选但当前阻塞 |
| mutation pending | spinner + 降低操作性 | 正在更新 |

不得仅通过降低 opacity 表示 disabled；目前 v0.21 的 `.disabled { opacity: .65 }` 应增加明确原因和足够对比度。

最低要求：

- 文本和背景满足 WCAG AA；
- checkbox/button 有可见 focus ring；
- `aria-pressed`、`aria-expanded`、`aria-describedby` 完整；
- screen reader 能读出“已选择且被 2 个下游依赖”；
- 动效尊重 `prefers-reduced-motion`。

## 7. 正向选择交互

1. 用户在 Raw/L1/L2 选择一个 `ready` Variant occurrence。
2. 行进入 pending，不立即伪造完整衍生状态。
3. 后端事件成功后返回 revision + state diff。
4. 卡片进入 pinned 区；下游受影响 Family 的计数和状态刷新。
5. 页面显示轻量反馈：

```text
已选择 total_return(window=20)
加工层 2：新增 3 个可直接选择项
```

正向选择不会自动选择任何下游 Feature。

## 8. 反向选择交互

加工层 3 的 Variant 主按钮使用明确文案：

```text
加入聚合输入
```

当 availability=`requires_ancestors` 时，按钮旁提前显示：

```text
将自动补齐 4 个祖先、2 个层间投影
```

点击后不需要二次确认，因为它不会删除用户状态。成功反馈：

```text
已加入 price_cross_above_ma(window=200)
系统自动点亮 4 个上游元素
```

提供短时“撤销”操作；撤销本质是取消这个 Stage 3 显式叶子，后端自动回收孤儿祖先。

若生产图存在冲突，不部分点亮祖先。保持原状态，并打开冲突路径 drawer。

## 9. 锁定与级联取消

### 9.1 普通锁定展示

自动需要的祖先不使用可误导的 disabled checkbox。展示锁图标和：

```text
被以下选择需要：
- price_cross_above_ma(window=200)
- golden_cross_event(50, 200)
```

点击依赖项可在 Bloodline Inspector 中定位路径。

### 9.2 真正删除锁定祖先

“从所有路径中移除”打开 impact preview drawer，显示：

- 将移除的下游显式 Feature；
- 将解除的自动祖先；
- 失效的 Aggregator/Strategy/Defense；
- 实验分支数变化；
- 是否有正在编辑但尚未编译的设置丢失。

确认按钮必须包含影响数量，例如：

```text
确认移除 3 个下游选择
```

不使用模糊的“确定”。

## 10. Bloodline Inspector

Inspector 是只读局部图，支持两个模式：

### 10.1 当前血缘

展示已存在 occurrence 的：

- Raw → L1 → L2 → L3；
- Node input/output port；
- projection；
- explicit/required；
- 直接 Aggregation consumers。

### 10.2 选择预览

对未选但 `requires_ancestors` 的 Feature，展示选择后会新增的路径。新增节点用虚线，已存在共享祖先用实线。

Inspector 不支持：

- 拖动连线；
- 创建节点；
- 修改公式；
- 绕过 Family/Variant 选择；
- 任意改写 input binding。

图过大时默认只展开当前 Feature 的最短完整生产图；共享分支按节点折叠。

## 11. 聚合层交互

聚合页顶部固定显示 Stage 3 输入集合：

- Family/Variant；
- payload type；
- 方向和排名语义；
- 数据可用性；
- 当前所选全部 Aggregator 是否兼容。

Aggregation Family card 包含：

- Family 与实现 Version；
- 输入政策；
- 已接受输入数/总输入数；
- Target Variant；
- Hyperparameter Preset；
- 预计形成的 aggregation instance 数。

多个 Aggregator 被选择时，每一个都必须接受完整 Stage 3 集合。Stage 3 页面显示：

```text
与全部 2 个已选聚合器兼容
```

如果用户先选 Aggregator，Stage 3 候选项立即按所有已选 Aggregator 的交集更新合法性。

Family 没有隐式默认 Target/Hyperparameter。前端可以标注“推荐”，但写入 Draft 的仍是明确逻辑 ID。

## 12. 策略与防御交互

每个 Strategy Family 卡片内分为：

1. 横截面选择参数：K、buffer、sector cap 等已发布选项；
2. Defense 选择：none 或一个已发布防御策略 Variant；
3. 与 Aggregation output 的兼容性；
4. 该配置生成的分支数。

Defense 在语义上独立于横截面排名，但 UI 嵌入每个 Strategy 配置中，符合“每个横截面策略选择一个防御方案”的设计。

若同一 Strategy 选择多个 Defense Variant，它们产生不同实验分支；每个具体实验仍只有零或一个 Defense。

## 13. Review 页面

Review 是开始实验前的唯一汇总页，按直接决策信息优先显示：

1. 资产域、频率和 Catalog Release；
2. Stage 3 最终输入；
3. Aggregation Family/Version；
4. Target Variant；
5. Hyperparameter Preset；
6. Strategy；
7. Defense；
8. Aggregation instance、Strategy branch 和回测 cell 数；
9. blockers/warnings；
10. 完整加工血缘入口。

主按钮：

```text
编译并开始实验
```

前端内部执行：

```text
compile exact draft revision → submit compiled graph
```

按钮文案虽然合并，后端仍是两个命令。

## 14. 每层数据导出

每个 Feature Variant occurrence 提供“导出此输出”，Stage 页面提供“导出本层已选”。

导出分两类：

- 已物化：直接创建导出包；
- 尚未物化：明确提示将先运行所需祖先和节点，再生成导出包。

不把所有数据强制转换为 CSV：

| Payload | 推荐格式 |
|---|---|
| scalar/table | Parquet，按需附 CSV |
| vector/tensor | Arrow/Parquet + schema |
| text/news | JSONL/Parquet + metadata |
| event/pattern | Parquet/JSONL |

每个导出包必须包含 manifest：Catalog、Feature Variant Version、visible stage、producer、上游 Artifact、payload contract、content hash、资产/时间范围和 PIT policy。

Layer Projection 导出不得复制生成一个新的假数据集身份；它引用同一 payload content，并在 manifest 中说明 visible stage。

## 15. 大 Catalog 的加载策略

### 15.1 两个查询区域

- Pinned 区：一次获取当前层全部 present Family/Variant；通常数量较小。
- Catalog 区：服务端搜索、过滤、cursor pagination。

搜索不会隐藏 Pinned 区，解决用户搜索后再次忘记已选内容的问题。

### 15.2 搜索和过滤

支持：

- 名称/key/经济含义；
- payload kind；
- ready/requires ancestors/incompatible；
- product eligible/research only；
- origin stage；
- compatible with selected aggregation；
- explicit/required/locked。

搜索输入 250ms debounce；结果响应必须带 Draft revision。翻页期间 revision 变化则重载当前查询，不能把不同 revision 的页拼在一起。

### 15.3 Family 展开

Family 列表只带 Variant 状态计数和少量 selected preview。展开时才请求完整 Variant page。展开状态、搜索词和过滤器可以保存在 session/local UI preference 中，但不得保存为 Draft Intent。

## 16. 前端状态与并发

### 16.1 替换 `WorkspaceSelectionContext`

新增 `WorkspaceGraphProvider`，只保存：

- 当前 Draft ID 和 server revision；
- server-confirmed Draft Intent 摘要；
- Derived View summary；
- mutation queue/pending commands；
- conflict state；
- UI preference。

它不在本地直接 toggle 一个完整 selection 数组。

### 16.2 命令队列

用户可以快速选择多个 Variant。客户端按点击顺序排队，逐个使用上一命令返回的新 revision：

```text
event 1 @ revision 12 → response 13
event 2 @ revision 13 → response 14
```

- Pending 行显示 spinner；
- 未经服务器确认不显示为 committed；
- 若某事件冲突，暂停后续队列并提示用户刷新/检查；
- Family 批量选择使用一个原子 batch event，避免几十次 revision；
- context change/rebase/cascade confirm 期间不接受普通排队事件。

因此 API 初版需补充：

- `batch_select_feature_occurrences`
- `batch_deselect_feature_occurrences`

批量事件要么全部成功，要么全部不变。

### 16.3 React Query

建议 query keys：

```text
workspaceGraph/draft/{id}
workspaceGraph/stage/{id}/{revision}/{stage}/{filters}
workspaceGraph/family/{id}/{revision}/{stage}/{family}/{cursor}
workspaceGraph/lineage/{id}/{revision}/{feature}/{stage}
```

事件响应直接更新 Draft summary，并按返回的 `affected_stages/family_ids` 精确 invalidate，不每次清空所有页面缓存。

### 16.4 Local Storage 与多标签页

Local Storage 只保存：

- 最近 Draft ID；
- 当前路由；
- 展开的 Family；
- 搜索/过滤偏好；
- 摘要栏开合。

不保存权威 Draft Intent 副本。使用 `BroadcastChannel` 通知同源其他标签页 revision 已变化；其他标签页自动重新读取 server state。若仍发生 409，暂停 mutation queue。

通用状态组件：

不要在 Raw/L1/L2/L3 各复制一套卡片逻辑；差异通过 stage-aware props 和主操作文案表达。

## 18. 前端测试门槛

### 状态渲染

- explicit、required、explicit+required 四种组合；
- ready/requires ancestors/incompatible；
- selected but blocked；
- selected Family 和 Variant 前置；
- 搜索时 pinned 区不消失。

### 交互

- 正向选择只改变下游合法性；
- Stage 3 选择自动点亮祖先；
- required 提升 explicit；
- explicit+required 取消主动保留后仍 present；
- locked ancestor 进入 impact preview；
- batch event 原子失败；
- Compile 使用精确 revision，Suite 使用返回的 graph ID。

### 并发

- 快速连续点击按 revision 顺序发送；
- 409 暂停队列；
- BroadcastChannel 更新另一标签页；
- 过期 impact token 重新预览；
- 翻页期间 revision 改变不混合缓存页。

### 可访问性

- 全流程只用键盘可完成；
- focus 在卡片重排后保持；
- screen reader 读出锁和依赖；
- 不依赖颜色区分状态；
- reduced motion；
- 移动端 drawer 和 stage navigation 可用。

## 20. 本轮需要确认的问题

### Q1：单一 Workspace Shell

建议把 v0.22 的选择集中到同一个 Workspace Shell，通过子路由切换 Raw/L1/L2/L3/Aggregation/Strategy；Factors、Signals、Models 独立页面保留为研究诊断和已发布结果，而不是继续承担草稿选择。

### Q2：同一元素可以同时“显式选择 + 被下游需要”

建议采用正交状态。自动祖先可以提升为显式；显式且被锁定的元素也能取消“主动保留”，但不会因此破坏下游。

### Q3：已选元素的前置方式

建议在每层设置独立 Pinned 区，把 present Family 真正移动到顶部，而不是复制；保持展开、滚动和焦点。搜索和过滤永远不隐藏 Pinned 区。

### Q4：图形界面的定位

建议只提供只读、局部的 Bloodline Inspector 和选择预览，不提供全 Catalog 可编辑画布或拖线。Family/Variant 列表仍是唯一选择入口。
